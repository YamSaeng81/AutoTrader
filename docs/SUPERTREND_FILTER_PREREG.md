# Supertrend 확인 필터 기여도 — 사전 등록 v2

> **목적**: 상위봉(H4) Supertrend 확인 필터가 **켜둘 가치가 있는가**를 본다.
> 다른 규칙을 함께 최적화하지 않는다. 새 전략을 만들지 않는다.

## 0. 두 질문을 분리한다

| 질문 | 비교 방법 | 무게 |
|---|---|---|
| **Q1. 나쁜 신호를 구별하는가** | 같은 기본 신호를 상위봉 동의·비동의로 나눠 이후 순수익 비교 | 거래당 품질 |
| **Q2. 실제로 켜둘 가치가 있는가** | 동일 기간·자본·청산·비용·포지션 제한에서 필터 ON/OFF 비교 | 🔴 **최종 판단은 여기** |

Q1 이 좋아도 Q2 가 나쁠 수 있다 — 필터가 **거래 수를 줄이고 기회를 놓치기** 때문이다.
그 손실은 Q1 에 안 잡히고 Q2 에만 잡힌다.

## 0.1 🔴 착수 전 이미 아는 것 — 합성 데이터에서는 필터가 아무것도 막지 못했다

`StrategyBehaviourFingerprintTest` 의 실효 중복 그룹 (core-engine 테스트, 합성 4구간 시나리오):

```
COMPOSITE_BREAKOUT == COMPOSITE_BREAKOUT_ICHIMOKU == COMPOSITE_MTF_BTC == COMPOSITE_MTF_BTC_STRICT
COMPOSITE_MOMENTUM_ICHIMOKU_V2 == COMPOSITE_MTF_MOMENTUM
COMPOSITE_MTF_CONFIRMED        == COMPOSITE_REGIME_ROUTER
```

**세 MTF 프리셋 전부가 필터 없는 기본과 거동이 같다.** 즉 그 시나리오에서 필터는 **한 번도 막지 않았다.**

⚠️ 다만 그것은 **합성 캔들 250봉 창 · 3봉 간격**의 제한된 흔적이다. 실제 시장에서도 같은지는 모른다.
그래서 **§2 의 발화율 측정을 게이트로 먼저 둔다.**

## 1. 대상과 고정 사항

### 필터

`MtfConfirmedStrategy` — H1 신호와 H1→H4 다운샘플 `SupertrendStrategy` 의 **방향이 다르면 HOLD**.
`SupertrendStrategy` 는 데이터만 있으면 HOLD 를 내지 않으므로 필터는 **순수하게 방향 게이트**다.

### 🔴 필터는 BUY 만이 아니라 **SELL 도 막는다**

```java
if (htfSignal.getAction() != ltfSignal.getAction()) {
    return StrategySignal.hold(...);
}
```

조건이 `!=` 이므로 **H1 SELL + H4 BUY 도 HOLD** 가 된다. 그리고
`BacktestEngine:403` 은 전략 SELL 을 **청산에 사용**한다("전략 SELL 게이트(L-2) — 실전매매와
동일하게 최소보유시간·본전청산차단 적용").

**따라서 래퍼 ON/OFF 는 진입과 청산을 함께 바꾸는 실험이다.**

| | |
|---|---|
| **Q2** | 배포된 필터를 켜둘 가치 → **래퍼 전체 ON/OFF** 를 비교한다. 진입·청산 **양쪽**이 바뀐다 |
| **Q1** | 그중 **BUY 선별 능력만** 설명하는 분석이다. Q2 의 차이를 전부 설명하지 않는다 |

게이트(§2)도 **BUY 차단 수와 SELL 차단 수를 따로** 센다.

### 기본 전략 3종 (필터 벗긴 것)

| MTF 프리셋 | 기본(필터 OFF) |
|---|---|
| `COMPOSITE_MTF_CONFIRMED` | `CompositeRegimeRouter` |
| `COMPOSITE_MTF_BTC` | `breakoutCore` (COMPOSITE_BREAKOUT) |
| `COMPOSITE_MTF_MOMENTUM` | `IchimokuFilteredStrategy(momentumV2Core)` |

### 🔴 착수 전 고정 — 셋

1. **필터 적용 전 기본 신호 전체**를 대상으로 한다. 실제 체결 거래만 쓰면 **이미 차단된 신호가 빠진다**
2. 상위봉은 **판단 시점까지 종료된 H1 봉만**으로 구성한다 (미래 참조 금지).
   주 분석은 **운영과 동일한 형성 중 H4 포함**(B), 보조로 완결 H4 만(A) — 아래 정정 참조
3. **해당 확인 필터만** 바꾼다. 진입·청산·비용·포지션 제한은 그대로 두고 **다른 규칙을 함께 최적화하지 않는다**

#### 📝 v2 정정 — **B(운영 그대로)가 주 분석이다**

v1 은 "완결 H4 봉만"(A)을 주 변형으로 두었는데 **지나치게 제한적이었다.**
`CandleDownsampler` 가 남기는 말미의 형성 중 H4 봉은 **판단 시점까지 종료된 H1 봉만**
집계한다 — 그 자체로 **미래 참조가 아니다**. 그리고 **배포된 것은 이쪽**이다.

| 변형 | 상위봉 | 역할 |
|---|---|---|
| **B (주)** | **형성 중 H4 포함 — 운영과 동일** | 🔴 **배포 필터 기여도의 주 분석** |
| A (보조) | 완결 H4 봉만 | **별도 변경안**의 보조 분석 |

Q1 의 Holm 9검정은 **주 분석 B 에만** 적용한다. A 는 **탐색적으로** 보고한다.

## 2. 게이트 — 발화율 먼저 잰다

```
BUY  차단 수 / 기본 BUY  수
SELL 차단 수 / 기본 SELL 수      ← 청산에 영향. 따로 센다
HTF 데이터부족 횟수 · HTF 중립 횟수
```

### 🔴 "발화율 1% 미만 = 차이 없음"은 성립하지 않는다

드물게 막는 거래 **하나**가 큰 손실을 피하거나 이후 포지션 경로를 바꿀 수 있다.
비율로 종료 판단을 하지 않는다.

| 차단 | 처리 |
|---|---|
| **BUY·SELL 모두 0건** | 같은 평가 조건에서 다른 동작 차이도 없다면 **무효과 판단 가능** |
| **0건 초과 · 1% 미만** | **"저빈도 차단"으로 기록하고 Q2 를 진행한다** |
| 1% 이상 | Q1 · Q2 진행 |

**Q1 의 NA 는 비율이 아니라 양 군의 실제 표본 수로 판단한다.**
기본 BUY 가 100만 건이면 0.5% 도 5,000건이다 — 비율만으로 표본 부족을 정할 수 없다.
기준: **각 군 · 각 코인에서 채택 관측치 ≥ 20, 양 군 공통 코인 ≥ 6** (§4).

## 3. Q1 — 동의·비동의별 이후 순수익

- 대상: **필터 적용 전** 기본 BUY 신호 **전체**
- 분할: `동의`(H4 Supertrend BUY) vs `비동의`(H4 SELL)
- 이후 순수익: 진입 `t+1` 시가, 청산 `t+1+h` 시가, `h ∈ {4, 12, 24}`봉, 비용 차감
- 비중첩 채택: `t' ≥ t + h` (각 군 안에서)
- 집계: **코인별 동일가중 평균**

### 🔴 양 군에서 **같은 코인 집합**을 쓴다

동의군과 비동의군 **모두** 표본 기준(코인당 채택 관측치 ≥ 20)을 충족한 코인만 포함한다.
그 **공통 코인**에서 코인별 `평균(동의) − 평균(비동의)` 를 먼저 구하고, 그 값을 동일가중한다.
군마다 다른 코인을 평균 내면 **필터 효과에 코인 구성 차이가 섞인다.**
공통 코인 < 6 이면 **NA**. 포함·제외 코인을 모두 보고한다.
- 불확실성: 패널 시간블록 부트스트랩 (L=72봉, B=2000, 시드 20260923, **중심화 p값**)
  — `SIGNAL_STUDY_PREREG.md` v5 §6 과 동일 절차

**주 통계량**: `θ = 평균_코인( 평균(동의)_코인 − 평균(비동의)_코인 )` (공통 코인)
단측 검정(필터가 나쁜 신호를 거른다면 θ > 0). 3전략 × 3h = **9검정 → Holm 보정 α=0.05**. **변형 B 에만 적용**(A 는 탐색적 보고).

⚠️ Q1 이 유의해도 그것은 **거래당 품질**이다. 켤 가치는 Q2 가 정한다.

## 4. Q2 — 필터 ON/OFF 운용 비교

`BacktestEngine` 으로 **동일 기간·자본·청산·비용·포지션 제한**에서 ON/OFF 만 바꾼다.

| 지표 | |
|---|---|
| 총 순수익률 | 🔴 **주 지표** |
| 거래 수 | 필터가 얼마나 줄였나 |
| 거래당 기대값 | Q1 과 대조 |
| 최대 낙폭(MDD) | |

코인 13종 각각 + 코인별 동일가중 합산. **전략 3종 × 변형 A·B** 로 돌린다.

### 판정 — 착수 전 확정

| 결과 | 판단 |
|---|---|
| BUY·SELL 차단 **0건** | **기여 없음.** 필터가 막는 것이 없다 |
| 차단 > 0 이지만 저빈도 | **저빈도 차단으로 기록하고 Q2 결과로 판단한다** |
| Q2 총 순수익 ON ≤ OFF (13코인 동일가중, 변형 B) | **켤 가치 없음.** 필터를 수익 개선 장치로 유지할 근거가 약하다 |
| Q2 ON > OFF **이고** 두 값 모두 음수 | 🔴 **손실 축소를 발견한 것이지 수익 전략을 확보한 것이 아니다** |
| Q2 ON > OFF **이고** ON 이 양수 | 별도 사전 등록으로 새 자료에서 검증할 후보 |
