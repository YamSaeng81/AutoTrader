# 실전 진입 기준 — 사전 등록 (2026-10-01 고정)

> **이 문서를 고정한 시각**: 2026-10-01, 66세션 전향 검증 T0(`2026-10-01T06:16:12.634313Z`)
> **직후**이며 **어떤 중간 성과도 보지 않은 상태**다. 그것이 이 문서의 유일한 효력 근거다.
> 결과를 본 뒤에 쓰면 결과에 맞춘 기준이 된다.

## 0. 이 문서가 하는 일과 하지 않는 일

| 한다 | 하지 않는다 |
|---|---|
| 전향 검증 결과가 **어떤 후속 결정으로 이어지는지** 정한다 | 🔴 `SUPERTREND_VALIDATION_PREREG.md` §4 의 판정 기준을 **바꾸지 않는다** |
| 실전 진입 전에 **추가로** 통과해야 할 관문을 정한다 | 🔴 A 의 탈락 기준을 **완화하지 않는다** |
| 소액 실전의 한도·중단·확대 조건을 정한다 | 🔴 결과가 좋은 팔을 **사후에 골라 합격시키지 않는다** |

🔴 **사후 선택 금지 — 구체적으로 무엇을 금지하는가**

- 이 실험에서 실전 후보가 될 수 있는 팔은 **A 하나뿐**이다. §4(가)가 "근거 있음"일 때만이다.
- (가)가 근거 없음이면 **이 실험에서 나오는 실전 후보는 없다.** B 가 코드에 남는 것은
  기본값 유지일 뿐 **실전 승격이 아니다.** B 를 실전에 올리려면 B 에 대한 **새 사전 등록과
  새 T0** 로 전향 검증을 다시 해야 한다.
- `OFF` 팔(`B − OFF`)은 §4 에서 **보고만** 하기로 고정했다. 사후에 판정 대상으로 끌어올리지 않는다.
- 종료 조건(§5: min(세 팔 각 200거래, 6개월))을 **연장하지 않는다.** 결과가 아쉬워서 구간을
  늘리는 것은 사후 선택과 같다. 더 보려면 새 사전 등록·새 T0 다.

🔴 **A 의 탈락은 프로젝트의 탈락이 아니다.** (가)는 "이 변경안을 채택할 것인가"라는 좁은 질문이다.
A 가 떨어져도 자동매매 프로젝트가 떨어지는 것이 아니고, A 가 붙어도 **실제 체결 가능성과
리스크 통제가 검증되는 것이 아니다.** 그 둘은 아래 §3·§4 가 따로 묻는다.

## 1. 검증 결과별 후속 결정

§4 는 (가) 변경안의 가치와 (나) 수익 후보 자격을 분리해 고정했다. 그 네 조합에 대한 후속 결정이다.

| §4 (가) | §4 (나) | 결정 | 다음에 할 일 |
|---|---|---|---|
| 근거 있음 | 충족 | **실전 후보 채택** | §2 → §3 → §4 를 **순서대로** 통과해야 실전 진입. 세 관문 중 하나라도 막히면 진입하지 않는다 |
| 근거 있음 | 미충족 | **실전 진입하지 않는다.** A 를 코드 기본값으로 채택하는 것은 가능 | A 자체가 비용을 넘지 못했다. 실전은 금지. 다시 보려면 새 사전 등록·새 T0 |
| 근거 없음 | — | **A 변경안을 접는다.** B 유지 | 이 실험에서 실전 후보는 없다. 다음 후보 전략은 같은 절차를 **처음부터** 밟는다 |
| 보류 | — | **보류로 기록하고 종료한다** | 🔴 구간을 늘려 재판정하지 않는다. 새 사전 등록·새 T0 만 허용 |

📌 종료 규칙은 §5 그대로다 — `min(모든 팔이 각각 200거래를 채운 공통 시점, 6개월 경과)`.
6개월 시점에 모든 팔 ≥ 100거래면 표본 부족을 명시해 판정하고, 한 팔이라도 < 100이면 **판정 불가**다.
⚠️ 종료까지 걸리는 시간은 **실제 거래 발생률에 달렸고 지금 알 수 없다.** 추정치를 적지 않는다.

## 3. 실제 체결 비용 — 고정 슬리피지로 확인하지 못한 것

### 페이퍼가 가정한 것

| 항목 | 값 | 출처 |
|---|---|---|
| 슬리피지 | **편당 0.1%** (고정) | `TradingConstants.PAPER_SLIPPAGE_PCT = 0.001` |
| 수수료 | **편당 0.05%** | `TradingConstants.FEE_RATE = 0.0005` |
| 왕복 합계 | **0.3%** | §4 의 "주 비용"과 일치 |
| 비용 스트레스 | 왕복 **0.5%** | §4 (나) 의 스트레스 열 |

🔴 **고정 슬리피지는 가정이지 관측이 아니다.** 페이퍼는 신호가격에 0.1% 를 더해 즉시 전량
체결된다고 **가정**한다. 실제로는 (1) 호가 스프레드, (2) 주문 크기 대비 호가 잔량, (3) 부분 체결,
(4) 미체결·취소가 있다.

📌 **이 위험은 이번 검증 과정에서 이미 실측으로 드러났다** (2026-10-01):
22코인 중 일부는 **한 시간 동안 체결이 한 건도 없다.** 09-28 18:00~18:20 UTC 의 1분봉은
KRW-POWR **0개**, KRW-GLM **0개**, KRW-HIVE **1개**였다. 체결이 없는 시간대에 성립하는
시장가 주문은 **호가를 긁고 들어간다** — 고정 0.1% 가 성립할 근거가 없는 구간이다.
즉 이 코인 집합에서 슬리피지 과소평가 위험은 **가설이 아니라 관측된 조건**이다.

### 검증 방법 (여기서 고정한다)

1. **도구는 이미 있다** — `ExecutionDriftTracker` 가 실전 체결마다
   `slippage(%) = (fillPrice − signalPrice) / signalPrice × 100` 을 `execution_drift_log` 에 남긴다.
   7일 누적 평균이 **0.5%** 를 넘으면 경고한다(`ALERT_THRESHOLD_PCT`).
2. **측정 단위**: 왕복 1건 = 진입 슬리피지 + 청산 슬리피지 + 수수료 2회.
   `실측 왕복 비용(%) = |진입 slippage| + |청산 slippage| + 0.10`
3. **표본**: 실전 왕복 거래 **≥ 30건**. (임의의 선택이며 사전에 고정했다. 30은 코인별 편차를
   보려면 20보다 낫고, 소액 구간을 불필요하게 늘리지 않는 선이다.)
4. **판정** — 실측 왕복 비용을 §4(나) 의 "거래당 순수익률 ≥ 0.10%" 에 **다시 넣어 계산한다**:

   | 실측 왕복 비용 | 판단 |
   |---|---|
   | ≤ 0.30% (가정 이내) | 가정이 유효하다. §4(나) 결과를 그대로 쓴다 |
   | 0.30% ~ 0.40% | 그 값으로 거래당 순수익률을 재계산해 **≥ 0.10%** 를 다시 요구한다. 미달이면 확대하지 않는다 |
   | > 0.40% | 🔴 **가정이 깨졌다.** 소액 실전을 중단하고 §4(나) 를 그 비용으로 전면 재판정한다 |
   | 7일 평균 편당 > 0.5% (경고선) | 🔴 즉시 중단. 전략 재검증 |

5. **코인별로도 본다.** 전체 평균이 통과해도 특정 코인의 실측 비용이 0.60% 를 넘으면
   **그 코인만 제외**한다. 🔴 단, 제외는 **성과가 아니라 체결 비용**을 근거로만 한다 —
   수익이 나쁜 코인을 비용 핑계로 빼는 것은 사후 선택이다.

## 4. 소액 실전 — 자본·손실·노출 한도와 중단·확대 조건

🔴 아래 숫자는 **임의의 선택이며, 사전에 고정했다는 데 의미가 있다.** §4 의 0.10% 기준과 같은 성격이다.

### 자본·노출 한도

| 항목 | 한도 | 근거 |
|---|---|---|
| 총 투입 자본 | **500,000 KRW** | 전액을 잃어도 프로젝트를 계속할 수 있는 금액. "회복 가능한 손실"의 정의를 금액으로 못 박는다 |
| 세션(코인)당 자본 | **50,000 KRW** | 업비트 최소 주문 5,000원의 10배 — 부분 체결·수수료가 비율을 왜곡하지 않을 최소 크기 |
| 동시 보유 포지션 | **≤ 5** | 총 노출을 250,000 KRW(자본의 50%)로 묶는다 |
| 대상 코인 | 전향 검증 22코인 중 **§3-5 를 통과한 코인만** | 체결 비용 근거로만 걸러진 집합 |
| 타임프레임 | **H1** (검증과 동일) | 다른 타임프레임은 다른 전략이다 |

### 중단 조건 — 하나라도 걸리면 **전량 정지**

| 조건 | 임계 | 출처 |
|---|---|---|
| 세션 총자산 / 초기자본 − 1 | **≤ −15%** | `KILL_CRITERIA.md` A `CAPITAL_LOSS` |
| 세션 고점 대비 하락 | **≤ −20%** | 같은 문서 `MAX_DRAWDOWN` |
| 서킷브레이커 누적 발동 | **≥ 3회** | 같은 문서 `CB_REPEAT` |
| 전체 투입 자본 기준 누적 손실 | **≤ −15%** (= −75,000 KRW) | 세션 단위 기준이 전체를 보지 못하므로 따로 건다 |
| 1일 손실 | **≤ −3%** of 총 투입 자본 | 하루에 더 잃는 것을 허용할 이유가 없다 |
| 실측 왕복 비용 | **> 0.40%** 또는 7일 평균 편당 **> 0.5%** | §3 |
| 그룹(전략×H1) 누적 실현손익 ≤ 0, n ≥ 20 | 발동 | `KILL_CRITERIA.md` B `NEGATIVE_EV` |
| 그룹 알파 < 0, n ≥ 20 | 발동 | 같은 문서 `NEGATIVE_ALPHA` |

🔴 중단은 **자본 보호**이고 표본과 무관하다. "곧 회복될 것"이라는 기대로 한도를 넘기지 않는다.
🔴 중단 시 **시점·사유·그때까지의 실현손익을 기록**한다. 남은 자료로 성과를 재판정하지 않는다.

### 확대 조건 — 네 가지를 **모두** 충족할 때만

| 조건 | 요구 |
|---|---|
| 표본 | 실전 왕복 거래 **≥ 30건** |
| 체결 비용 | 실측 왕복 **≤ 0.40%** |
| 수익성 | 그 실측 비용으로 재계산한 **거래당 순수익률 ≥ 0.10%** |
| 알파 | 동일기간 벤치마크 대비 **≥ 0** |

충족 시 **자본을 2배까지** 올린다(500,000 → 1,000,000). 한 번에 2배를 넘기지 않고,
올린 뒤에는 **표본 30건을 다시 모아** 같은 네 조건을 재확인한다.
🔴 확대는 **결과가 좋아서**가 아니라 **위 네 조건이 충족돼서** 한다. 조건을 그때 고치지 않는다.

## 5. 이 문서를 바꿀 수 있는 경우

| 허용 | 금지 |
|---|---|
| **엄격해지는 방향**의 수정 (한도를 줄이고, 표본을 늘리고, 관문을 추가) | 🔴 느슨해지는 방향의 수정 |
| 코드·설정 사실의 **정정** (예: 상수가 실제로 다른 값이었다) | 🔴 결과를 본 뒤의 기준 변경 |
| 운영 오류·위험 대응 (기록 필수) | 🔴 사후에 다른 팔·다른 코인·다른 구간을 끌어오는 것 |

수정할 때는 **무엇을·왜·언제** 바꿨는지 이 문서에 남긴다. 조용히 고치지 않는다.
