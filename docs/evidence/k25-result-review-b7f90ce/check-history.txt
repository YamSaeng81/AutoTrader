총괄 검토 실행 이력(제품 시험 아님)
1. review.py 첫 실행: errors-all-deploy/after30 파일에 원시 ERROR 3줄이 있을 것으로 잘못 단언해 중단했다(AssertionError).
   실제 U3/U4 원문에서 errors-all은 이미 캔들 최신성·기존 NOT404 필터를 지난 파일이다. 네 오류 파일이 0바이트인 것을 확인했다.
   검토 코드의 파일 의미 단언만 고쳤다. 제품 코드·제출 근거·기존 시험·실행 블록은 바꾸지 않았다.
   원시 로그 3건 집계는 개발 보고이며, 세 전체 로그는 서버에만 있어 이번 총괄 검토가 독립 재집계한 값이 아니다.
2. 두 번째 실행: ': 완료 ' 문자열 수로 성공 출처 6개를 세어 완료 0인 CryptoPanic까지 포함했다(AssertionError).
   완료 건수가 양수이고 미완료가 0인 출처 줄을 세도록 검토 코드만 고쳤다. 제출 출력과 제품 기대값은 그대로다.
3. 세 번째 실행: 전송 본문 끝에 줄바꿈이 항상 있다고 가정해 전송 기록을 바로 붙여 비교했다(AssertionError).
   원본 네 파일은 서버 보존 해시와 같다. 본문 모든 줄 뒤에 last_send 한 줄만 더해지는지 비교하도록 고쳤다.
   바이트 대조는 각 파일의 서버 해시·커밋 블롭 검사에서 별도로 유지한다.
4. 네 번째 실행: 파이프가 있는 줄 모두를 DB 키로 세어 완료 표지 END|ok까지 포함했다(AssertionError).
   소문자 DB 키 계약의 32행과 완료 표지를 구분하도록 검토 코드만 고쳤다. 파서 제품 코드는 바꾸지 않았다.
5. 문서 검사 첫 실행: F1이 git 결과 파일의 첫 줄로 HEAD를 비교하는데 직접 명령 치환으로 비교할 것으로 잘못 단언했다.
   원문 형태에 맞춰 검사했다. 이 확인 중 F1의 실패 안내문에 이전 7a94472 이름이 남은 것도 발견해 ee509cf로 맞췄다.
   실제 HEAD 비교는 이미 갱신된 NEW를 읽고 있었다. 안내문 정정 뒤 F1 블록 해시를 다시 계산했다.
