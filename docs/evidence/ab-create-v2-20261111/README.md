## 2. 생성 운용안과 호출기 (`RUNBOOK.md`, `create/`)

- **경로:** 기존 `POST /api/v1/paper-trading/sessions` + `Authorization: Bearer`입니다. 토큰은 파일 경로로만 받고, 출력·기록부·명령줄에 넣지 않습니다.
- **`/sessions/multi`는 쓰지 않습니다.** `MultiStrategyPaperRequest`는 전략 목록·코인·주기·자본·텔레그램만 받습니다(소스 확인).
- **소스로 확인한 응답 사실:**
  - 거절(`IllegalStateException`)은 **HTTP 200 + `success:false`**로 옵니다. HTTP 200만 보면 안 됩니다.
  - 생성 응답과 목록에는 `investRatio`·`stopLossPct`·`maxHoldHours`가 없습니다. 그래서 **같은 쌍의 A·B가 API로 구분되지 않습니다.** 팔별 저장값은 생성 뒤 읽기 전용 질의(`create/post_creation_check.sql`, 미실행)로만 확인됩니다.
- **공통 T0:** 생성 API는 곧바로 RUNNING을 만듭니다.
  - 그래서 M15 경계 C에서 6~12분 사이에만 보냅니다. 그 회차의 후보 수집 마감(C+5분)이 지나 첫 BUY 접수가 거절되므로, 첫 거래는 C+15분 = T0 이후입니다.
  - 생성 뒤 T0 이전 주문·포지션 0을 다시 확인합니다.
  - 이 방법은 진입 회차가 켜져 있어야 성립합니다(선행 조건 0-4).
- **호출기 `create/ab_create.py`:**
  - 계획만 모드가 기본입니다.
  - 응답을 HTTP 코드·`success`·새 정수 id·응답 저장값으로 판정합니다.
  - OK가 아니면 즉시 멈추고 다시 보내지 않습니다.
  - 기록부에 결과가 있으면 다시 실행해도 보내지 않습니다.
  - 멈추거나 끝나면 목록으로 팔별 실제 생성을 대조합니다.
- **대역 시험(`create/test_ab_create.py`, 대역 `standin_server.py`): 9/9 통과입니다(`create/test-run.txt`).** 다음 사례를 봅니다.
  - 계획만 모드
  - 정상 8개(T0 = C+15분)
  - 창 밖 2개 시각(5분 59초, 12분 1초)
  - 401 / 500 / HTTP 200 + success=false / 생성됐는데 시간 초과 / 응답 저장값 불일치: 각각 그 지점에서 멈추고 POST 수가 그 횟수입니다. 대조 결과가 맞고, 재실행은 보내지 않습니다(종료 4).
  - 같은 서명 세션이 이미 있으면 보내지 않습니다.
  - 모든 사례에서 토큰 문자열이 표준 출력과 기록 파일에 0번 나오고, 서버는 매 호출 `Bearer` 헤더를 받습니다.
- **첫 실행 실패(출력은 재실행이 덮었음):** 6건이 실패했습니다. 대조가 쌍 서명으로만 세션을 찾아 같은 쌍의 A·B가 서로의 결과로 섞였습니다. 위의 "A·B 구분 불가" 사실이 원인이었습니다. OK 응답 id로 팔을 귀속하고, 귀속되지 않은 새 id를 멈춘 팔에 붙이도록 도구를 고쳤습니다. 시험 기대는 바꾸지 않았습니다.
- **대역의 지연:** `timeout_at` 사례에서 대역 서버가 3초 늦게 응답합니다. 호출기의 1초 시간 초과를 만들기 위한 서버 쪽 지연이며, 시험 통과를 위한 대기가 아닙니다.
- **`plan-only/plan.json`:** 계획만 모드로 만든 v2 본문 8개입니다. v1 초안과 다른 점은 확정 모드 키를 더한 것뿐입니다.
