# 청산 A/B 8세션 생성 운용안 — 미실행 (v1.145 §3-4)

**실제 생성은 승인되지 않았습니다.** 이 문서는 승인 뒤 그대로 따를 순서입니다. 각 단계에 기대, 멈춤 조건, 보고 항목을 적었습니다. 토큰을 요청하기 전에 호출 경로와 대역을 먼저 완성했습니다(`create/`, 대역 시험 9/9).

## 0. 선행 조건 (모두 충족 전에는 1단계로 가지 않음)

| # | 조건 | 확인 방법 | 아니면 |
|---|---|---|---|
| 0-1 | 총괄이 생성을 승인했다 | 지시문 | 멈춤 |
| 0-2 | 운영에 LIVE_ALIGNED 보완 후보가 배포됐고 그 SHA가 고정됐다 | 배포 기록 | 멈춤. 모드 키가 없는 서버에서 생성하면 종전 PAPER가 된다 |
| 0-3 | 두 전략이 활성이다 | 읽기 전용 질의: `strategy_type_enabled`, `strategy_timeframe_enabled` | 멈춤 |
| 0-4 | 진입 회차가 켜져 있다(운영 단계가 등록 단계) | 설정 읽기: `trading.capital-pool.stage` | 멈춤. 꺼져 있으면 첫 평가에서 바로 매수할 수 있어 2단계 창 방법이 성립하지 않는다 |
| 0-5 | 토큰은 운영자가 파일로 둔다 | 경로만 받는다 | 명령줄·화면·대화에 값을 쓰지 않는다 |
| 0-6 | `protocol.json` sha256이 `8d787fe9…d3db`이다 | `sha256sum` | 멈춤. 프로토콜이 바뀌었다 |

## 1. 계획만 실행 (보내는 것 없음)

```bash
python -X utf8 create/ab_create.py --base-url <운영 API> --token-file <경로> --protocol tool/protocol.json \
  --out-dir <기록 폴더> --code-sha <0-2의 SHA>
```

- **기대:** 종료 2, `plan.json`에 본문 8개가 있습니다. A에는 `stopLossPct` 키가 없고 B는 5입니다. 8개 모두 `strategyParams`가 `{"paperMaxInvestment":20000,"paperExecutionMode":"LIVE_ALIGNED"}`입니다.
- **보고:** 본문 sha256 8개.

## 2. 생성 (승인된 경우에만, `--execute`)

1. **창 확인:** 지금이 지난 M15 경계 C에서 6~12분 사이일 때만 실행합니다.
   - 그 회차의 후보 수집 마감(C+5분)이 지났으므로, 새 세션의 첫 BUY 접수는 "회차 마감 뒤 도착"으로 거절됩니다.
   - 다음 봉은 C+15분 = **T0**에 닫힙니다. 첫 거래는 T0 이후에만 생길 수 있습니다.
   - 창 밖이면 도구가 아무것도 보내지 않고 끝납니다(종료 2). 기다리는 장치는 두지 않습니다. 다음 창에 사람이 다시 실행합니다.
2. **사전 확인(도구 자동):** 목록 조회 `success`를 봅니다. 같은 쌍 서명의 RUNNING 세션이 이미 있으면 보내지 않습니다(종료 2).
3. **POST 8회:** 고정 순서로 1회씩 보냅니다. 응답마다 HTTP 코드, `success`, 새 정수 id, 응답 저장값(전략·코인·주기·자본·파라미터·RUNNING·시작 시각)을 봅니다.
   - **멈춤:** 401·403, HTTP≠200, `success≠true`(운영은 거절을 HTTP 200 + `success:false`로 줍니다), 시간 초과·응답 불명, 새 id 아님, 저장값 불일치 중 하나라도 나오면 즉시 멈춥니다.
   - **재전송 금지:** 멈춘 뒤에는 그 본문도, 남은 본문도 보내지 않습니다.
4. **대조(도구 자동):** 목록을 다시 읽어 팔마다 실제 생성된 세션을 셉니다.
   - 같은 쌍의 A·B는 목록으로 구분되지 않습니다(응답에 `stopLossPct`가 없습니다). OK 응답 id로 팔을 귀속하고, 귀속되지 않은 새 id는 멈춘 팔에 붙입니다.
   - 응답 불명이어도 실제 생성 여부는 여기서 드러납니다.
5. **결과:**
   - 종료 0: 8개 OK, 쌍마다 정확히 2개, 생성 시각이 모두 T0 전입니다. `creation_log.draft.json`이 써집니다(`db_verified=false`).
   - 종료 3: 중간에 멈췄습니다. **새로 보내지 않고, 만든 세션도 정지하지 않고** 기록부와 대조 결과를 총괄에 보고합니다. 일부 생성·응답 불명 처리(남은 팔 생성, 기존 팔 정지, 새 T0)는 총괄 결정입니다.
   - 종료 4: 기록부에 이미 결과가 있어 보내지 않았습니다. 기록부를 보고합니다.

## 3. 생성 직후 읽기 전용 확인 (`create/post_creation_check.sql`)

- **@@stored 기대:** 8행입니다. 모두 RUNNING·M15·100000·0.8·24, 파라미터는 프로토콜과 같습니다. **A `stop_loss_pct` NULL, B 5.00**이고 `started_at < T0`입니다. 팔별 하한은 이 질의로만 확인됩니다.
- **@@fingerprint 기대:** T0 전후 첫 평가 뒤 세션마다 지문이 하나입니다. 팔마다 다를 수 있으므로 같다고 요구하지 않습니다.
- **@@before_t0 기대:** T0 + 20분(첫 회차 마감 D+만료 여유) 뒤 다시 실행해 0, 0입니다. 하나라도 있으면 동시 시작이 성립하지 않습니다. 멈추고 보고합니다.
- **기록부 완성:** 위 결과로 `creation_log.draft.json`의 `stored`·`ruleset_hash`를 채우고 `db_verified=true`로 바꿉니다. 그 파일은 이후 바꾸지 않습니다. 집계기 v2가 이 기록부와 8세션을 대조합니다.

## 4. 하지 않는 것

- `/sessions/multi`를 쓰지 않습니다. 그 본문은 비율·손절·보유시간·`strategyParams`를 전달하지 못합니다(소스 확인).
- DB INSERT나 서비스 직접 호출로 우회하지 않습니다.
- 401이나 거절 뒤 토큰을 바꿔 바로 다시 보내지 않습니다. 보고가 먼저입니다.
- 비밀값을 출력·기록·명령줄에 넣지 않습니다. 도구는 토큰을 헤더에만 싣습니다. 대역 시험이 출력과 파일 전체에서 토큰 문자열 0을 확인합니다.
- 42일 동안 설정을 바꾸지 않고, 결과를 보고 연장·조기 종료·튜닝하지 않습니다.
