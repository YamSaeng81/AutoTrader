## 원인 (읽기만, 추가 실행 없음)

- r2 DB 읽기: 포지션 24 = `CLOSED`, `size 0.00019900`, `exit_reason TAKE_PROFIT`, `closed_at` 있음.
- 제품 LIVE 전량 매도 확정(`LiveTradingService` 3338~3346행, c43e1f1a)은 상태를 CLOSED로 바꾸고 손익·수수료를 더하지만 **`size`를 0으로 만들지 않는다**(체결 수량을 남긴다). 같은 저장소의 `OrderExecutionEngine` 2362행 경로는 `size=0`으로 닫는다. B의 4파일 변경과 무관한 기존 규칙이다(d81c3f2f→c43e1f1a 제품 차이에 이 부분 없음).
- 게이트 v3 31행 `p.status IN ('OPEN','CLOSING') OR p.size <> 0`은 CLOSED이면서 size가 남은 정상 청산도 잔량으로 센다. 합성 정상 세션은 `position(id, "CLOSED", "0")`으로 만들어 이 제품 규칙을 반영하지 못했다 → 합성 29/29가 실제 경로 결함을 못 잡았다.
- **판단: 제품 결함이 아니라 게이트 SQL(과 합성 고정 자료)의 가정 결함으로 본다.** 시험 기대값 문제도 아니다. 운영 1만원 시험에서 이 게이트를 그대로 쓰면 정상 왕복 뒤에도 FAIL이 나온다.

## 멈춘 범위와 필요한 결정

- 지시 §2에 따라 멈췄다. **전체 회귀·LF jar는 시작하지 않았다.** 추가 PG 회차·게이트 수정 실행 0.
- 다음 회차에 필요한 것(승인 전 미실행): 게이트 v4 — 잔량 조건을 `status IN ('OPEN','CLOSING')` 또는 `status <> 'CLOSED' AND size <> 0` 쪽으로 바꿀지 결정, 합성 정상 세션에 "CLOSED·size 남음" 사례 추가, 반대로 "OPEN인데 size 0" 같은 잔량 사례는 FAIL 유지. 그다음 격리 PG 새 회차 1회 → 통과 시 회귀·jar.
- 실제 서비스 매수·매도는 신호 평가를 건너뛴 로컬 시험이다. 자연 전략 신호·실제 거래소 연결·휴대폰 수신·운영 재기동은 검증하지 않았다.
