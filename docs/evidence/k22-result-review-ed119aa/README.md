1. 제출 README의 설치 전 `INSTALLED_SHA 930ee34e…`는 **파일 sha256**이다. `sha256(d491fd1의 40자리 + LF)`가 정확히 `930ee34e1e59d5761c83c3de19894ccd973c09be07a314373d02634a500b4369`다. marker 내용이930ee34e로 바뀐 것이 아니다. 원문을 덮어쓰지 않고 이 정정으로 구분한다.
2. HOLD 처리 줄이 없다고 질의가 실행되지 않았거나 처리량이 부족했다고 단정하지 않는다. 코드상 두 질의는 정기 경로에서 호출되고, **조회 결과가0행이어도 SQL은 실행**된다. 정상 신호 평가 완료 줄은 HOLD 단계보다 앞에서 찍히며 HOLD 단계 완료까지 증명하지 않는다. 따라서 이번 정기 HOLD 처리/질의 시간은 **로그로 확인하지 못함**이 정확하다. catchup의 HOLD23/23 및 정기01:50:21Z의0/2는 개발 보고에 남긴 요약이며 세부 원문 줄은 별도로 제출되지 않았다. 총괄이 직접 본 holdobs에는 catchup 시작/종료 시각만 있다.
