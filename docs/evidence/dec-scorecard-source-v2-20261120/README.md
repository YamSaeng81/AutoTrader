## 2. 계약 v2 (C1~C7)

| 규칙 | 내용 |
|---|---|
| C1 경계 값 | 월초 `from`과 월말 T의 값은 포착으로만 얻는다. 포착 시각이 경계와 같으면 그대로 쓴다. 다르면 **[경계, 포착] 공백 전체를 같은 시각 축으로 덮는** `no_change` 또는 `exact_restore` 근거가 있어야 확정이다. 그렇지 않으면 미확정이며, 현재값이나 0으로 채우지 않는다. 포착마다 실제 시각·축·`snapshot_id`·공백 초를 보고에 남긴다. T 값을 M 뒤에 포착했다면 근거가 있어도 받지 않는다. |
| C2 같은 스냅숏 | 세션의 가용 KRW·포지션·예약은 한 `snapshot_id` 안의 값만 함께 쓴다. 계좌는 `exchange` 축의 별도 포착으로 받으며, DB 포착과 동시라고 가정하지 않는다(보고 `same_db_snapshot:false`). |
| C3 월 귀속 | 월 귀속은 앱 관측/장부 반영 시각(BUY `filled_at`, SELL `sell_applied_at`)이 `[from,T)` 안에 있을 때만 한다. 이전 달 매도는 이 달 거래가 아니다. 이월 매수는 `carry_in_buys`에 원가를 따로 적는다. 거래소 체결 시각은 추정하지 않는다. |
| C4 주문 T 값 | `[T,M]` 포착이 `settlement_final`이고, 정산 대기가 아니며, `reported_observed_at < T`일 때만 확정한다(마지막 관측이 T 앞이라는 것이 불변 근거다). 아니면 정산 시각을 null로 넘기며, v3는 그 거래의 수수료·실현을 미확정으로 낸다. |
| C5 정정 | 연속한 포착 사이의 차이는 `{prev_capture, cur_capture, known_delta, observed_window, attribution}`으로 남긴다. 관측 구간이 한 달 안이면 그 달에 귀속하고, 달을 걸치면 **귀속 미확정**이다. 귀속 미확정 정정은 어느 달의 확정 손익에도 넣지 않는다. |
| C6 새 세션 | 기간 중 생성된 세션은 `started_in_period=true`, 기초0으로 계산한다. 기초 포착을 함께 주면 거절한다. 배정은 등록표 ALLOCATE 이벤트로만 넣는다. `initial_capital`은 최초 배정액과 대조하는 데만 쓰며, 값이 다르면 거절한다. 이벤트가 없을 때 `initial_capital`로 배정을 대신 만들지 않는다(순입금 미확정). |
| C7 자금 이벤트 | 고유 ref, 양수 유한 금액, 종류, KRW 통화, 적용·기록 시각(기록 ≥ 적용), 축, 세션 연결(배정·회수만 연결하고 입출금은 연결하지 않음)을 검사하고 중복 적용을 막는다. |

이 계약은 기존 세션의 월 기초에도 별도의 유효한 경계 자료를 요구한다(C1, S3f). 경계 포착 때문에 거래를 멈추거나 운영 스케줄을 바꾸지 않는다.

## 4. 하지 않은 것과 남은 결정

- DB 읽기 명령, 포착 수집기, 새 제품 열·이벤트 테이블은 만들지 않았다. 읽기 초안은 [등록표 v3 §5](../dec-registry-v3-p7v6-20261120/README.md)에 검토용으로만 두었다.
- 불변 근거(`no_change`)로 무엇을 인정할지는 정하지 않았다. 예를 들면 공백 동안 그 세션의 주문 0건과 배정 이벤트 0건을 같은 축으로 확인한 읽기다. 실제 근거의 종류는 읽기 초안을 검토할 때 정한다.

체크섬은 [SHA256SUMS](SHA256SUMS)에 있다.
