# 개입 #21 (N12) 관측 함수 `httpobs` 보완 — 계획 §5-9 63

2026-11-04 KST. 총괄 v1.94(§5-9 62)의 지시에 따른 로컬 보완이다. 서버·운영 DB·외부 HTTP 에는 접속하지 않았다. 운영자는 총괄이 검토하기 전에는 L 블록을 실행하지 않는다.

## 1. 바뀐 것

| 항목 | §61(v1.93) | §63(v1.95) |
|---|---|---|
| 짝 후보 | 뒤 5개 로그 머리 줄 중 아무 줄 | 뒤 5개 로그 머리 줄 안에서 **같은 스레드의 첫 줄 하나** |
| 짝 조건 | 같은 상태, sourceId 있으면 같은 값 | 위 줄이 같은 상태·같은 sourceId 의 상위 `FAILED 종류=HTTP_n … 받은=0건 신규=0건` |
| 결과 줄 재사용 | 여러 HTTP 줄이 같은 결과를 씀 | 한 번만 씀 |
| CoinGecko(HTTP 줄에 sourceId 없음) | 같은 상태면 어느 출처 결과든 짝 | 같은 스레드 첫 줄 규칙 + 그 sourceId 를 로그에서 다른 출처 클래스가 찍었으면 짝 아님 |
| 출력 | 요약 줄에 로그의 `sourceId=…` 원문 | 출처 클래스 이름 4개·상태 숫자·로그 시각(숫자)·건수·꼬리 글자 수만. sourceId·스레드 이름·꼬리·본문 출력 없음 |
| 판 표지 | `LV=61` | `LV=63` |

- 같은 스레드 규칙의 근거: 앱 `6995c52` 의 `NewsAggregatorService` 는 `source.fetch(config)` 를 호출한 같은 스레드에서 이어서 `수집 완료`/`수집 미완료` 를 기록한다. 그 사이에는 DEBUG 기록만 있다. 출처 HTTP 비200 줄 바로 다음의 같은 스레드 INFO/WARN 줄은 그 요청의 상위 결과다.
- 짝이 아니면 ⚪(종료 3)이고, 이유는 정해진 문구 다섯 가지 중 하나로만 낸다. 기존 5줄 제한으로 생기는 보수적인 ⚪ 는 그대로 둔다.
- 종료 1(🔴 본문 형식·연속 줄)과 미관측(종료 0) 판정은 §61 과 같다.
- 나머지 7개 블록은 판 표지 확인 줄 1줄만 바뀐다. 바뀐 줄 전체는 `l-to-m.diff` 에 있다.
  - L0~L4, L 뒤, L 되돌림: `= 61` → `= 63`, 문구 `§5-9 61` → `§5-9 63`.
  - 앱 `6995c52`·`LARX`·`(끝) 879 879`·복구 기준·`~/maint-n12`·`httpobs` 호출 위치와 종료값 처리는 그대로다.
- 계획 문서의 bash 블록은 84개에서 92개가 됐다. 앞 84개는 순서·바이트가 그대로다. §61 블록은 실행하지 않는다는 한 줄을 §61 머리에 더했다.

## 3. 하지 않은 것과 한계

- 앱 변경·실행 ID 추가·jar 재빌드·K1 jar 변형 시험·뉴스 시험·167건·전체 리허설·L 단계 대역 실행은 하지 않았다.
