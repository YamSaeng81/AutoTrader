## 2. SSH와 통신 판정의 정정

**SSH는 별도의 🔴 보안/접근성 후속으로 올린다.** 기존 DB 연결 획득 실패 P0와 구분한다. 대량 인증 실패·MaxStartups 제한은 확인됐지만 침입 성공은 입증되지 않았다. 현재 공격 지속 여부도 미확인이다.

| 사실 | 판정/한계 |
|---|---|
| 07:50~08:10 Failed 합계20,754, `143.198.x.x` 합계20,708 | **한 IP라고 확정할 수 없다.** supp.sh는 IP를 가린 뒤 합산하므로 같은 앞 두 옥텟의 여러 IP도 합쳐진다. 원래 로그·체크섬은 보존하고 새 메모로 정정 |
| 08:06:58 `00:48:31, 149646 connections dropped`, 08:07:02 제한 재시작 | 인증 전 연결 제한이 실제 작동했다. 149,646은 약48분31초 구간이며 20분의 실패 건수와 합치지 않는다. 개발 연결 끊김의 유력 원인이고 개별 연결 인과는 미확정 |

| `Failed password`·PAM 실패 | 비밀번호 인증 경로 노출 정황. 효과적인 sshd 설정은 미확인이다. supp.sh가 오류를 버리고 공통 문구를 쓰므로 sudo 권한 부족이라는 세부 원인까지 입증된 것은 아님 |

MFA/자동화 의존·IPv4/IPv6·공유기/호스트 방화벽을 확인해 실제 차분·복구 명령을 제출한다. 기존 연결/콘솔 복구 경로·별도 새 키 접속·백업·`sshd -t`·적용 뒤 새 접속 확인을 갖춘 뒤 **운영자 확인1회**를 받아 적용한다. 이번 지시로 설정/방화벽/포트/daemon을 바꾸거나 fail2ban을 설치하지 않는다. sudo 비밀번호나 DB 비밀번호를 대화로 요청하지 않는다.
