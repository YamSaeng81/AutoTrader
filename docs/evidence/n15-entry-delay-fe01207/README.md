## 3. 결론과 판단 대기

- **확인된 것**: 제때 접수된 후보의 승인 실행 시각에는 상한이 없다. 사전 등록 "최대 5분"은 강제되지 않는다. 지연은 (가) 공용 스케줄러 풀(8, `SchedulerConfig` 주석 기준 60초 틱 작업 9개와 공유) 포화, (나) 같은 회차 앞 후보의 승인 지연, (다) 앞 회차 처리 지연(`fixedDelay`)으로 생길 수 있다. 실제 운영에서 지연이 일어났다는 근거는 없다(운영 로그를 조회하지 않음. 현재 실자금 RUNNING 세션 없음, SID 203 `CREATED`).
- **영향**: LIVE 는 승인 시점 최신 캔들·블랙스완·BTC 관문을 다시 보므로 늦은 승인이 가격 면에서는 승인 시점 가격으로 들어간다. 다만 신호(마감 봉)는 1시간 이상 낡을 수 있고 EMA200·RANGE 는 다시 보지 않는다. DYNAMIC 은 승인 시점 시세를 읽지 않으므로 늦을수록 평가 때 종가 기준 주문·손절가가 실제 시세와 벌어진다(② 에서 손절가가 진입 순간 이미 시세 위).
- **수정하지 않은 이유**: 고치려면 "승인 실행 기한"이 필요하다. 수집 마감에서 바로 끊으면(기한 0) 정상 후보가 전부 거절된다. 처리는 마감 뒤 5초 주기로 시작하기 때문이다(지시 금지 사항). 새 숫자는 넣지 않았다.
- **판단 요청(총괄)**: 승인 실행 기한을 무엇으로 할지.
  - (가) **다음 캔들 마감**(`candleOpen + 2×타임프레임`) 전까지만 승인. 새 숫자 없이 DYNAMIC 주석의 기존 전제를 강제한다. H1 이면 수집 마감 뒤 최대 55분까지 허용되어 "최대 5분"보다 넓다. 권고: 최소 안전 하한으로 (가).
  - (나) 수집 마감 + 처리 허용 X분. 사전 등록 문구에 가깝지만 X 를 새로 정해야 한다.
  - (다) 코드 그대로 두고 PREREG·계획 §2-3·DYNAMIC 주석을 "처리 시각 상한 없음"으로 정정. 사전 등록 조건 변경이다.
  - 어느 쪽이든 검사는 회차가 아니라 **후보마다 승인 직전의 실제 시각**으로 해야 ③(앞 후보 지연)을 막는다. 이를 위해 `EntryPriorityRounds` 에 시계 주입이 필요하다. 거절 사유는 신호 기록(`blocked_reason`)에 남긴다.
- 계획 §2-3 표의 "마감 뒤 최대 5분 안에 승인"은 위 판단과 함께 정정할 문서 표현이다(지금은 고치지 않음).
- 정지 재확인·동시 처리·재기동은 기존 시험·근거로 충분하다(새 시험 없음). 범위 밖으로 남긴 것: 정지 후 대기 중 다시 `RUNNING` 이 된 세션의 옛 후보는 승인된다. 같은 회차의 재평가 접수는 중복으로 거절되므로 결과는 재평가와 같은 신호다. 결함으로 보지 않았다.
