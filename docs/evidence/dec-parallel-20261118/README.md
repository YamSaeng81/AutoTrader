### 2-4. 병행 운용용 등록·대조 계약 초안 (적용 전 제안)

1. **등록 세션 집합(외부 등록표):** 허용 실자금 세션을 `종류·ID·전략·주기·코인(고정 또는 DYNAMIC)·initialCapital·시작 시각·코드 SHA`로 고정한다. SID203은 기존 행 그대로다. 등록표 파일 해시를 N03 설치 기록에 남긴다.
2. **N03 키 분할:** `real_*`를 "등록 밖 실자금(기대 0, 🔴 유지)"과 "등록 세션별 상태(sid_*와 같은 규칙: 중복 매수·미결 지연·UNKNOWN·정산 불일치만 🔴)"로 나눈다. 등록 밖 판정은 **ID와 종류가 함께 맞을 때만** 허용한다. 제외 조건을 "DYNAMIC 전부"로 넓히지 않는다.
3. **계좌 합산 대조(F3 대체 후보):** `Δ거래소 KRW = Σ등록 세션 잔액 증감 ± 반올림(세션 수 × 1원)`, `Δ거래소 코인별 수량 = Σ등록 세션 순체결량 = Σ열린 포지션 수량`을 코인별로 맞춘다. **외부 입출금·미정산/CLOSING·회계 반영 대기·동시 주문 진행 중**이면 판정하지 않고 미확정(❔)으로 둔다. 기준 시점은 모든 등록 세션의 미결 주문 0인 순간으로 잡는다.
4. **세션별 대조:** 기존 SID203 F3-2 장부는 그대로 두고 DYNAMIC 등록 세션에 같은 형식의 세션 장부를 만든다. 세션 장부 합과 계좌 합산 대조가 둘 다 맞아야 정상이다.
5. **F1 변경 후보:** `EGS`의 DYNAMIC 활성 기대값을 등록표의 개수·ID와 대조하는 식으로 바꾼다. 미등록 활성은 계속 멈춤이다.
6. **시작 순서:** SID203 F1→F2를 먼저 끝내고(첫날 F3 단독 대조 보존), DYNAMIC은 별도 시각에 등록·생성·응답/DB 모드 대조 뒤 시작한다. 같은 분에 두 엔진의 첫 주문이 겹치지 않게 한다.
7. **기존 원문 보존:** 현재 F1/F3/F5 원문·설치본·체크섬은 SID203 단독 구간용으로 남긴다. 병행용은 새 절차 번호와 새 설치판으로 제출해 별도 판정을 받는다.

모의 9개 생성은 `paper-trading` 경로(가상 잔고)라 위 실자금 대조에 들어가지 않는다. 기존 승인 절차를 그대로 따른다.

### 4-2. 매회 최대 요청액 제안 (적용 안 함)

- **새 세션 설정 `maxOrderKrw`(명시 필수, 실자금만):** 요청액 = `min(둘째 자리 버림(가용 × 비율 × 배수), maxOrderKrw)`. 적용 위치는 `executeBuy`의 요청액 계산 직후·최소 주문 보정 앞이다(0e1d2a02 S:1663~1675). 예약 서비스의 등록 상한 검사는 **그대로 둔다** — 최종 보호선은 바뀌지 않는다. `maxOrderKrw ≤ perPositionCapKrw`를 생성 때 검사한다.
- **모의 차이:** PAPER에도 같은 식을 적용해야 엔진 동등이 유지된다. 미지정 PAPER는 종전 계산을 유지할지 따로 판정받는다.
- **최소 주문:** 상한으로 줄인 뒤에도 5,000원 미만이면 기존 규칙대로 차단한다. 감액 보정(5,000원 올림)은 상한 안에서만 적용한다.
- **기록:** 잘린 경우 `blocked_reason`과 다른 별도 표지(요청 원값·적용 상한)를 신호 기록에 남겨 월 성적표에서 "상한 적용 진입"을 구분한다.
- 자본·기본값·풀 한도는 바꾸지 않는다. 숫자는 사용자 금액 결정 뒤 정한다.
