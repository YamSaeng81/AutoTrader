## 3. 앞선 제출의 표현 정정 (원문은 고치지 않음)

- **§3-1** (`stop-race-wait-20261111`): "놀고 있는 작업자 경로였다는 것이 유일하게 맞는 설명"은 **"조기 읽기 확인, 유력 메커니즘 재현"**으로 한정합니다. 원래 실패 순간의 `queue.take`/worker-lock은 계측하지 않았습니다. 그리고 프록시를 벗긴 실행기 시험과 실제 `@Async` 전달 시험은 범위가 다릅니다.
- **§3-2** (`aligned-gaps-20261111` 1절): `RiskManagementService` "REAL/DYNAMIC 판정은 같은 식·같은 순서·같은 중단 조건"은 **사실이 아니었습니다.** 조회가 조기 반환 앞에 있었고(R6), 이번에 복원했습니다.
- **§3-2 B01 표 1행:** "판단 평균가 — 같음 선언, 관측 다름"은 LIVE 평균가의 수량 버림 차이(0.001% 미만) 때문입니다. 잔액 20,223.88은 확인한 사례의 결과이고, 평균가가 수학적으로 같아졌다는 뜻이 아닙니다.
- **§3-2 0원 정지 보완:** "최근 봉 종가로 정산"은 이번에 철회했습니다(R2). 키가 없는 PAPER의 0원 정지는 **별도 미해결 제품 결함**으로 남깁니다. 66의 규칙과 성과는 바꾸지도 열람하지도 않았고, 운영에서 0원 청산이 있었다고 추정하지 않습니다.

## 4. DDL 변경안 (제출만 — 운영 DB 변경 승인 아님)

판단 시각과 MDD 피크를 재기동에도 잃지 않으려면 열이 필요합니다. 규칙 지문(`strategy_params`)에 런타임 상태를 섞지 않기 위해 열로 둡니다.

```sql
-- V95 안 — 제출만, 적용하지 않음
ALTER TABLE paper_trading.position        ADD COLUMN IF NOT EXISTS exit_decided_at TIMESTAMPTZ NULL;  -- 청산 대기 판단 시각
ALTER TABLE paper_trading.virtual_balance ADD COLUMN IF NOT EXISTS mdd_peak_krw   NUMERIC(20,2) NULL; -- 선택 모드 MDD 피크
```

- **키 없는 세션:** 둘 다 NULL이라 읽지도 쓰지도 않습니다.
- **선택 모드:** 대기 표시 때 `exit_decided_at`을 쓰고, 서킷 브레이커 판단 때 피크를 올려 씁니다.
- **적용하지 않는 동안:** 판단 시각은 "미상(재기동 전)"으로 남고, 피크는 실현 고점 임시안으로 판단합니다.
