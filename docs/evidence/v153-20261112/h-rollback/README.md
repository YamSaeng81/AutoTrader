# H — 선택 모드 세션 생성 전/후 구판 복구 관문·로컬 PG 예행 (총괄 v1.153 H, 2026-11-12)

**초안이다. 운영 실행·DDL·세션 생성은 승인되지 않았다.** 자동 되돌림은 없다 — 관문은 판정만 하고, 바꾸는 명령은 사람이 고른다.

> 총괄 v1.154 §4: 이 1판은 체크섬 생성이 실패해도 `POST_CREATION_OK`·종료 0 으로 끝난다(총괄 재현). 기록 실패 시 성공을 막은 **2판은 `v2/`** 다(가짜 명령 10/10, PG 예행 10/10). 1판 파일은 원문 그대로 둔다.

## 1. 왜 생성 전/후를 나누는가

- 구판(b5cd1d0)은 V96 두 열이 남은 DB 에서 기동한다(aligned-v150 `pg/oldbin`: Flyway `96 FUTURE_SUCCESS`, validate·JPA validate 통과, 열 값 보존).
- **그러나 구판은 선택 모드를 모른다**(같은 근거):
  - `paperExecutionMode=LIVE_ALIGNED` 키를 해석하지 않는다. RUNNING 으로 남은 새 모드 세션은 구판의 종전 PAPER 규칙으로 돈다.
  - PAPER 포지션의 `CLOSING` 을 모른다. OPEN 조회 0, 잔고 API 가 기록 총자산을 현재 평가처럼 보이고, CLOSING 은 정산되지 않고 남는다.
- 그래서 **구판 기동 성공 = 복구 성공이 아니다.** 새 모드 세션이 생긴 뒤에는 아래 관문을 지나야 구판 복구를 한다.

## 2. 절차

| 시점 | 관문 판정(`rollback_gate.sh`) | 할 일 |
|---|---|---|
| 생성 전 | `PRE_CREATION_OK`(새 모드 세션 0) | 종전 D4 U되돌림 그대로. V96 열은 지우지 않는다 |
| 생성 후 | `STOP_RUNNING`(새 모드 RUNNING>0) | **새 바이너리에서** 그 세션들만 세션별 정지. 기존 66/REAL·PAPER 일괄 정지(`stop-all`)는 복구 도구로 쓰지 않는다(66 사전 등록 세션까지 멈춘다) |
| 생성 후 | `HOLD_PENDING`(CLOSING>0) | **구판 복구 보류.** 새 바이너리를 유지해 첫 유효 시세 정산을 기다린다. 0원 청산·행 삭제·상태 강제 변경으로 조건을 만들지 않는다. 보유·미확정 평가·판단 시각(`exit_decided_at`)을 보존한다 |
| 생성 후 | `STOP_MISMATCH`(정지된 새 모드 세션에 OPEN) / `STOP_UNKNOWN`(이상 상태값·판단 시각 없는 CLOSING·새 모드가 있는데 V96 열 없음·집계 실패) | 아무것도 바꾸지 않고 멈춘다. 원문 보존, 사람 판정 |
| 생성 후 | `POST_CREATION_OK`(RUNNING 0·OPEN 0·CLOSING 0·이상 0) | 관문이 마지막 장부(세션·포지션·주문 CSV + SHA256SUMS)를 **덮어쓰기 없이** 남긴 뒤 종전 U되돌림 |

- "진행 중 승인·정산 없음": 회차 승인 대기는 메모리에만 있고 세션 정지로 사라진다. DB 로 볼 수 있는 진행 상태는 CLOSING 이다. 그래서 관문은 RUNNING 0 과 CLOSING 0 을 함께 요구한다. 메모리 상태는 DB 로 증명하지 않는다(정지 뒤 다음 회차가 지난 것을 운영자가 로그로 확인하는 칸을 실행안에 둔다).
- 옛 로그 공백: U2/U되돌림 재생성 **직전에** 실행 중 컨테이너 로그를 읽기 전용으로 저장하고(`docker logs`), 저장 범위(첫·끝 줄 시각)를 기록부에 남긴다. 이미 확보하지 못한 과거 구간을 확보했다고 쓰지 않는다.
- V95→V97: 이번 후보는 V94+V96 만. main 의 미배포 V95 를 나중에 함께 내보낼 때는 번호를 V97 로 옮기는 별도 통합 차분·순서 계획이 필요하다(이번 범위 밖).
- 관문 실행 값(`PSQL` 명령의 컨테이너·사용자·DB)은 실행안의 변수 블록이 정한다. 이 초안은 서버 값을 추정하지 않는다.

## 3. 로컬 PG 예행 (`rehearse.sh`, 3회차 판정)

- 장소: 로컬 격리 컨테이너 `v152-pg`(TimescaleDB pg15, 이 작업이 만든 것). 운영 접속 없음.
- 템플릿 DB `h153` = 후보 aligned2 마이그레이션 V1..V94+V96 95개를 psql 로 순서대로 적용(실패 0).
- 사례마다 템플릿을 복사해 상태를 만들고 관문을 돌린다. 관문 전후 세 표(세션·포지션·주문) 내용 해시가 같아야 통과(읽기 전용 확인).
- **결과 10/10** (`runs/run3/`):

| 사례 | 상태 | 판정·종료 코드 |
|---|---|---|
| s1 | 키 없는 세션(66 과 같은 형태)만 RUNNING·OPEN | PRE_CREATION_OK 0 |
| s2 | 새 모드 STOPPED·CLOSED | POST_CREATION_OK 0 + 장부 3 CSV·SHA256SUMS |
| s3 | 새 모드 RUNNING | STOP_RUNNING 3 |
| s4 | 새 모드 STOPPED·CLOSING(판단 시각 있음) | HOLD_PENDING 2 |
| s5 | CLOSING 인데 판단 시각 없음 | STOP_UNKNOWN 3 |
| s6 | 새 모드 세션 상태값 PAUSED | STOP_UNKNOWN 3 |
| s7 | 새 모드 STOPPED·OPEN | STOP_MISMATCH 3 |
| s8 | 새 모드 있음·V96 열 없음 | STOP_UNKNOWN 3 |
| s9 | 새 모드 없음·V96 열 없음 | PRE_CREATION_OK 0 |
| s10 | s2 와 같으나 장부 폴더가 이미 있음 | LEDGER_REFUSED 4 |

- 실패 회차(원문 보존):
  - `run1-template-busy`: TimescaleDB 배경 작업자가 템플릿 DB 에 붙어 복사 거절 0/10. 예행 장치 결함 — 템플릿을 접속 불가로 두고 그 DB 배경 작업자만 끝내게 고쳤다.
  - `run2-ledger-command-tags`: 판정 10/10 이었으나 장부 CSV 첫·끝 줄에 psql 명령 표지(BEGIN/ROLLBACK)가 섞였다. 관문 결함 — `\set QUIET on` 으로 고쳤다.
- 대역으로 주장하지 않는 것: 실제 서버 psql 경로·권한, 실제 세션 정지 API, 첫 유효 시세 정산 시간, 운영 데이터의 상태 분포.

## 4. 독립 DYNAMIC 후보 81b0e7a7 — 초안 값만 점검

`dynamic-jar-81b0e7a7/README.md` §4 를 읽기만 했다. 고정 코인 후보와 합치거나 운영 반영하지 않았다.

- 값·대상: 기점 b5cd1d0, jar 항목 734=734(확장 881→881), 내용 차이 DynamicTradingService 계열 7개 + 모듈 jar 3개(시각만), DDL 없음 — 기존 제출 값 그대로다.
- 부작용: 배포 재기동 때 최근 240분의 DYN_PAPER 차단이 REAL 을 더는 막지 않는다(REAL 진입이 덜 막힐 수 있음). 초안에 적혀 있다.

- **새로 생긴 겹침:** F 후보 `ec7d33ef`(이번 v1.153 F)도 `DynamicTradingService.java` 를 바꾼다(실시간 처리기 애너테이션). 초안의 "두 후보 경로는 겹치지 않는다"는 aligned2 기준으로만 맞다. F 와 함께 내보내면 합친 커밋을 새로 만들고 jar 대조를 다시 해야 한다.
