# 생성 묶음 v4.2.1 중간 점검 — 마지막 기록 실패 뒤 성공 표지 잔존

2026-11-17, v1.178 후속 중간 보고에 대한 추가 지시다. 아직 고정 커밋 제출 전이므로 전체 도구를 수용하지 않는다. 검토한 실행 틀 해시는 **1c4bb697cefd17a7705a6c128ed361ba8723764ba88ef686fa35f1dc65985005**이며 보존 사본에 고정했다. 총괄은 제품 코드·개발 작업 중인 실행 틀을 고치지 않았다.

## 확인한 공백과 범위

`finish()`는 단계 rc 파일에 0을 쓴 다음 마지막 로그를 쓴다. 그 로그 쓰기가 실패하면 종료값은8이지만 rc 파일에는0이 남는다. `prev_ok()`는 그 파일만 읽으므로 다음 단계를 허용한다. 실제 도구 성공과 기록 성공이 함께 확정되지 않은 상태가 다음 단계의 성공 표지가 되는 공백이다.

보존 원문의 함수만 로컬 Bash에서 호출했다. 마지막 로그 쓰기 실패를 주입하면 `finish_exit=8 rc_file=0`, 이어 `next-step-allowed`, `next_stage_guard_exit=0`이 나온다. 전체 실행 틀·생성기·docker·서버·DB·네트워크는 실행하지 않았다. 결과는 [result.json](result.json), 재현기는 [probe_record.py](probe_record.py)다.

## 추가 지시

1. **기록 실패 뒤 성공 표지가 남지 않게 한다.** 성공은 필수 출력·로그·최종 표지까지 확인된 경우에만 확정한다. 그 이후 성공을 실패로 바꿀 필수 기록을 두지 않는다. 중간 종료나 기록 실패 흔적이 있으면 다음 단계가 거절해야 한다. 방법은 별도 임시/완료 표지와 순서 보완 등으로 최소 변경한다.
2. 도구0+마지막 로그 실패, 도구0+rc 파일만 쓰기 실패, 도구3+기록 실패, 성공 표지 확정 전 중단을 실패 주입으로 확인한다. 각각의 프로세스 종료값과 남은 파일을 보존하고 **그 상태로 다음 단계도 직접 호출해 도구 호출0**을 확인한다. Windows에서 권한으로 못 만들면 대역 쓰기 실패 또는 이미 허용된 로컬 Linux 환경을 사용한다. 미실행을 통과로 합산하지 않는다. 기존 도구 비정상 종료값은 보존한다.
3. 대역 PATH 결함은 수정 경위만 보존한다. 첫8/19 실행의 화면 출력과 임시 폴더는 남아 있지 않으므로 POST0은 당시 관측에 대한 제출자 설명으로 구분한다. 향후 대역 시작 전 도구 해석 경로 확인·허용 외 실행 차단을 유지하고, 원문 출력은 시험 종료 전에 별도로 보존한다.
4. **예약된 SMA20 로컬 HTTP/격리 PG 연결, N03·통신 읽기는 기존 승인대로 계속한다.** 이 실행 틀 보완으로 독립 작업 전체를 멈추지 않는다. 실행 여부와 실제 시각·종료값을 확인한 뒤 최종 묶음에 포함한다. 실제 운영 생성·T0는 여전히 검토 전이다.

사용 한도 중단의 제출 근거는 최종 고정 커밋에서 검토한다. 기록이 없는 구간을 작업·감시 또는 자동 재개 성공으로 쓰지 않는다. 이 보충 근거도 다음 실질 결과와 함께 커밋한다.
