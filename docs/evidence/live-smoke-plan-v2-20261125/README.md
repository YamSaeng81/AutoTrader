# 소액 실주문 시험 실행안 v2 — 1회 제한(maxEntries=1) 후보와 연결한 포함·검증 순서 (v1.242 §3-4)

2026-11-25 KST, 로컬 문서 작업이다. **운영 호출·주문·계좌 조회는 0회다.** v1([live-smoke-plan-20261124](../live-smoke-plan-20261124/README.md))은 체크섬 보존을 위해 고치지 않았다. 이 문서는 v1의 §0~§4를 그대로 따르고, 달라지는 점만 적는다. 실행 원문이 아니다.

**유지하는 사용자 승인:** 시험 전체의 누적 매수대금 + 매수 수수료 ≤ 10,000원, 합산 예산 10만원 안, 한 세션 한 왕복([v1.238](../live-smoke-authorization-20261124/README.md)). 다음 항목은 모두 **별도 수용 전**이다. 실제 계좌 여유(A3), 수수료 계약, 응답/DB 대조, 정지/청산, 복구 확인, 구체 실행 원문.

## 3. 안 B에서 v1과 달라지는 점

- **생성 본문:** v1 §2와 같다. 다만 `"strategyParams":{"maxEntries":1}`이다. 1은 정수로 보낸다. `1.0`·`"1"`은 생성 첫 줄에서 거절된다. 금액은 그대로 매수 요청 9,950원, 수수료 0.05% 포함 9,954.98원 이하다. 수수료율과 최소 주문액은 실행 환경의 계약으로 다시 확인한다.
- **C 생성 뒤 확인 추가:** 응답과 DB 행에서 `strategy_params->>'maxEntries' = '1'`이고 `session_type = REAL`인지 본다. 다르면 start하지 않는다.
- **재진입 차단의 주체가 바뀐다:** 두 번째 매수 의도는 제품이 거절한다. 그래서 매수 뒤 정지 시점이 사람의 반응 속도에 덜 묶인다. 정지 전에 자연 매도(신호·손절·익절)가 나면 그 경로도 관측할 수 있다. 그래도 **강제로 신호를 만들지 않는다.** 대기 창은 총괄이 정한다.
- **B 매수 뒤 확인 추가:** 그 세션의 LIVE BUY 행 수가 1이다. 이후 자연 신호가 와서 거절이 생기면 `ENTRY_LIMIT_REACHED` 로그와 행 수 1 유지를 기록한다. 거절이 생기지 않았으면 "거절 미관측"으로 적고 통과로 세지 않는다.
- **첫 시도가 체결 없이 끝나도 1회로 센다:** FAILED·CANCELLED·UNKNOWN 모두 센다(B 시험 ⑥). 그 세션에서는 다시 매수하지 않는다. 새 시험 세션을 만들지는 총괄이 다시 정한다. 자동으로 만들지 않는다.
- **종료:** v1 §3의 S2·X를 그대로 한다. 끝 판정은 [복구 확인 v2](../one-entry-recovery-sql-20261125/recovery-check-v2.sql)의 `_block` 4열이 0이고 STOPPED인 것이다. 거래소 잔량은 A3·장부로 따로 확인한다.
- **구판 복구가 필요할 때:** B판에서 시험 세션을 stop하고 위 확인이 통과한 뒤에만 되돌린다. 구판에서 그 세션을 start하지 않는다. 구판은 maxEntries를 무시하므로 재개하면 제한 없이 돈다.

## 4. 한계 — 그대로 남는 것

- 제한은 "새 매수 의도 최대 1회"이다. 금액 상한은 여전히 `initialCapital`·`maxInvestment`가 정한다.
- 정지와 동시 승인의 경합은 해결되지 않았다(stopSession은 계좌 잠금을 쓰지 않는다).
- 주문 행을 손으로 지우면 제한이 무력화된다. DB CHECK가 없다.
- 일봉 SMA20(안 A)은 신호가 드물다. 창 안에 매수가 없으면 **미실행**으로 끝낸다.
- 10,000원은 투입 제한이다. 급변·장애 때 손실 상한을 보장하지 않는다.

## 5. 총괄이 정할 것

1. B를 포함할지, 포함한다면 기점과 검증 범위(B2·B3)
2. 시험을 안 D(d81만, 사람 정지)로 먼저 할지, B 포함판까지 기다릴지
3. 전략 안 A/B, 대기 창, 실행 시각. 실행 시각은 R1=0·인수 뒤이고, 12-01 본운영과의 순서를 함께 정한다
4. A3 계좌 읽기 범위, 사전·사후 읽기 원문과 횟수, 복구 확인 SQL의 PG 검증
