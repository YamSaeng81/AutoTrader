## 2. 인증 관측과 관리자 읽기

11:22:55의 응답 **`Permission denied (publickey,password)`**, 키 인증/비밀번호 질문/접속 재사용을 끈 시도1회, 기대한 ssh 종료255를 확인했다. **그 계정·출발 조건에서 서버가 password 방식을 제시한 것은 확인**했다. 비밀번호 인증 경로를 닫는 우선순위는 유지한다. 비밀번호 입력 성공이나 root/다른 출발지의 정책, 설정 파일 값을 확인한 것은 아니다. [RFC4252의 방식 목록](https://www.rfc-editor.org/rfc/rfc4252#section-5.1)은 목록에 있는 방식의 실제 성공까지 보장하지 않으므로 유효 설정 확인을 대신하지 않는다.

**운영자가 자신의 관리자 권한으로 제한 읽기를 진행하는 범위는 허용한다.** 개발 세션에 sudo 비밀번호를 넘기거나 권한 설정을 넓힐 필요는 없다. bc5a39d9의 admin_read.sh(0b8f3c32…)는 수집용으로 사용하되 아래 한계를 함께 기록하고, 그 출력만으로 변경 가능 표지를 만들지 않는다.

- 스크립트는 `host=addr`를 **UseDNS no로 가정**하지만 UseDNS 값을 수집하지 않는다. 같은 관리자 읽기에서 서비스와 같은 설정/인자의 `sshd -T` 결과 중 usedns 값을 추가로 확인한다. no가 아니거나 Match Host/추가 Include/명령줄 옵션이 있으면 지금5조건을 실제 접속의 완전한 정책이라고 쓰지 않고 실제 hostname 조건까지 다시 고정한다. [UseDNS·Match 규칙](https://man.openbsd.org/sshd_config.5#UseDNS)을 따른다.
- 전체 종료0은 개별 읽기 성공이 아니다. sshd -t/-T 각 종료값·필수 키 존재·설정/키 목록 해시·방화벽 실패를 분리한다. 필수 읽기가 실패하면 **미확인**으로 보고하며 빈 해시를 변경 전제에 쓰지 않는다. 가림/키 본문 검사가0인지 확인한 뒤에만 결과를 가져온다.
- 운영자 답은 승인 계정·키/MFA/자동화 의존, 콘솔/복구 접근, 공유기 관리 포트와 다른 전달 범위다. 이미 모은7일 로그를 다시 수집하지 않는다. 관리자 실행이 불가능하면 그 항목만 대기하고 아래 로컬 보완을 계속한다.

## 3. 추가 관측 — 변경·복구 묶음은 보완 필요

원본 분기를 분리하고 경로를 이 검토 폴더의 임시 파일로 바꾸었다. 실제 파일 복사/삭제는 그 임시 파일에만 했고 sshd/systemctl은 무해한 대역이다. 실제 운영에서 발생했다는 뜻은 아니다.

| 입력 | 현행 관측 | 필요한 계약 |
|---|---|---|
| 정상 복구 대조 | 이번 설정 삭제·reload·종료0 | 유지 |
| 00설정이 제3 내용으로 바뀜 | **그 파일을 삭제하고 reload, 종료0** | 이번 변경판/원판/제3/조회 불명을 먼저 판정 |
| 주 설정이 백업과 달라짐 | **주의만 출력한 뒤 삭제·reload, 종료0** | 전제 불일치면 변경·reload 없이 사람 판단 |
| authorized_keys에 후속 키가 추가됨 | **백업으로 덮어써 후속 내용을 잃고 종료0** | 백업판/이번 추가판 이외는 덮어쓰지 않음 |
| reload 명령0·서비스 inactive | **inactive를 출력하면서 종료0** | 실제 active·확인 가능 상태가 아니면 실패/미확인 |

백업 체크섬이 맞는 것과 현재 파일이 이 작업의 산출물인 것은 별개다. 삭제/복원 전 설정·포함 파일 집합·키 파일의 현재 출처를 모두 판정하고, 하나라도 제3/조회 불명이면 **변경 명령0**으로 멈추는 최소 보완을 만든다. stage 검사 실패 때 지우는 파일도 자신이 놓은 바이트인지 확인한다. 키 추가 직후 해시/권한·지문과 설정 stage 직후 해시를 기록해 복구 전제로 삼고, 백업 목록 생성/검증 실패는 성공으로 가리지 않는다. active/조회 불명도 종료값과 기록으로 구분한다. 변경된 경로의 음성 사례만 추가하며 실제 서버에는 적용하지 않는다.
