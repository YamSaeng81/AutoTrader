## 2. 새 공백 R1 — POST가 자동 GET으로 바뀐다

`create/ab_create.py`의 Client.call은 직접 GET을 거절한다. 그러나 기본 urllib.request.urlopen은 **301·302·303의 Location을 자동 추적하며 POST를 GET으로 바꾼다.** 같은 전체 목록 URL을 Location으로 주자 POST → GET 2요청이 발생했고, 가짜 세션560의 성과 필드가 든 목록 응답이 함수로 반환됐다. 307·308은 POST 한 번 뒤 멈추는 대조군이다. 외부 통신·실제 성과 조회는 없었으며 운영에서 리다이렉트가 있었는지도 미확인이다.

1. **생성 HTTP 클라이언트의 모든 자동 리다이렉트를 금지한다.** 같은/다른 경로·호스트, 301/302/303/307/308 모두 두 번째 요청0으로 확인한다. 응답을 따라가거나 POST를 재시도하지 않는다. 3xx는 접수 여부 불명으로 기록하고 남은 팔 전송도 중단한다. DB 메타 대조는 잠정 확인일 뿐 자동 재전송 근거가 아니다.
2. 기존 GET 직접 거절·정상8 POST·거절/불명/기록 실패 계약은 유지한다. 이 보완 전 위 입력이 실패하고 보완 뒤 통과하는 국소 시험과 영향받는 도구 시험을 제출한다. 새 SMA20 단건 도구도 같은 전송 규칙을 쓴다. 기존 v4.1 제출·원문·체크섬을 고치지 않는다.
3. 실제 생성 묶음의 기본 URL은 검토한 backend 직접 경로로 고정한다. 프록시·로그인으로 리다이렉트되는 주소를 묵인하지 않는다. backend 전체 회귀·jar·서버 배포를 이 도구 변경 때문에 반복하지 않는다.

4. 차트 제목 대비의 독립 frontend 최소 후보와 밝은/어두운 테마 표시를 확인한다. 9본문·생성/확인 도구·SQL·실행 틀의 출처/해시·구체 창/T0·인증 경로·부분 생성 후 중단을 한 고정 묶음으로 제출한다. 실제 생성·T0 실행은 검토 뒤 결정한다.
