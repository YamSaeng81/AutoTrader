# 1eed27d1 회귀 중 경계 탐침 후속 지시

## 1. 판정

- **CLOSING과 SELL 의도 생성의 원자성은 유지한다.** 옛 탐침을 통과시키려고 의도 생성을 비동기 작업 안으로 되돌리지 않는다.
- `SubmitOrderBoundaryProbeTest`는 최초 `TradeLogRepository.save()` 하나를 제출 경계로 삼아, 그 기록이 정지 트랜잭션에 합류하지 않는다고 단언한다. 이 시험은 84fb03d6 대비 바뀌지 않았다.
- 현재 최초 기록은 `null → INTENT_READY`이며 CLOSING과 같은 트랜잭션에서 만드는 것이 허용된 새 계약이다. 따라서 이 단언은 단계별 계약으로 보완한다. 시험 삭제·실패 제외·단언 완화로 처리하지 않는다.
- `PositionLimitTest`의 H2 보완은 **실자금 손실 합산 관문만 승인으로 대역 처리하는 범위**로 허용한다. 포지션 한도·신선도·정지 단언과 제품 코드는 유지한다. 이 H2 결과는 손실 보호식 검증 근거가 아니며 해당 실제 PG 근거와 분리한다.

## 2. 탐침이 고정할 네 경계

같은 주문 ID와 전이의 `oldState/newState`로 관측을 연결한다. “첫 save”나 트랜잭션 이름 하나만으로 단계를 구분하지 않는다.

| 단계 | 단언할 계약 |
|---|---|
| CLOSING 및 `null → INTENT_READY` | 정지 호출자의 같은 트랜잭션 안에서 함께 저장. 커밋 전 외부 주문 0 |
| `INTENT_READY → SUBMITTING` claim | 호출자 커밋 뒤, 다른 작업 스레드의 활성 트랜잭션. 호출자의 트랜잭션에 합류하지 않음 |
| 거래소 `createOrder` 대역 호출 | 다른 작업 스레드에서 **실제 DB 트랜잭션 비활성**. 호출 1회 |
| `SUBMITTING → SUBMITTED` 결과 저장 | 별도의 활성 트랜잭션. 같은 주문의 상태 반영 1회, 최종 주문 행 1개 |

**거래소 HTTP 호출은 “자체 트랜잭션 안”이 아니다.** 현재 `callExchangeAndRecord()`는 조회/결과 저장만 `submitTx`로 감싸고 외부 호출은 그 밖에서 한다. 보고서의 표현도 이 경계에 맞춘다.

- 트랜잭션의 동일/분리는 실제 자원 또는 동기화 경계로 확인하고, 이름 문자열만으로 결론내리지 않는다.
- 완료 대기는 해당 주문의 실제 제출·결과 커밋을 기준으로 한다. 작업자 수/빈 큐만 보고 통과시키지 않으며, 정해진 대기 한도 내 오지 않으면 실패한다.
- 기존 `ClosingIntentRollbackPgTest`의 호출자 롤백 시 의도·CLOSING 함께 롤백 및 외부 호출 0, `ClosingIntentAtomicityPgTest`의 중복/거절/응답 불명 보호는 유지한다. 이미 확보한 동일 제품판 PG 근거는 출처·바이트를 대조해 연결하고, 변경 영향이나 미확인 경계가 있을 때 추가 실행한다.
