# 실주문 실행 초안 v3 — HTTP·기록·시작 확인 보완

2026-11-28 KST, 총괄 v1.255. 원본 v2와 과거 체크섬은 보존하고 새 사본에서 준비했다. 제품·운영 이미지·설치본은 변경하지 않았고 이 초안으로 SSH/POST/DB/계좌를 실행하지 않았다. 현재 상태와 실제 사전 조회는 [후속 준비](../postdeploy-next-20261128/README.md)에 있다.

## 변경과 확인

- `safe_api.py`: 기존 서버 .env의 인증값을 프로세스 메모리에서만 읽고 localhost의 허용된 GET/생성/시작/정지 경로에만 보낸다. curl 인자에 Bearer 값을 넣지 않는다. HTTP 비2xx·손상 JSON·success=false·data 누락/error이면 실패한다. 예외/서비스 오류 원문을 출력하지 않는다.
- 생성/시작/정지는 POST 전 noclobber 표지를 쓰고 응답을 직접 파일에 기록한다. HTTP나 기록이 실패하면 다음 단계로 넘어가지 않는다. 시작 뒤에는 DB가 정확히 `RUNNING|t`여야 한다. stop은 정산·청산을 포함하는 기존 API다.
- 생성 대조는 REAL·전략·코인·주기·원금·비율·주문 상한·손절·보유시간·maxEntries와 시작 전 상태를 확인한다. 고정 LIVE 생성 DTO에는 sessionType 입력 필드가 없어 미지원 필드를 보내지 않고 저장/응답 REAL을 대조한다.
- q/종료 게이트 SQL에는 읽기 전용·15초/2초 PGOPTIONS를 넣었다. watch의 일치 로그 0행은 정상 0행으로 처리하되 검색 자체의 오류는 실패한다.
- 사용자 수신/대응 확인 `OPERATOR_READY=yes`와 외부 수동 거래/입출금 중지 `EXTERNAL_FREEZE=yes`가 없으면 생성·시작을 거절한다. 현재 두 값은 비어 있고 추정으로 채우지 않았다.
- 전체 `set -e`를 적용하고 단계별 실패를 명시 처리했다. 로컬 RUN_TAG 형식·서버 별칭·원문 가독성도 검사한다. 기존 gate v4·KST 변환기·제품은 바꾸지 않았다.
- 원문 조립기의 마지막 `[ "$STEP" = gate ] && ...`가 P0 같은 비gate 단계에서 1을 반환하는 틈을 고쳤다. v2 정상 P0 조립은 rc1, v3는 rc0임을 파일 출력으로 재현했다. 읽을 원문이 없으면 조립 자체도 실패한다.

## 직접 영향 검사

- `boundary-results.json`: **12/12**. HTTP 정상, 비2xx, 손상 JSON, success=false, data.error, data 누락/배열, 허용 밖 경로를 opener 전에 거절. shell 함수 검사로 RUNNING 확인, CREATED 미변경 거절, HTTP 실패 거절, 필수 표지 쓰기 실패 시 api 호출0을 확인했다.
- `payload-results.json`: v2/v3의 P0 조립만 각각 실행해 기대한 rc1/rc0. 조립된 원문을 실행하지 않았고 SSH 호출0이다.
- bash -n: launch/smoke 모두 통과. 전체 launch/smoke 연결, 실제 HTTP POST, 운영 PG, 생성·시작·정지·게이트는 실행하지 않았다. 기존 PG/회귀/jar·v2의 시험 묶음도 반복하지 않았다.

## 실행 전 남은 조건

이 초안은 완성된 무인 시험 배치가 아니다. 사람이 답해야 하는 수신/대응·APENFT 기존 보유 분리·외부 거래 중지와 새 날짜/창/결과 이름, 시작 직전 신선한 원천 대조가 남아 있다. 현재 P0의 반올림 계좌 요약은 필요조건뿐이며, 별도 실제 order-chance의 정확한 KRW/BTC·수수료·최소 주문 및 배정 원천으로 보완해야 한다. 이 읽기들의 선후 구간을 원자적 스냅숏이나 P7 전체 관측으로 선언하지 않는다.

실제 start 전에 서버에서 독립적으로 지속되는 유한 관측/정지 담당·종료 시각과 경합 대응도 고정해야 한다. 자연 신호를 기다리며 매수가 없으면 미체결/미실행으로 기록한다. 신호를 조작하거나 전략을 바꿔 체결을 만들지 않는다. 매수 의도는 상태 무관 1회 제한으로 소비되며 실패/취소 뒤에도 재시도하지 않는다. stop 매도는 자연 전략 매도와 구분하고 gate v4 PASS 및 계좌/잔량 대조 뒤에만 종료한다.

따라서 v3의 검증된 함수/조립 보완을 수용하되, 전체 실행·실전 시작 완료로 확대하지 않는다. 실제 운영 단계는 후속 준비 문서의 작업 순서대로 진행한다.
