## 3. 해석 (v1.235 §3-4)

1. **ORIG 9 = SPLIT P 9이고 A는 0이다.** 9는 같은 스냅숏에서 다시 계산한 값이다. 그래도 10:30의 9를 재현했다고 쓰지 않는다. 시각이 다르고, 행이 같은 9건인지는 확인할 수 없다. UQ union_items가 9이므로 겹침 없이 **고유 포지션 9건**이다.
2. **9건 모두 REAL 모드 DYNAMIC 세션의 CLOSED 포지션이다.** 이 포지션들에는 매수·매도를 통틀어 **주문 행이 하나도 없다**(N_NO_ORDERS 9). exit_reason은 NULL이다. PAPER·NO_ROW·OTHER 혼입은 0이다. 따라서 "모드 조인 누락으로 모의 행이 섞였다"는 가설은 이번 스냅숏에서 지지되지 않는다.
3. **R1에 걸린 경로는 ④ NO_SOURCE다.** 체결 BUY도 확정 SELL도 없는데 무거래 확정 예외를 받지 못했다. 현재 예외(`CONFIRMED_NO_TRADE`)의 첫 갈래는 `exit_reason='ENTRY_REJECTED'`·size 0·주문 0을 모두 요구한다. 이 9건은 주문이 0이고 exit_reason이 NULL이라 이 갈래에 들지 못한다. 둘째 갈래는 BUY 주문이 있어야 하므로 해당이 없다. N_ER_SIZE_NOT_ZERO가 0이므로 "ENTRY_REJECTED인데 size만 0이 아님"도 아니다. size 값 자체는 읽지 않았다.
4. **원천 결측 가설(V81/V87 이전 매수)은 이 9건에 해당하지 않는다.** A 분기 0, AX/AF 0, LEG before_v81·before_v87 0, opened_null 0이다. 9건 모두 V87 설치(10-16) 뒤에 열렸다. LEG는 보조 지표일 뿐이며 인과를 입증하지 않는다는 점은 그대로다.
5. **AGE: 9건 모두 D00_06이다.** 30일 창에서 빠지기까지 남은 일수가 0~6일이라는 뜻이다. 즉 closed_at이 DB 기준 [10-25 04:49Z, 11-01 04:49Z) 안에 있다. 그러므로 같은 조건의 새 행이 생기지 않는다면 **늦어도 12-01 04:49Z(DB 시각 기준) 전에 9건 모두 R1에서 자연히 빠진다.** 버킷 단위라 행별 정확한 만료일은 모른다. 앱 시계 기준이면 수 초 차이가 있을 수 있다.
6. **판정 연결(r1-diag §6 표):** "PX NO_SOURCE·PF N_*" 행에 해당한다. 이것이 **무거래 확정 정의의 누락**(주문 없이 닫힌 포지션을 무거래로 봐야 하는 경우)인지, **실제 원천 결측**(주문이 있었는데 행이 없음)인지는 이 읽기로 확정하지 않는다. 확정하려면 이런 포지션을 만드는 제품 경로를 알아야 한다. 즉 주문 생성 전에 포지션이 CLOSED로 닫히고 exit_reason이 비는 경로다.

## 4. 한계

- 집계뿐이다. 행별 시각·세션·size·주문 이력은 없다. 9건이 한 세션에 몰렸는지 여러 세션에 흩어졌는지도 모른다.
- DB `now()` 기준이고, 제품은 앱 `Instant.now()` 기준이다.
- 운영 중인 0e1d2a02에는 R1 관문이 없다. R1은 d81c3f2f를 배포한 뒤에 진입을 막는다. 이 결과는 "배포하면 DYNAMIC R1>0으로 LIVE를 포함한 신규 실자금 진입이 최대 약 7일간 거절된다"는 근거다. 단, 그동안 같은 종류의 새 행이 생기지 않는다는 전제에서다.
- 사용률은 관측하지 못했다(미확인이며, 0으로 두지 않음).
