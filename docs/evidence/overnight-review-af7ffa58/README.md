## 3. 배포 전 로컬 보완 — 우선순위대로 계속한다

### 3-1. DynamicStopRaceTest의 대기를 정확히 만들고 실패를 설명한다

1차 XML은 `[DYNAMIC 정지→claim] state=INTENT_READY`를 출력한 직후 같은 주문318에 대해 18:16:05.000~.001에 `WITHDRAWN_STOPPED` 철회 로그를 남긴다. 이는 정지 확인이 동작하지 않았다는 확정 근거가 아니고, 비동기 완료 전 읽기 가능성을 뒷받침한다.

총괄의 `DrainWitness.java`는 시험의 조건(큐 비었음·active0·taskCount=completed)을 그대로 사용했다. idle worker가 작업을 큐에서 꺼낸 뒤 실행 표시를 잡기 전을 latch로 고정하면 **drained=true인데 executed=false**가 재현된다. 원래 Spring 실패가 반드시 이 창이었다고 확정한 것은 아니다. 총괄 1차 하네스는 시작 worker를 막아 active1이라 재현하지 못했고, 수정 경위를 r1/r2에 보존했다.

개발은 실제 제출 작업의 완료(Future/완료 신호/정확한 주문 종결 상태)를 기다리도록 시험을 보완하고, 미완료를 정상 종료로 보지 않게 한다. 실패 시 타임아웃은 실패다. 임의 sleep·기대값 완화·반복해서 녹색 얻기·시험 제외는 쓰지 않는다. 고정 재현과 기존 정지/정산 단언을 같이 확인한다. 제품 결함이 확인되면 그 경계를 별도 보고한다. 최종 후보가 안정되기 전 전체 회귀를 반복하지 않는다.

### 3-2. LIVE_ALIGNED에 남은 매매 판단 차이를 닫는다

제출 요약의 “진입·거절·청산이 이제 같다”는 **검사한 사례에 한정**한다. 상세 근거에는 다음이 남아 있다.

- **평균가·수수료**: 실제 매수 뒤 LIVE는 체결 평균가, PAPER는 수수료 포함 원가를 평균가로 쓴다. ±0.3% 전략 SELL 등 판단 경계가 달라진다. A12는 평균가를 동일하게 미리 넣은 매도 시험이라 이 차이를 닫지 않는다. 새 선택 모드에서 판단용 체결 평균가와 비용/원가를 구분하고, 같은 체결·수수료 입력의 **실제 매수→경계판정→매도→잔액/손익**을 끝까지 대조한다. 기존 PAPER 회계/66 기록은 바꾸지 않는다. 수수료를 빼먹거나 두 번 차감하지 않는다.
- **급변 시 손절 확인**: LIVE는 급변 시1초, 새 모드는5초 고정이다. 가격 경로에 따라 매도 시점이 달라질 수 있다. 정상5초·급변1초의 실제 경계를 같은 입력으로 재사용/검증한다. 이미 있는 실제 처리기 호출 시험을 확장하되 매번 throttle 지도를 지워서 간격 검증을 대신하지 않는다.
- **위험 관문**: 세션 서킷 브레이커까지 REAL 전용으로 묶어 빠뜨린 상태다. 공통 판단은 같은 기준으로 검증하고, REAL 계좌/공유 풀과 분리된 모의 계좌 상태를 입력으로 쓰는 최소 설계를 작성한다. REAL 자금을 배정하거나 차감하지 않는다. 현재처럼 대응물이 없음을 기록하는 것만으로 “전체 동일”을 선언하지 않는다. SMA20의 실제 자본/한도 비교와 독립 A/B 팔의 가상 계좌를 구분한다. 큰 개편이 필요하면 구체적 경계만 제출하고 다른 보완을 계속한다.
- **가격 없는 시간 청산**: LIVE 시장가 의도와 PAPER 다음 틱 지연은 아직 다르다. 청산 판단/요청 시점과 체결 가능 가격의 차이를 분리해 기록·검증한다. 단순 가격 부재를 “청산 판단도 없었음”으로 숨기지 않는다.
- **새 비동기 경계**: `approveAlignedEntry`의 E검사는 `executeBuy` 호출 앞에 있고, 뒤에 규칙/지문 조회와 여러 save가 있다. `alignedLock`은 새 평가/승인/RT끼리만 공유하며 기존 `stop()`은 이 잠금을 쓰지 않는다. 현 단계는 소스상 검증 공백으로 기록한다. E 도달·정지 커밋·RT/평가 청산 경합을 latch로 고정해 시험하고, 차감·포지션·주문·잔액이 부분 반영되거나 중복되면 선택 모드의 같은 트랜잭션/정지 경계에서 최소 수정한다. 실제 DB 행 잠금을 판단할 때만 로컬 PG를 사용한다. 기존 REAL 경로를 완화하지 않는다.

### 3-3. 회차가 켜진 76+9 간섭과 처리 여유를 확인한다

F와 후속 포지션 시험은 합성 입력/H2에서 기존76 결정·청산·잔액 변화0을 보였다. 그러나 **회차 비활성, A/B8은 기존 PAPER**, REAL표는 애초0행인 대조다. 운영 STAGE_1 회차 + 새9 LIVE_ALIGNED를 검증한 것이 아니다. 틱568ms와1083ms도 부하 근거가 아니다.

확정한 모드로 로컬76+9를 구성하고 회차 활성·REAL 후보·열린 포지션을 함께 넣는다. 동일회차 REAL우선뿐 아니라 서로 다른 만기 회차 사이에 느린 PAPER 승인으로 REAL이 지연되는지, 만료/정지·스케줄러와 marketDataExecutor/구독 합집합이 기존 판단에 영향을 주는지 확인한다. 입력과 캐시를 고정해 틱/승인/RT 지연을 비교하고 환경/표본 수와 한계를 기록한다. 운영 부하 시험은 이번 지시에 없다. 새 세션이 없을 때 기존 결과가 그대로인 대조도 남긴다.

### 3-4. A/B 집계와 생성 계약을 보완한다

총괄은 제출 `check_config`와 합성 fixture를 바꾸지 않고 다음 네 입력을 넣었다. **모두 ACCEPTED**였다(`review.json`).

1. 4쌍 모두 같은 전략+BTC로 바꿈.
2. 모든 팔 원금을200000으로 바꿈.
3. 모든 팔 주기를H1으로 바꿈.
4. P4만 코드SHA를 다른 값으로 바꿈(쌍 안에서는 같음).

현재 검사는 쌍 내부 동등성 위주이며 고정 실험의 네 조합·100000/0.8/20000/24·모드·전체 동일 SHA를 강제하지 않는다. **불변 프로토콜/생성 기록부와 전체8세션을 대조**해 이 입력들을 거절하도록 보완한다. 지문은 팔마다 다를 수 있으므로 무조건 동일성을 요구하지 말고 생성 기록부와 맞춘다. 비용·미실현/빈 날·끝 가격 미확인 단언은 그대로 유지한다. 이 문제는 실제 성과가 틀렸다는 판정이 아니며 아직 합성 자료만 썼다.

생성 API는 곧바로 RUNNING으로 만든다. 8회 POST 후 T0를 적는 것만으로 동시 시작이 보장되지 않는다. **공통 T0 이전 거래0·일부 생성 실패/응답 불명 시 중복 생성 방지·저장 설정 재확인**을 포함하는 운용안을 완성한다. HTTP200만 보지 않고 `success`, 새 ID, 저장값을 대조한다. 401/거절/응답불명은 무작정 재POST하지 않는다. `/sessions/multi`가 모든 설정을 전달하는지도 확인 전에는 대체하지 않는다. 비밀값을 요구하기 전에 호출 경로와 대역을 완성한다. 실제 생성 승인은 아직 아니다.

### 3-5. DYNAMIC 격리 후보와 D4 안내 정정

- 쿨다운은 종류×코인으로 기록/조회/복원을 맞춘다. PAPER→REAL·REAL→PAPER 간섭없음, 각 종류의 재기동 전후 동일, REAL 자체차단/만료/진입가 가드 보존을 같은 입력으로 확인한다. 이것을 시장 전체 급락 보호 기준 완화로 확장하지 않는다.
- D4 README §4의 “U1에서 멈추면 U1되돌림”, “U2 뒤에 멈추면 U되돌림”은 너무 넓다. 실제 블록은 checkout 전, BTC 미충족, P0 보고 등 처리가 다르다. **checkout 전에는 U1되돌림 금지; checkout 뒤 해당 조건에만; 운영 되돌림은 명시된 ‘되돌림 필요’ 또는 총괄 지시 때만**으로 안내를 맞춘다. 자동 되돌림을 넣지 않는다.
- 새 SHA가 고정되면 변경 경로·실제 로컬 jar·기대 출력·실행 블록과 복구 기준을 함께 갱신한다. af7의 기대값을 새 후보에 그대로 복사하지 않는다. 바뀐 로직과 복구 경계만 대역 확인하고, 배포 직전에는 U3~뒤 관측의 권한/담당을 먼저 마련한다.

## 4. 기록·일정

지금 바로 위 로컬 작업을 이어갈 수 있다. 선행 원인 규명이 막히면 집계/생성안/쿨다운 격리 등 독립 작업으로 넘어간다. 근거·후보 커밋/push는 기존 권한 안에서 진행하고, 운영 변경은 검토 뒤다. A/B를 빨리 시작하려고 비교 조건을 약화하거나 기존66의 성과를 열지 않는다.

아침 인계는 이미 존재하는07:50 원본의 실제 시각으로 채운다. 대기 종료 시각을 읽기 시각으로 쓰지 않는다. 09:30 장부/10시 보고는 생성 후 기존 승인 범위로 읽는다. 총괄의 이번 문서·검토 근거는 다음 실제 결과와 함께 그대로 넣고 설정 권한 파일은 제외한다. 과거 체크섬/원문은 불변이다.

12-01 08:50 제한시험 목표는 유지하지만 이번 국소 통과가 수익성 검증은 아니다. 42일 A/B는 아직 시작하지 않았으며 12-01 이전에42일 결과가 나오는 일정도 아니다. SMA20의 전향 관측과 실전 시작 판단, A/B의 청산 정책 탐색을 구분한다.

총괄 실행 범위: Git/소스/보존 원문·체크섬 검토, 합성 집계기4음성+1정상 입력, JDK 대기 조건 소형 재현뿐이다. 서버 접속·운영 변경·제품 시험/Gradle/jar·커밋/push는 하지 않았다. 수익률이나 전략 성과를 새로 계산하지 않았다.
