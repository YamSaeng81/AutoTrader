## 1. 무슨 일이 있었나

A1 실행기 초안 [a1-read.sh](../a1-time-20261123/approval/a1-read.sh)의 종료 경로(정상·핀 불일치·보호값 없음·표준오류·빈 출력·SSH 255)를 **가짜 ssh**로 시험하려 했다. 가짜 ssh는 로컬 일회용 컨테이너(postgres:15-alpine, 합성 행)에 연결하도록 만들었다([fake-ssh-not-used.sh](fake-ssh-not-used.sh)).

시험 명령이 `PATH="$TEMP/claude/a1test/bin:$PATH"`로 가짜를 앞에 두었으나, Git Bash의 `$TEMP`가 Windows 형식(`C:\Users\…\Temp`)이라 콜론에서 PATH가 끊겼다. 그래서 **실제 `/usr/bin/ssh`가 `cat-prod`로 접속**했다. 출력의 `OT합 7026 / CNT주문 7026 · PT합 199`(합성 값은 6/3)를 보고 즉시 알아채 중단했다.

## 2. 보존

- 6회의 실행 기록 전체를 [runs/](runs/)에 모드 이름별로 옮겼다(원래 임시 폴더 `…\Temp\claude\a1test`). 해시는 [SHA256SUMS](SHA256SUMS)(79파일), 줄바꿈 보존을 위해 `.gitattributes`(`* -text`).
- 각 `a1.tsv`는 14줄이다. META 시각만 달라 해시가 다르다. 개발 세션은 OT/PT 합 대조 줄(7,026/199) 외 내용을 해석·판정에 쓰지 않았다.

## 3. 원인과 재발 방지(제안, 총괄 판단 전)

- 원인: 시험 도구가 실제 운영 별칭 `cat-prod`를 쓰는 실행기를 그대로 돌렸고, 가짜가 실제로 선택됐는지 **실행 전에 확인하지 않았다**.
- 제안: 가짜 시험은 (1) `cygpath -u`로 변환한 경로만 PATH에 넣고, (2) `command -v ssh`가 가짜 경로인지 확인한 뒤에만 실행하며, (3) 실행기 사본의 호스트 별칭을 존재하지 않는 이름으로 바꾼 사본에서만 돌린다. 세 조건 중 하나라도 어기면 시작하지 않는다.
- 실행기 본체(a1-read.sh)의 결함은 아니지만, 가짜 경로 시험은 아직 완료되지 않았다.
