# 총괄 v1.232 — 운영 대리 위임과 D81 배포 착수 지시

2026-11-23 KST. 사용자 지시: 총괄을 운영 대리인으로 지정하고, 필요하다고 판단하면 배포를 지시하며, 최종 결정은 사용자에게 남긴다. 필요한 야간 작업은 배치로 이어 가도록 요청했다. 이 문서는 [v1.231](../review-3444c40c/README.md)의 승인 경계를 아래 범위에서 갱신한다. 과거 지시·실행 원문은 고치지 않는다.

## 1. 운영 대리 판단과 역할

**D81 배포가 필요하다.** 운영 0e1d2a02에서는 매수 수수료를 포함한 실제 손실과 손실 보호 입력이 달라지는 결함이 확인됐고, d81c3f2f는 그 보완과 직접 영향·전체 회귀·PG 근거를 갖췄다. 문서 보완을 계속 늘리는 대신 승인된 배포 절차로 실제 인수 단계에 진입한다. 이는 수익성 입증이나 실자금 매매 시작 승인이 아니다.

| 역할 | 담당·권한 |
|---|---|
| 최종 의사결정 | 사용자. U2 재기동 직전 결과를 보고 최종 확인 1회. 실자금 생성/시작·전략/배정 결정도 사용자에게 남김 |
| 운영 대리·검토 | 총괄 Codex. 준비 수용, 실행 범위·일정 지정, 보고된 실제 결과 검토와 중단/후속 지시. 반복적인 준비 승인 질문을 줄임 |
| 실행 | Claude Code의 단일 실행 세션. 검토된 원문으로 실행·원문 보존·검사·보고. 총괄과 동시에 운영 명령을 실행하지 않음 |

대리인 지정은 휴대폰 실제 수신, 관리자 권한, 콘솔 복구, 부재 시 인간 대응을 확인한 것으로 대신하지 않는다. 총괄/Claude 세션은 상시 감시·야간 자동 기상·즉시 대응을 보장하지 않는다. 실제 사람만 확인할 항목은 미확인으로 남기되, 그것을 로컬 준비/U0/U1 전체 중단 사유로 묶지 않는다.

## 2. 승인하는 실행 범위 — D81 U0·U1

**11-24 10:30~12:00 KST에 한 번의 배포 준비 시도를 승인한다.** 실행자는 Claude Code다. 먼저 해당 회차의 10:00 보고·09:30 장부를 기존 고정 read.sh로 회수한 실제 결과를 확인한다. 이미 회수된 회차는 재회수하지 않는다. 회수 실패/부분 상태, 새 매매·정산/P0 안전 이상, 운영 기대값 불일치이면 U0에 진입하지 않고 보고한다.

- 출처: 제품 `d81c3f2f`, 실행 D81A2 `65a384e5`, U0 `91ea9342`, JARM `33a06f0e`, 복구 관문 4판. 커밋에서 꺼낸 11블록의 고정 해시를 확인한다. 요약으로 명령을 재작성하지 않는다.
- **U0 안 A2 SQL v3 R1~R3의 지정 금액 조회·판정 출력도 승인한다.** 이 SQL은 U0 안 1회만 사용한다. 실패 원문은 검토된 보정대로 서버에 남기고 고정 사유/종료값/경로/해시만 보고한다. 추가 A1·A3·계좌 조회·과거 행 상세/금액 조회는 포함하지 않는다.
- U0 통과 후 원문 조건대로 30분 안에 U1을 시작한다. U1의 검토된 backend 빌드·git 전환·조건부 보존 태그 생성까지 승인한다. backend 재기동·frontend 변경은 하지 않는다. JARM 불일치/소유 불명/기록 실패/관문 거절이면 다음 단계로 넘어가지 않는다.
- **U1이 끝나면 U2 직전에서 멈추고**, 실제 U0/U1 시각·종료값·현재 실행 컨테이너·새 이미지 대응·JARM·복구 태그·새 안전 이상 여부를 사용자에게 한 번에 제시한다. 사용자에게 **“재기동 진행”** 확인을 1회 받는다. 이 문서만으로 U2를 실행하지 않는다.
- U2 확인을 받으면 그때 승인된 창과 고정 출처가 유효한지 다시 확인하고, U2→U3→U4→뒤 관측으로 이어 간다. 확인이 늦어 실행 창이 끝나거나 원문 전제가 깨지면 결과를 보존하고 대리인에게 새 창 판단을 요청한다. 원문 시간 조건을 임의로 늘리거나 배포 기록을 다시 쓰지 않는다.
- U0/U1 실패 시 해당 단계에 연결된 검토된 복구 블록을 그 전제·관문 안에서만 사용한다. 복구 실패/출처 불명/STOP_INCOMPATIBLE이면 즉시 멈춘다. 자동 재시도·태그 강제 덮기·DB 열거값 수정·미완료 표지 삭제는 하지 않는다. 상태가 부분적으로 바뀌었으면 무엇이 바뀌었는지 먼저 보고한다.

이번에 정한 창은 U0/U1 준비 창이다. 야간 무인 재기동, 실전 시작, 자금 이동/배정, 새 세션 생성, SSH 보안 설정 변경은 포함하지 않는다. 휴대폰/보안 등 실제 시작 인수 조건은 여전히 실전 시작 전에 닫아야 한다. r6 A3 충분 판정은 배포의 선행 조건으로 붙이지 않는다.

## 3. 오늘 밤~11-24 아침 작업 배치

기존 검토된 실행기·예약 기능을 사용하며 **새 상시 운영 배치 시스템/cron을 만들지 않는다.** 같은 작업은 한 세션에서만 실행한다. 세션이 종료되거나 PC가 절전이면 실행되지 않을 수 있음을 인계한다.

1. 11-23 22:00 N03 회수는 기존 4bc9e12a의 실제 상태/결과를 확인해 중복 없이 1회만 수행한다. 이미 실행됐으면 결과만 회수한다. 고정 read.sh `41e4f337`, 장부 없는 회차, 실패 자동 재시도 없음. 원문·해시·실제 시각을 보존한다.
2. 그 뒤 로컬에서 D81A2 고정 출처/블록 해시와 기존 인수표를 연결하고, 위 승인 창·실행자·U2 최종 확인자를 표에 기입한다. 실제 미확인 항목은 그대로 둔다. 새 PG·회귀·jar 빌드·가짜 SSH 시험은 돌리지 않는다. U1에서 필요한 서버 빌드와 기존 로컬 검증 반복을 구분한다.

4. 준비가 끝나면 커밋·일반 푸시·커밋 블롭 체크섬 확인을 마치고 기다린다. 사용량 80%가 실제 확인되면 필수 기록을 먼저 확정하고 대기한다. 초기화가 관측되면 미완료 작업부터 재개한다. 사용률을 못 읽는다는 이유로 0%로 쓰지 않고 작은 단위로 진행한다. PC/세션이 사라진 뒤의 자동 재개를 보장하지 않는다.
