## 1. A3 — 계좌 요약의 반올림·시각 명세

### 1-1. 원천과 출력 (0e1d2a02 `AccountService.java`, d81c3f2f와 같음)

| 출력 필드 | 원천 | 처리 | 정밀도 |
|---|---|---|---|
| `availableKrw` | 업비트 계좌 조회의 KRW `balance`(b) | 122행 `setScale(0, HALF_UP)` | 원 단위. 원천 b ∈ [출력−0.5, 출력+0.5) |
| `lockedKrw` | KRW `locked`(l) | 123행 같은 처리 | 같음 |
| `totalKrwBalance` | b+l(49행, 반올림 전 합) | 124행 같은 처리 | b+l 에 **반올림 1회** |
| 코인 `balance`·`locked`·`totalQuantity` | 업비트 원문 | 반올림 없음(101~103행) | 원문 그대로. BTC 수량은 정확히 대조할 수 있다 |
| `fetchedAt` | `Instant.now()`(130행) | 계좌 조회(41행)와 코인별 시세 조회가 모두 끝난 뒤 응답을 조립하는 시각 | 앱 서버 시계, UTC |

- 세 KRW 필드를 각각 반올림하므로 `availableKrw + lockedKrw`는 `totalKrwBalance`와 −1·0·+1원만큼 다를 수 있다. 예: 원천 0.49+0.49 → 출력 0+0, 합계 출력 1. 원천 0.5+0.5 → 출력 1+1, 합계 출력 1.
- KRW 계좌 줄이 응답에 없으면 세 필드가 모두 0이 된다(47~48행). 이때는 "0원"과 "KRW 줄 없음"을 구분할 수 없다. 계좌 조회 예외면 `error` 키가 생기고 KRW 필드는 없다(132~135행).
- `fetchedAt`은 거래소가 잔고를 읽은 시각이 아니며 DB 장부와 같은 스냅숏도 아니다. 계좌 조회는 그보다 앞서고, 시세 조회 시간만큼 차이가 난다.

### 1-2. 기존 F3 허용 기준은 그대로

RUNBOOK F3(267행)·F5-3(487행)의 "거래소 KRW 증감 = 세션 증감 ±1원"은 그대로 둔다. 이 기준은 두 회차의 `availableKrw+lockedKrw` 차이에 대한 기존 계약이다. **"1원 미만이면 허용"을 다른 산출의 공통 예외로 넓히지 않는다.**

### 1-3. 새 미배정 현금 산출 명세

| 항목 | 정의 |
|---|---|
| 사용 필드 | `totalKrwBalance` 하나만 쓴다(반올림 1회). `availableKrw+lockedKrw`는 참고로만 적는다(반올림 2회) |
| 차감 | 같은 회차 DB의 RUNNING/CREATED 실전 세션 `available_krw`(소수 2자리, 반올림 없음)의 합 S |
| 결과 | 미배정 현금 원천 범위 **[R−0.5−S, R+0.5−S)**. 점 값으로 "정확히 일치"를 선언하지 않는다 |
| 필요액 판정 | 범위 하한 ≥ 필요액이면 충분, 상한 ≤ 필요액이면 부족, 필요액이 범위 안이면 **미확정(반올림 경계)** |
| 중복 차감 방지 | 업비트 `locked`는 미체결 매수 주문의 잠금액을 포함한다. 이것을 세션 잔액이나 예약과 따로 빼면 같은 돈을 두 번 뺄 수 있다. 그래서 **진행 주문·정리 대기가 0이 아니거나 `lockedKrw`≠0이면 산출하지 않고 보류**한다. 진행 주문이 있을 때의 차감 규칙은 정하지 않는다 |
| 기대 총액 대조 | 자금 이벤트 기록(입금·출금·외부 매매)으로 기대 KRW 총액이 있으면, R의 반올림 범위 밖의 차이는 **확정 설명 없는 차이로 보류·보고**한다. 허용 오차로 흡수하지 않는다 |
| 시각 | 호출 직전 t0·직후 t1(서버 `date`)을 기록하고 t0 ≤ `fetchedAt` ≤ t1을 확인한다. 장부 SQL의 DB `now()`를 따로 적는다(서버·DB·앱 세 축을 구분한다). 두 시각 사이 구간에 그 세션의 주문 생성·체결·취소가 있거나 시각이 없으면 계산을 보류한다 |
| 계좌 실패 | `error` 키나 KRW 필드가 없으면 미확정이다. 0으로 채우지 않는다 |

**파일 사례 r1 — [a3calc.py](a3/a3calc.py), [결과](a3/a3-r1.tsv), [입력](a3/cases/) 8/8 기대 일치:** 반올림 두 번의 차이(c1), 필요 79,800원이 범위 안인 경계(c2 → 미확정), 충분(c3), 기대 총액과 10원 차이(c4 → 보류·보고), 진행 주문(c5 → 보류), 조회 실패(c6 → 미확정), 시각 없음(c7 → 보류), 구간 안 주문(c8 → 보류).

c2가 뜻하는 것: 계좌가 정확히 100,000원으로 보여도 원천은 99,999.5원일 수 있다. 이 경우 20,200원 배정 뒤 79,800원이 남는지는 요약 응답만으로 확정할 수 없다. **정밀 원천이 필요하면** 업비트 KRW `balance`·`locked` 원문 2열만 출력하는 별도 읽기안(호출 1회·서버 안·KRW 줄만)을 총괄에 제출한다. 지금 조회하지 않으며, 이 묶음의 승인 대상도 아니다.
