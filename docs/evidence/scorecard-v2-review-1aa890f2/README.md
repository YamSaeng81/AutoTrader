## 판단 1·2 — SMA20 후보, 상한 저장 위치와 배포

### 상한 지원은 부분 수용, 새 열은 지금 추가하지 않는다

`strategy_params.paperMaxInvestment`를 **PAPER 실행 설정으로 명시적으로 예약**하는 최소 방식은 이번 범위에서 채택한다. 검증·지문·기존 키 없는 경로를 보존한다면 새 열/마이그레이션이 꼭 필요하지 않다. 미배포 V95를 함께 넣지 않는다. “V95와 겹쳐서 새 열은 불가능”이라는 뜻은 아니며, 현재 변경 규모에 대한 선택이다.

국소 보완 한 건은 필요하다. 후보 helper의 `get(KEY) == null`은 **키 없음과 명시적 null을 같은 것으로 처리**한다. 실제 후보 helper를 JDK17로 컴파일해 `paperMaxInvestment:null, initialCapital:100000`이면 상한도 위반도 null, 즉 상한 없는 세션으로 통과함을 확인했다. “키가 있는데 숫자가 아니면 거절”이라는 제출 계약과 다르다. `containsKey`로 두 경우를 구분하고 명시적 null은 생성 전에 거절한다. 키 없음/정상 숫자/숫자 문자열/0·음수/형식 이상/명시적 null을 DTO·서비스 경로에서 필요한 국소 시험으로 고정한다. 입력 원문을 오류에 그대로 붙일 필요도 없다. 기존 최소 원금·상한 없는 PAPER 기본 동작은 유지한다.

17항목 차이표를 만든 것은 올바르다. 특히 다음은 결과를 바꿀 수 있는 **판단·감시 차이**다.

66성과 비열람/T0/분모/종료 조건은 그대로다. 120 상한 안이라는 사실만으로 추가 세션의 간섭이 없다고 보지 않는다. 생성 전 현재 RUNNING 수와 `(coin,timeframe)` 조합·루프/수집 부하를 확인한다. 66 **성과는 읽지 않고** 기존 설정/부하 메타데이터만 쓴다.

로컬 대역에서 기존 66과 신규 1(SMA20) + 8(A/B) 부하를 겹쳐 입력 신선도·평가 지연·순서/캐시 공유를 확인한다. 연구 세션의 실행 상태·잔액·시세/위험 상태가 기존 66이나 REAL을 바꾸지 않는지 확인한다. 실효성 있는 격리가 안 되면 별도 연구 실행기/격리 런타임 방안을 만든다. 이때도 기존 66을 정지/재시작하거나 계약을 바꾸지 않는다. **부하·동작 정렬 검토 뒤 운영 생성 여부를 결정**한다.
