## 2. 도구 — `n06_prepare.py`

새로 짠 추출기가 아니다. 계획의 F2-1·F5-3 블록 **안에 적힌 awk 원문**을 꺼내 같은 명령으로 실행한다(손으로 옮기지 않는다). 하는 일은 다음과 같다.

1. 출처가 40자리 소문자 SHA이고 저장소에 있는지 본다. 아니면 종료 2 또는 1이다.
2. 계획 bash 블록 수(149)를 보고, F 15블록(색인 12~26) 해시를 v1.132 승인값([expected-v1.132.json](expected-v1.132.json))과 대조한다. 이 값은 n06-blocks.json에서 그대로 읽은 것이다.
3. F 변수 `NEW`, F1 `IMGF1`·이미지 기록 경로·설치값 다섯 개를 확인한다.
4. §3-1과 F3를 꺼내 해시를 대조한다. 옛 F3 `30b5e729…`는 거절한다. 꺼낸 F3가 계획 F3 블록과 바이트까지 같은지도 본다.
5. 실행 사본을 만든다.
   - F2-1·F5-3: 첫 줄 자리표시자만 40자리로 채운다. 정확히 한 번, 바뀐 줄 1개, 남은 자리표시자 0이어야 한다.
   - 종료 cron 사본: 3행 `FROM=CREATED; TO=RUNNING`만 `FROM=RUNNING; TO=<최종 상태>`로 바꾼다.
6. 문법을 본다.
   - 원문 두 개는 자리표시자 때문에 **그대로는 실행되지 않아야** 한다(`bash -n` 실패 = 통과).
   - 나머지 사본은 `bash -n`을 통과해야 한다.
7. 하나라도 어긋나면 사본을 쓰지 않고 `fail.json`만 남긴다. 출력 폴더가 이미 있으면 덮어쓰지 않는다(종료 2).
