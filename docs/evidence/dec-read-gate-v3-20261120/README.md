# 12월 준비 25 — 읽기 게이트 v3: R3 등록 밖 종결 행 기본 STOP (총괄 v1.205 §2·§4-2) — 운영 실행 금지

2026-11-20 KST, 개발 세션 제출(총괄 판정 전). [v1.205 지시](../review-read-gate-v2-20261120/README.md) §2의 결정대로 [v2](../dec-read-gate-v2-20261120/README.md)의 새 사본에서 R3만 고쳤다. v2 파일과 run1·run2는 그대로 보존한다. **운영 DB·제품 PG·애플리케이션·빌드·회귀는 실행하지 않았다.** 허용된 R3 한정 격리 로컬 PG 1묶음만 실행했다: **4건 중 3건 PASS, 1건(A_V3)은 구동기 기대 오류로 FAIL 기록 보존 → 보존 원문 대조로 정상 확인**(§2).

## 1. 바뀐 계약 (v2 → v3)

| 항목 | v2 | v3 |
|---|---|---|
| 등록 밖(UNREG) 주문 | 진행·미정산·미해결 차이·비CLOSED 포지션 연결 중 하나일 때만 STOP | **종결·정산 확정이어도 STOP.** 위 네 조건은 `ID_O` 8번째 열에 참고로만 남기고 판정에 쓰지 않는다 |
| 등록 밖 포지션 | 비CLOSED만 STOP | **CLOSED여도 STOP** |
| 등록 밖 STOPPED 세션 행 | 금액 없는 목록 | 그대로 (주문·포지션이 없으면 STOP 아님) |
| 소유 이상·R1·R2·2단계 범위 | — | v2 그대로 |

근거: 입력 계약에 "기준 이전부터 있었고 바뀌지 않았다"는 목록/버전 근거가 없다. 그래서 최근에 완료된 미등록 거래와 과거 거래를 구별할 수 없다. **기대 변경:** 과거 종결 행(v2 A의 주문21·포지션20)도 이제 STOP이다. 과거 주문 예외는 별도로 검토된 출처로만 정한다. 자동 면제·삭제·NULL 변환·등록표 임의 추가는 하지 않는다. 운영에 이런 행이 있는지는 읽지 않아 모른다. 있으면 게이트는 계속 STOP이다.

파서([parse.py](parse.py)): META 판 `v3`. `ID_O`/`ID_P`에 나온 행이 STOP 표시가 없으면 30으로 거절한다. 참고 열은 `live_relevant_info`로 보존한다. 종료값은 v2와 같다(0/10/20/30). [read.sql](read.sql)의 v2 대비 변경은 머리말·META 판·ID_O/ID_P 표시·게이트 두 WHERE 줄이다.

## 2. 격리 로컬 PG 1묶음 ([run1](run1/tests_pg.out.txt))

- **환경**([setup.txt](run1/setup.txt), [setup_pg.py](setup_pg.py)): `timescale/timescaledb:latest-pg15`(15.13), `--network none`, 데이터 tmpfs, d81c3f2f 마이그레이션 95개(V1~V96). flyway 이력은 최소 대역 표다. 시험 뒤 컨테이너를 삭제했다.
- **구동기**([tests_pg.py](tests_pg.py)): v2 `tests_pg.py`의 공통 픽스처·도우미를 해시 고정으로 가져온다. v1.205 §3대로 **호출마다 고유 폴더**를 쓰고, 폴더가 있으면 멈춘다. v2의 11건은 반복하지 않았다.

| 사례 | 내용 | 결과 |
|---|---|---|
| R3_V2 | **반례 고정.** v2에 등록 밖 STOPPED LIVE100의 기준 뒤 완료 주문22(FILLED·정산 확정)·CLOSED 포지션21을 넣음 | psql0·파서0·**GO**, 22·21 `stop=false`, 2단계 11행 |
| R3_V3 | 같은 픽스처에 v3 | psql0·파서10·`gate_bad=4`(주문21·22, 포지션20·21), **2단계 0행** |
| PAST_V3 | v2 A와 같은 공통 픽스처(과거 종결 주문21·포지션20만) | psql0·파서10·2단계 0행 (**기대 변경**: v2 A는 GO) |
| A_V3 | 등록 밖 주문·포지션을 지운 정상 원천 | psql0·파서0·GO. 등록 주문 {11,12,13,14,41}, 포지션 {7,8}, PAPER 금액 없음. 원문 판정은 **FAIL**(아래) |

**A_V3 FAIL 원인:** 구동기는 2단계 11행이 v2 run2/A 원문과 바이트 동일하기를 기대했다. 10행은 같았다. `D` 행의 `detected_at` 1칸만 달랐다(04:16:51 vs 04:27:34 UTC). 픽스처가 이 열을 넣지 않아 V82의 `DEFAULT CURRENT_TIMESTAMP`(삽입 시각)가 들어갔다. 게이트·읽기 범위와는 무관한 기대 오류다. PG를 다시 돌리지 않았고 `tests_pg.out.txt`의 FAIL은 고치지 않았다. 대신 보존 원문끼리 대조했다. 이 열을 빼면 11행 모두 같다([a-v3-compare.json](run1/a-v3-compare.json)). 다음 구동기는 시각 기본값 열을 픽스처에서 고정하거나 비교에서 명시적으로 제외한다.
