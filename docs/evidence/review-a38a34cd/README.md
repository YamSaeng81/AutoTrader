## 1. 준비 확인과 보존 정정

- 로컬 `/d/tmp/d81brun-20261127-exp1/blocks-d81/`의 11개 파일을 `blocks.json` 해시와 대조했고 전부 일치한다. source는 `452ac38430dff30300048026e9478e555e015b8c`, run.sh SHA256도 승인값 06b913a8…과 같다. 현재 out 폴더가 없음을 확인했다. 이는 현재 로컬 준비 확인이지 예약 실행이나 운영 접속 확인이 아니다.
- 준비 근거 체크섬은 작업 파일 **4/4**가 맞지만, `a38a34cd` 블롭은 **3/4**다. `blocks.json`만 작업 파일의 CRLF 62개가 커밋에서 LF로 바뀌었다. 줄바꿈을 정규화하면 내용은 같다. 실행 블록이나 승인 핀 문제로 확대 해석하지 않되, 원문 바이트 보존은 보완해야 한다.

## 2. 실주문 초안의 세 문제

1. **KST 검사:** 로컬 launch.sh와 원격 smoke.sh가 `TZ=Asia/Seoul date`에 의존한다. Windows Git Bash에서 오작동한 기록이 있으며, 두 번 검사한다는 이유로 수용할 수 없다. 서버에 tzdata가 있을 것이라고 가정하지 않는다.
2. **종료 판정 전달:** launch.sh의 gate 단계는 Python 판정기를 `tee`에 연결한 뒤 최종적으로 원격 `rc`를 반환한다. 원격 SQL/SSH가 0이어도 로컬 판정기가 FAIL/HOLD이면 최종 0이 나올 수 있다. 게이트 v4 자체를 바꾸는 대신 실행기가 실제 판정 종료값과 기록 실패를 전달해야 한다.
3. **정지 직전 보유 표시:** smoke.sh의 `held-before-stop`은 여전히 `OPEN/CLOSING OR size<>0`이다. 정상 CLOSED 수량을 실보유로 세는 v3의 오류가 남았다. 이미 결정한 상태 기준으로 맞춰 대기 종료/보유 중 강제 정지 표시를 구분한다. 실제 거래소 잔량 증명은 별도다.

## 3. 지금 할 로컬 보완 — 새 사본, 파일 검증만

원본 `live-smoke-draft-20261125`와 이전 체크섬은 보존하고 **`docs/evidence/live-smoke-draft-v2-20261125/`**에 새 사본을 만든다. 제품·배포 출처·게이트 v4 SQL/판정기는 바꾸지 않는다. 착수 확인 없이 다음을 진행한다.

### 3-1. 시각 함수

로컬/서버가 같은 규칙을 사용하도록 작은 시각 함수를 둔다. **Python 표준 라이브러리의 aware UTC 시각을 고정 오프셋 `UTC+09:00`으로 변환**하는 방식으로 날짜와 HHMM을 한 번의 표본에서 함께 얻는다. 시스템 로컬 시간대·`TZ` 환경변수·IANA zoneinfo/tzdata에 의존하지 않는다. 한쪽에만 고치지 않는다. Python 부재·오류·형식 결함이면 거절한다.

승인 날짜는 실제 달력 날짜, HHMM은 0000~2359의 유효 시·분이며 시작≤끝인지 검증한다. 현재 계약은 승인 날짜 안의 창이고 자정 통과 창은 허용하지 않는다. 창 끝 포함 여부는 기존 계약처럼 포함으로 유지한다. p0/create/verify/start의 날짜·창 확인을 유지하고, **create/start POST 바로 앞에도 새 현재 시각으로 재검사**한다. stop/gate는 기존 계약상 창 이후에도 필요하므로 창 만료만으로 차단하지 않는다. 실제 실행에 임의 테스트 시각을 넣는 환경변수/옵션을 추가하지 말고, 고정 시각은 파일 검증 함수에만 제공한다.

### 3-2. gate 종료값과 보유 표시

SSH/원격 SQL 실패, 판정기 PASS/HOLD/FAIL, 파싱·파일 읽기·필수 출력 기록 실패를 구분한다. PASS는 원격 성공·판정기 실제 종료0·결과 기록 성공을 모두 만족할 때만 최종0이다. HOLD/FAIL을 원격0이나 tee0으로 덮지 않는다. 원격이 이미 실패했으면 그 원래 종료값과 로컬 오류를 따로 남기고 성공으로 덮지 않는다. 필수 기록이 실패하면 확정/후속 사용을 차단한다. gate SQL 읽기 성공만으로 종료를 확정하지 않는다.

정지 직전 보유 표시는 `status IN ('OPEN','CLOSING')`으로 맞춘다. CLOSED 양수 size는 이 수에 넣지 않되, 별도 게이트·계좌 확인을 생략하지 않는다.

### 3-3. 직접 영향 확인 1묶음

고유 보존 경로와 기대를 실행 전에 고정한다. 운영/거래소/실제·가짜 SSH·curl·Docker·PG를 실행하지 않는다. **함수/파일 검증만** 하며 launch.sh나 smoke.sh 전체를 실행하지 않는다. 실제 원격 도구로 빠질 PATH 치환을 사용하지 않는다.

- 고정 UTC 표본에서 KST 날짜 넘김, 창 시작 직전/정각, 끝 정각/직후를 확인한다. 로컬/서버 공통 규칙의 결과가 같아야 한다. UTC·다른 로컬 TZ 조건에서도 같은 UTC 표본은 같은 결과여야 한다.
- 잘못된 날짜, 2460 등 잘못된 HHMM, 역전/빈 창, 시각 함수 실패는 거절한다. create/start 직전 창을 벗어나는 모형은 POST 수행 부분에 도달하지 않아야 한다. 원격 도구 대신 부작용 없는 함수 도달 횟수로만 확인한다.
- gate 원격0+PASS→0, 원격0+HOLD→비0, 원격0+FAIL→비0, 원격255→255, 판정/필수 기록 실패→비0을 보존된 입력과 순수 모듈/부작용 없는 대역으로 확인한다. 원래 초안이 gate FAIL을 최종0으로 덮는 반례도 **해당 종료 처리 부분만** 잘라 파일로 고정한다. 전체 실행기를 돌리지 않는다.
- CLOSED 양수 수량의 정상 종료와 OPEN/CLOSING의 보유 표시 구분은 기존 r3 자료의 상태를 파일로 재사용한다. PG를 다시 실행하지 않는다.

사례·기대·실제 결과·실패 원문을 보존한다. 실패가 생기면 원인과 추가 검증 필요를 보고하고, 무제한 재실행하거나 통과를 위해 기대를 약화하지 않는다. 완료 즉시 변경표·새 해시·체크섬·블롭 대조를 제출한다.
