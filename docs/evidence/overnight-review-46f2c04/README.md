## 직접 보완한 실행 절차

### 1. holdobs의 스택 줄 누락

기존 함수는 HEAD와 같은 줄의 `Connection is not available, request timed out`만 셌다. 일반적인 `ERROR ... Unexpected error` 다음 `Caused by: ... SQLTransientConnectionException` 줄에 있는 같은 메시지는 종료0/획득시간초과0으로 통과했다. 머리줄 대조군은 종료1이었다. 운영에서 실제 획득 장애가 발생했다는 뜻은 아니며 가짜 입력 재현이다.

이제 모든 줄에서 해당 문구를 한 번씩 센다. 최근 머리줄의 시각/정규화한 스레드만 문맥으로 출력하고, 머리줄 없이 시작한 스택이면 시각/스레드 미확인으로 출력한다. 원문/연결 이름/오류 본문은 출력하지 않는다. 중복 표현은 **일치 줄 수**이며 독립 장애 횟수로 합산하지 않는다.

원래5개 입력과 스택/중복/머리없음/HTTP시간초과/CRLF/머리줄/빈로그/인자없음의13사례가 기대와 같다. HTTP request timed out만 있는 대조군은 P0로 분류하지 않는다. 가짜 비밀 문자열/정확한 scheduler-7은 출력되지 않는다. 새 앱 시험은 필요하지 않았다.

### 2. 설치 실패 뒤 DRY_RUN 방지

기존 설치 블록은 서브셸이 실패해도 바로 다음 DRY_RUN을 실행했다. 이제 단순 명령인 설치 서브셸이 끝난 직후 INSTALL_RC를 저장하고, 성공일 때만 DRY_RUN을 실행한다. `(...) && DRY_RUN`으로 감싸지 않는다(그 형태는 내부 errexit를 무력화할 수 있다).

성공/명시중단/내부 미검사 명령실패의3사례로 DRY_RUN여부·종료값·set-e보존을 확인했다. 후보 셸/SQL/설치백업 경로는 바꾸지 않았다. 실제 서버 설치를 실행한 것은 아니다.
