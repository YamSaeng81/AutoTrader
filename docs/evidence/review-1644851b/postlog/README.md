# V172D4 진행 중 추가 확인

2026-11-16. R1~R3 보완 블록과 실행 틀을 읽었다. 보존 태그의 명시적 부재 판정, 두 서비스의 복구 전 이름 판정, 첫 로그의 P0 검사 순서가 반영돼 있다. 영향 범위 대역은 개발 세션에서 진행 중이다.

## 뒤 관측의 두 번째 로그 검사

`v172d4-20261116/d4/blocks-d4/U뒤관측.sh`는 첫 로그에서 P0를 검사한 뒤 이미지·뉴스 설정을 조회하고 로그를 다시 읽는다. 두 번째 로그의 `holdobs`가 종료1을 반환하면 P0를 출력하고 N15~N20 검사로 계속 진행한다. 이 검사들이 성공하면 블록은 종료0이다.

확인한 블록의 SHA256은 `36987edc24ec0274fe1827502afeb8036f359b70e43ef56dac7e84449ca80f5a`다. 원문에서 두 번째 HOLD 검사부터 블록 끝까지를 추출해 외부 명령을 셸 함수로 대체했다. `holdobs=1`, 이후 검사 모두0을 넣었을 때 P0 출력과 **블록 종료0**을 확인했다. 첫 로그를 읽은 뒤 새로 발생한 연결 획득 실패가 이 경로에 해당한다. 실행용 블록·백그라운드 대역·서버에 변경을 가하지 않았다.

**현재 대역 결과를 먼저 보존한 뒤 이 분기를 보완한다.** 두 번째 검사에서도 연결 획득 실패가 있으면 즉시 비정상 종료하고, 판정 실패도 검사 미완료로 종료한다. ‘첫 로그 정상 → 두 번째 로그 P0’와 ‘첫 로그 정상 → 두 번째 holdobs 판정 실패’를 관련 사례에 추가한다. 수정된 블록 해시·실행 틀·차분을 새 고정 출처에 연결한다. 이 추가 지시 때문에 완료한 제품 회귀나 전체 대역을 반복하지 않는다.

격리 분기를 다시 확인하는 도구는 [probe.ps1](probe.ps1)에 있다. 초기 진단은 PowerShell 표준 입력의 문자 인코딩과 출력 대역 설정을 보완한 뒤 다시 확인했다. 저장한 도구도 첫 실행의 PowerShell 한글 경로 해석 문제를 UTF-8 BOM으로 보완했고, 재실행에서 위 종료0을 확인했다. 도구의 출력은 해당 분기 종료값이며 전체 대역의 결과로 합산하지 않는다. 상위 검토의 SHA256SUMS는 보존하며 이 폴더의 파일은 별도 목록으로 확인한다.
