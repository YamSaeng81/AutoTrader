# v1.261 즉시 거래소 왕복 시험 — 키 로딩 정정 사본

사용자의 “진행 가능하면 바로바로 진행” 지시로 수행하는 누적 매수대금+매수수수료1만원 이내 외부 거래소 실체결 시험이다. [첫 고정 원문과 범위](../broker-smoke-now-20261128/README.md)를 그대로 따르며 앱 장부/자연 전략 검증으로 쓰지 않는다.

첫 실행은18:38 KST BROKER_AUTH_NOT_CONFIGURED로 POST 의도 생성 전 중단됐다. 매수/매도 호출0, 기존 원문/실패 기록은 보존한다. 내일 예약은 CANCELLED·trial_started=false로 이미 취소됐다. 새 실행기는 이 두 사실을 서버 파일로 확인해야만 시작한다.

실제 compose는 UPBIT_ACCESS_KEY_ENCRYPTED/UPBIT_SECRET_KEY_ENCRYPTED를 컨테이너의 UPBIT_ACCESS_KEY/UPBIT_SECRET_KEY로 주입한다. **이름만으로 값이 암호문이라고 단정할 수 없다.** 고정 EngineConfig는 그 컨테이너 실효값을 UpbitOrderClient에 바로 전달한다. 새 사본도 정확히 두 컨테이너 키만 서버 메모리에서 골라 사용하며 자체 복호화·설정 변경·키 반출을 하지 않는다. 첫 설명의 “암호화된 키여서 복호화 필요”는 이 코드 확인으로 정정한다.

응답 원문 파일명에도 클라이언트 인스턴스별 고유 접두어를 붙여 예외 정리에서 새 Broker가 만들어져도 기존 원문을 덮지 않게 했다. 주문 식별자·1회 POST/조회 재확인·같은 체결량만 매도·1만원 상한·종료 잔량/현금 대조는 그대로다.

키 선택/누락/중복3경계를 추가한 순수17/17 통과. SSH·API·DB·주문 호출0인 파일 시험이며 실제 인증 성공을 뜻하지 않는다. 외부 원문은 새 서버0700 폴더에만 보존한다. 원래 앱 제품·DB·SID203·APENFT는 바꾸지 않는다.
