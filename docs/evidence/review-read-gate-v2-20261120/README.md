[독립 파일 대조](checks.json) **26성공·실패0**: 제출 목록106/106과 별도 `.gitattributes`, 앞 총괄7/7 일치. 앞 판 SQL·파서는43d729db 블롭과 같다. 새 원문 해시는 SQL **f5ffdb063c88d9de99a48cbd3499f36ab325241d03f2a9dd2150d7cb6de47bf4**, 파서 **2a114fa92c5706e863ee396029d6176e6df22c3d5c44c4222a25a9a90956b81f**다. 이 해시를 검토 기준으로 쓰되 운영 실행 고정 커밋으로 간주하지 않는다.

## 1. 판정

**R1·R2와 등록 세션 원천 전체 조회, 보존된 PG11개 판정은 로컬 범위 수용한다. R3의 등록 밖 종결 주문 예외는 아직 닫지 않는다.** 소유자 CASE·등록 존재/REAL 모드 확인이 SQL에서 선행하는 점, 등록 세션의 과거 매수·CLOSED 포지션·뒤늦은 매도 반영을 시간 필터 없이 읽는 점은 확인했다. 파서의 등록표 해시·게이트 건수·행 수 대조는 추가 방어로 수용한다. 파서 성공은 계좌 일치·월말 값 확정이나 운영 읽기 승인이라는 뜻이 아니다.

[사례별 원문 대조](case-audit.json)에서 A는 psql0·파서0·GO이고 매수12·매도13·CLOSED 포지션8이 있다. B~J의9개는 모두 SQL STOP·파서10·금액 단계0행이다. K는 psql3·파서20·금액 단계0행이다. 각 파서 결과의 원문 해시와 실제 보존 TSV가 같으며, 앞 판 V1B/V1F의GO와 PAPER 금액 노출도 원문으로 확인했다. 총괄은 SQL·파서 시험·PG·Docker·운영 접속을 다시 실행하지 않았다.

## 2. R3에 남은 것 — 등록 밖 종결 행을 자동으로 과거로 보지 않는다

현재 A는 등록 밖 STOPPED LIVE100의 주문21(FILLED·정산 확정·차이 없음·CLOSED 포지션)을 `stop=false`로 허용한다. [정적 조건 모형](range-probe.json)처럼 이 거래가 **기준 관측 뒤 새로 완료된 경우**에도 active/unsettled/open_disc/open_pos는 모두false다. SQL은 그 체결·정산 시각이나 기준 목록의 존재를 대조하지 않으므로 게이트 결과가 같다. 이 모형은 실제 PG 재현이 아니며, A의 과거 입력11/11 성공을 부정하는 근거도 아니다. 다만 과거 입력 하나의 성공으로 최근 미등록 종결 거래까지 확인됐다고 판정할 수 없다.

총괄 결정은 **과거임을 확인할 원천이 없는 등록 밖 주문을 종결 상태만으로 면제하지 않는 것**이다. 지금 입력 계약에는 기준 이전부터 존재했고 변경되지 않았다는 목록/버전 근거가 없다. 따라서 현재 사본의 기본값은 이런 행도 금액 조회 전 STOP으로 한다. 과거 주문의 예외는 금액 없는 목록과 별도로 검토된 출처로만 정하며, 자동 면제·기록 삭제·NULL 변환·등록표 임의 추가는 하지 않는다. 운영에 해당 행이 있는지는 아직 읽지 않았으므로 모른다.

## 3. 보존과 검증 범위 정정

- `tests_pg.py`의 K는 `run_case(...,'K',...)`에서 정상 SQL을 먼저 실행한 뒤, 잘못된 배열로 다시 실행해 같은 stdout/stderr/종료값/변수 파일을 덮어쓴다. **새 SQL 실행은12번, 앞 판 대조2번**이며11/11은 보존된 판정 사례 수다. K의 첫 정상 출력은 미보존으로 남기고 성공 근거에 추가하지 않는다. 이 기록 공백 때문에 PG를 다시 돌리거나 원문을 재구성하지 않는다. 다음 구동기는 준비와 SQL 실행을 나누거나 호출별 고유 폴더를 쓴다.
- run1은 템플릿 생성 오류로 실제 읽기 전 중단된 기록을 수용한다. PG15.13·이행95개/최대96은 보존된 출력으로 확인했다. 네트워크 없음·tmpfs·컨테이너 삭제는 개발 보고에 연결하며 해당 설정을 총괄이 Docker에서 별도 검증한 것은 아니다. Flyway 이력은 최소 대역 표이므로 제품 Flyway validate 결과로 쓰지 않는다.
- 파일 대조1회차는 목록 밖 `.gitattributes`1개를 총괄이 일반 원문 누락으로 센 기대 오류였다([기록](checks-attempt1.json)). 파일 내용이 `* -text`임을 별도 확인한 최종26/26을 사용한다. 개발 제출의 원문 누락으로 판단하지 않는다.
