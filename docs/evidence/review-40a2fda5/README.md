## 2. 실제 읽기를 보류하는 이유

**G1 — 실자금 종류를 현재 모드로 숨긴다.** state-2.sql은 `session_kind IN ('DYNAMIC','DYN_PAPER')`와 현재 PAPER 모드를 함께 모의 제외 조건으로 쓴다. 저장된 B3도 DYNAMIC 주문/포지션이 목록에서 사라진다. 등록 세션이면 W1이 모드 변경을 잡지만 미등록 세션에서는 그 보호를 전제할 수 없다. **저장된 DYNAMIC은 실자금 종류라는 증거를 유지해야 한다.** 현재 세션 모드와 충돌하면 행을 남기고 KIND_MODE_MISMATCH 수집 불통과로 처리한다. 모의 제외는 DYN_PAPER 종류와 실제 PAPER 소유가 일치하는 경우로 한정한다. U·CNT에도 같은 조건을 쓴다. 과거 종결 행의 시간 일괄 면제 불허는 그대로다.

**G2 — 문서의 실행 관문과 코드가 다르다.** pm-read.sh에는 문서가 약속한 HEAD0e1d2a02·backend2c5d8427·Flyway96 비교가 없다. read/post가 각각 마지막에 exit0을 써서 앞의 SQL/로그/변환 실패나 기록 실패가 최종 성공으로 보일 수도 있다. 현재 post 임시 점검은 원문이 없어 성공 근거로 연결하지 않는다.

**G3 — 로그 끝 시각의 축이 다르다.** UNTIL은 개발 PC의 date로 만들면서 post는 server_utc 구간으로 적는다. PC와 서버 시계 관계를 확인하지 않았으므로 같은 축으로 선언하면 안 된다. SINCE/UNTIL은 검토된 서버 UTC 근거로 만들고 실제 요청 인자와 수집 결과를 보존해야 한다.
