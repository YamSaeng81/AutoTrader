## 3. 지금부터 계속할 순서 — 로컬 보완 승인

### 3-1. 청산 대기 가격·소유 상태 연결

1. **W1부터 실패 시험으로 고정**하고 주기·실시간·정지·재기동 복원에서 같은 기존 가격/유효기간 계약을 사용한다. 대기 청산에 판단 이전 완성 봉 종가를 현재 시장가처럼 쓰지 않는다. 신선한 시세가 없으면 계속 CLOSING이며 매도·정산은0이어야 한다. 신선한 시세가 오면 보존한 사유로 한 번 정산한다. 봉 최신성 검사를 느슨하게 하거나 새 허용 시간을 임의로 만들지 않는다.
2. **단건·일괄 이력 삭제**는 선택 모드에 미정산 포지션이 있으면 거절하거나 해당 세션을 건너뛴다. 단순 STOPPED만으로 삭제 가능하다고 판단하지 않는다. 전부 정산된 이력의 종전 삭제는 유지한다. DB 상태를 같은 트랜잭션에서 확인하고 삭제와 정산 경합도 확인한다.
3. 포지션·잔액·성과/API/최종 A/B 집계에서 CLOSING은 **아직 소유한 미정산 자산**으로 표현한다. CLOSED 손익이나 완료 거래에 미리 넣지 않는다. 기존 `OPEN` 상태의 의미를 몰래 바꾸는 대신 대기를 명시적으로 노출해도 된다. 가격이 없을 때 미실현손익을 0으로 메워 정상/완료로 보이지 않게 한다. 마지막 평가값을 쓴다면 시각·유효 여부를 함께 표시하고 평가 불가를 구분한다. 마지막 T1 평가 가격이 없으면 A/B 판정은 불가로 남긴다.
4. 정지 응답뿐 아니라 알림·일괄 정지·최종 자산 표시도 대기 상태를 반영한다. 청산 대기인 STOPPED에 “정산 완료/최종 확정 자산”이라는 표현을 쓰지 않는다. 운영자에게 반복 정지나 이력 삭제로 대기를 없애도록 안내하지 않는다.
5. 한 포지션의 정산 실패가 다른 세션의 청산 대기를 계속 막지 않는지도 실패 주입으로 확인한다. 새 REAL 조회/주문 경로나 66 처리 정책을 섞지 않는다.
