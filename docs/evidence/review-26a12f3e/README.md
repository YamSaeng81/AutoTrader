## 3. 추가 착수 확인 없이 진행할 순서

1. **v4.1 조회 경계와 단건 도구를 보완한다.** DB 읽기 열은 식별자·상태·전략·코인·주기·초기자본·실행 설정·시작 시각 등 생성 대조에 필요한 메타데이터로 제한한다. 성과·잔고·포지션·신호를 담는 전체 목록 API는 정상·실패·응답 불명 경로 모두 호출하지 않는다. 중복·잠정 후보·새 ID·동시 다른 생성·저장 시각 정밀도·다른 DB 거절 기능을 보존한다. 조회 출처와 도구 판을 완성기·기록부에 명시하고 기존 API 출처 값을 DB 확인값인 것처럼 재표기하지 않는다.
2. **변경 영향 검증을 한다.** 기존 도구 계약 시험을 연결하고, 전체 목록 GET이 한 번이라도 오면 실패하는 대역, DB 조회 실패·빈 결과·중복·일부 생성 뒤 실패·기록 실패·불명 응답·창 만료를 확인한다. 단건은 정상 1회와 거절/불명 뒤 추가 POST 0을 확인한다. 실제 격리 PG와 HTTP 대역에서 8팔·단건을 각각 연결하고 다른 DB 동일 ID·1µs 차이 거절을 유지한다. 외부 통신은 대역으로 제한한다. backend 전체 회귀·jar·운영 배포는 이 도구 변경 때문에 반복할 필요가 없다.
3. **사전 조회와 T0 확인을 보완한다.** 현재 preflight.sql의 BTC 질의는 개수·최소·최대뿐이다. 봉 공백·최신 완료 봉·SMA20 필요 이력을 확인했다는 판정에는 부족하다. 운영의 기존 완료 봉·신선도·B1/B3·필요 이력 규칙을 재사용하는 열 제한 질의를 묶고, 로컬 PG에서 누락 봉·낡은 끝 봉·정상 입력을 구별한다. 전략 활성은 실제 생성 관문과 같은 기본값/주기 의미로 판단한다. 생성 직전 RUNNING+9 상한과 중복을 다시 확인한다.
4. **고정 실행 묶음을 제출한다.** v4.1·완성기·단건·SQL·실행 틀의 출처/해시, 9본문, 구체 생성 창과 T0 계산, 인증 파일 경로 인자, 직전 상태·생성 후 DB 확인·기록부·실패 시 중단을 한 곳에 모은다. 비밀값은 명령 인자·문서·출력·증빙에 넣지 않는다. 토큰 준비가 필요한 시점은 이 묶음 검토 후 실제 호출 직전이며 로컬 작업을 기다리게 하지 않는다. 현재 운영 핀·V96·66 비열람 계약을 기준으로 한다.
5. **차트 제목 대비 결함은 독립 frontend 후보로 고친다.** 흰 카드와 제목의 색 조합만 최소 변경하고 로컬 밝은/어두운 테마에서 제목을 확인한다. 본문·거래 규칙·공유 스타일 변경을 넓히지 않는다. 후보·사진·차분을 제출하고 생성 도구 작업과 독립적으로 진행한다. 현재 모의 준비의 선행 조건으로 추가하지 않는다.
6. **22:00 N03과 아침 인계를 이어 간다.** 세부 시각과 추가 확인을 기다리지 않고 진행할 범위는 아래 §4를 따른다.
