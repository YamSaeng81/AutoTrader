## 2. 실행 틀의 기록 실패 — 먼저 보완

[원문 run.sh](../d81d4-20261120/runner/run.sh)는 `tee`와 마지막 종료값 기록의 실패를 확인하지 않는다. [가짜 SSH 재현](runner-record-probe-round2.json)에서 다음을 확인했다. 원격 명령 문자열은 실행하지 않았다.

| 주입 | 관측 |
|---|---|
| 첫 시작 로그 쓰기 실패 | 가짜 SSH1회 호출, 종료0 |
| 원격 출력 로그 또는 마지막 로그 쓰기 실패 | 각각 가짜 SSH1회, 종료0 |
| 종료값 기록 파일 대신 같은 이름의 디렉터리 | 기록 파일 없음, 가짜 SSH1회, 종료0 |
| 원격 종료7 + 마지막 로그 실패 | 종료7 유지 |

**별도 로컬 보완으로 처리한다.** 첫 필수 기록 실패는 SSH0회로 멈추고, 접속 후 필수 기록이 실패하면 원격0이어도 로컬 성공으로 끝내지 않는다. 원격 비영 종료값은 기록 실패가 덮지 않게 유지하며 두 값을 따로 보존한다. 성공 종료값/완료 표지를 확정한 뒤 필수 기록이 남지 않게 하고, 기록 실패·미완료 흔적이 있으면 뒤 단계도 호출하지 않는다. 원격 접속 뒤 기록 실패는 “원격 상태 미확인/부분, 확인 전 재실행 금지”로 보고하며 자동 재시도하지 않는다. [앞 배치 기록 보완](../review-e0119f0a/README.md)의 계약을 참고하되 현재 run.sh에 실제로 적용한다.

정상·위4주입·원격7과255가 기록 실패와 겹치는 경우·같은 출력 거절·뒤 단계 직접 호출 거절만 새 가짜 SSH 사례로 확인한다. 새 틀 자체가 실수로 실제 ssh를 고르지 않도록 실행 전 대역 경로를 단언한다. 기존30건과 블록201건을 전부 반복하지 않고 변경 영향만 확인한다.

## 3. pf3ok 형식 거절 — 같은 좁은 보완에 포함

[합성 입력 재현](pf3-probe.json)에서 정상2개 외에 **원가 `not-a-number`, 매도 수량 `Infinity`, 무거래 플래그2, 매도 순대금 누락**도 모두 종료0이었다. R3의 원가를 “빈 값 아님”만으로 보고, 일부 수치와 플래그의 유효성을 확인하지 않는 공백이다. 운영에 이런 값이 있다는 근거나 제품 결함 판정은 아니다.

판정에 사용하는 수량·원가·순대금은 **유효한 유한 십진수 또는 계약상 허용한 NULL**인지 구분하고, 무거래 플래그는0/1만 받는다. 빈 값·비정상 값·UTF-8 읽기 실패를 정상0이나 무거래로 바꾸지 않는다. 정상 형식의 원천 미상은 종료1, 형식/읽기 실패는 종료3 등 명시한 비영 값으로 멈춘다. 무거래 확정 행의 NULL 합계는 기존 계약대로 허용하되, 잘못된 형식이 플래그1이라는 이유로 검증을 건너뛰지 않게 한다. 원문 값은 오류 출력에 복사하지 않는다.

정상 R3없음/확정/무거래, 정상 형식의 판정 불가, 위4반례·NaN/음의 수량·플래그 경계·읽기 실패만 파일 입력으로 확인한다. 제품 조회문·SQL v3·위험 정책은 바꾸지 않는다. U0에서 판정 실패가 ok-U0 이전에 멈추며 checkout/build/restart0인 연결만 대역으로 보충한다.
