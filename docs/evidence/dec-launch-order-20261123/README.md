## 6. 작업 지속·토큰·보고

한 항목 완료/중간 제출만으로 전체 작업을 멈추지 않는다. 오늘 읽기 결과를 기다리는 동안 §3-2를 진행하고, 읽기가 막히면 금액 없는 원인 목록·배포/복구 제출안·실제 원천/운영자 인수 준비를 계속한다. 의미 있는 허용 작업이 모두 끝나거나 모두 외부 결정에 의존할 때만 완료/차단 사유/다음 시각을 남겨 대기한다. 시간 채우기 재시험은 하지 않는다.

18:00 이후에는 현재 계획의 다음날08:00 원칙을 적용한다. 실제 사용률80% 확인 시 체크포인트를 보존하고 초기화/현재값 확인 뒤 재개한다. 사용률 파일 부재는 미확인이며0/엄격한80% 제어 완료로 쓰지 않는다. 세션/PC 종료·절전·한도 중단을 감시 시간으로 쓰지 않고 실제 재개 여부를 기록한다.

현재 지시·인계·필요한 원천 절만 읽고 긴 문서/로그를 일괄 재독하지 않는다. 원문은 파일에 보존하고 콘솔/보고에는 rc·실패명·핵심 차이만 요약한다. 같은 입력 회귀/PG/jar는 연결 근거를 재사용하고 새 코드/새 경계만 검증한다. 새 산출 경로의 Windows 예약 이름과 git 무시 여부를 실행 전에 확인한다. 제품/빌드/보호 계약이 바뀌면 영향 검증과 최종 검증 범위를 총괄이 정한다.

각 제출은 **완료/미완료·다섯 시작조건 변화·실제 읽기 시각·후보/운영 SHA·다음 독립 작업·승인 요청**만 짧게 쓴다. 상세 근거는한 곳, 관리 문서는링크/현재 상태만 갱신한다. 이번 지시와 예산 결정·체크섬을 정확한 파일 범위로 커밋/일반 푸시한다. 원문 로그 local-only·권한 설정·인증·캐시는 제출에서 제외한다. 12월의 신규 다전략 선택 엔진·성과 튜닝·차트 개선·불필요한 도구 증설은 이번 시작 경로에 넣지 않는다.
