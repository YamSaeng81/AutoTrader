`nosecret`(STEP 2·4 의 도구 뒤):
- 토큰 파일이 없거나, 읽을 수 없거나, 비어 있으면 **검사 미완료**로 처리한다.
- `grep -rlF` 종료값을 나눠 처리한다.

  | grep 결과 | 처리 |
  |---|---|
  | 0 = 일치 | 노출, **종료 9** |
  | 1 = 정상 불일치(출력도 비어야 함) | 통과 |
  | 2 이상, 또는 1인데 출력 있음 | **검사 미완료** |
- 검사 미완료일 때 종료값:
  - 도구가 이미 0이 아닌 값이면 그 값을 보존한다(예: 3).
  - 도구가 0이면 **새 종료 10**이다.
- 어느 쪽이든 `STEP.rc`는 0이 아니다. 그래서 다음 단계는 앞 단계 확인에서 6으로 거절된다.
- 토큰 값은 출력하지 않는다. grep 오류 문구에는 경로만 나온다.
- 일치는 도구 rc 와 상관없이 9다. 도구 rc 는 같은 줄에 적는다.
- 실제로 생성된 뒤 실패한 경우, 도구 기록(`ab-create/`, `sma20-create/`)은 그대로 둔다. 재전송 경로는 없다(v4.2 와 같음).

## 실행 경위(그대로 남김)

1. **시험 패치 1차 실패**
   - Python 패치를 셸 here-doc 안에 넣었는데, 안쪽 `EOF` 줄이 바깥 here-doc 을 끝냈다.
   - 그 뒤 몇 줄이 Git Bash 에서 그대로 실행됐다. `STUB` 가 빈 값이라 `chmod +x /*` 가 Git 설치 폴더 항목마다 권한 거부로 끝났다.
   - `/grep` 은 생기지 않았고 시험 파일도 바뀌지 않았다(해시 확인).
   - 패치는 스크래치 파일로 다시 적용했다.
2. **WSL 1차 실행 무효**
   - `wsl -- bash -c '…'` 에서 `$D` 가 바깥에서 빈 값으로 풀렸다. 그래서 `/tmp` 복사본이 아니라 마운트된 이 폴더에서 돌았다.
   - 새 폴더에 `SHA256SUMS.bundle` 이 아직 없어서 STEP0 3건이 해시 rc 1로 실패했다(46/49).
   - 확인 결과:
     - WSL `/`·`/runs`·`/keep` 에 새 항목이 없었다.
     - 빈 임시 폴더 `/tmp/v423.WTAp` 와 이 폴더의 빈 `keep/` 은 지웠다.
   - 결과 파일은 무효라 지웠다. 이후 실행기를 스크립트 파일([runs/wsl_run.sh](runs/wsl_run.sh))로 바꿨다.
3. **WSL 2차 실행(49/49) 기록 덮임**
   - Windows 쪽에서 stdout·stderr 를 한 파일로 받는 과정에서 결과 파일 첫 줄들이 덮였다.
   - 실행기가 WSL 안에서 한 fd 로 쓰도록 바꿨다(`exec >`).
   - 3차 실행(01:48:33)을 보존본으로 삼았다. 2차 파일은 남기지 않았다.
