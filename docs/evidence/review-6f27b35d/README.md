## 1. 판정

**G1은 이번에 재현한 정지 중 두 번째 보호 매도에 한해 시험의 낡은 읽기 문제로 종결한다. 제품 변경은 필요 없다.** 정지 트랜잭션 안 저장소 읽기는 claim 전에 읽은 엔티티를 계속 반환했지만, 같은 주문의 독립 JDBC 읽기·거래소 대역 호출·결과 커밋은 제출 완료를 보였다. `em.refresh` 뒤 값도 바뀐다. 조기 읽기 없는 대조, 단언 실패에 따른 정지 롤백, 별도 스레드에서 정지를 정상 커밋한 대조가 이 설명과 맞는다.

- `dispatching=false`는 이 사례에서 claim 종료의 정상 해제다. 캐시된 `INTENT_READY`와 합쳐 제출 유실로 해석한 종전 추정은 철회한다. 제품 `claimOwned`의 `finally` 해제와도 맞는다.
- 정정 메모에서도 두 값을 구분한다. 낡게 읽힌 것은 저장소 엔티티의 상태이고, 등록부의 `dispatching=false` 자체가 캐시된 값이라는 뜻은 아니다. 기존 메모는 보존하고 추가 메모로 명확히 한다.
- 폴러 회복은 **인위적으로 만든 미제출 의도**에 대한 직접 호출 근거다. 실제 G1 주문이 폴러로 회복된 것은 아니다. LIVE·DYNAMIC 모두 철회 → OPEN → 정리 재매도 접수, 반복 호출 중복 없음으로 수용한다. 체결 완료나 실제 주기별 회복 시간의 증거로 넓히지 않는다.
- 과거 60초 제출 지연 **G2는 미확정**, 실제 5초·10초 회복 시간 **G3**, 배포 뒤 최종판 연결 **G4**는 남는다. G1의 원인으로 함께 닫지 않는다.
- 음성 단언 3곳의 보완과 N05 **K20~K23 후보판**을 수용한다. 409차의 “N16 이미 보완”은 ③에 해당하지 않았다는 정정도 수용한다.

## 3. 추가 확인 없이 이어 갈 작업

1. **원문 보존부터 보완한다.** 기존 SHA256SUMS·6f27b35d·과거 근거는 고치지 않는다. G1 근거 폴더에 국한한 `* -text` 속성을 둔 뒤 원래 경로의 누락 로그23개를 강제 추가하고, 줄바꿈이 바뀐106개를 보존 중인 원본 바이트로 다시 추가한다. 다른 폴더나 제품 파일을 일괄 정규화하지 않는다. 새 커밋의 블롭236개를 **기존 SHA256SUMS**와 바이트 단위로 대조한다. 속성 파일·정정 메모는 별도 보완 목록으로 기록한다. 원본이 없으면 다시 생성해 대체하지 말고 그 파일만 미확보로 보고한다.
2. **6클래스의 실제 외부 연결을 시험에서 격리한다.** ExchangeRecoveryRestart·LimitedTestExchangeRecovery·LiveEmergencyStop·N17·SlWatchdog·StaleRealtimeExit를 대상으로 한다. 복구 이벤트 뒤 세션 상태를 보는 시험은 WS 클라이언트를 대역으로 둬도 기존 복구 단언을 유지할 수 있다. 실제 재연결/구독 자체가 시험 대상이면 더 아래 전송 계층이나 루프백 서버를 대역으로 쓰고, 해당 로직과 기존 단언을 그대로 실행한다. 검사를 끄거나 모두 성공으로 처리하는 대역으로 바꾸지 않는다. 주문·시세 HTTP·Telegram도 같은 원칙이다. 제품 연결 로직·운영 설정은 바꾸지 않는다. 전체 회귀 준비 중 다른 클래스에서도 같은 실제 외부 연결이 확인되면, 입증한 항목만 이 원칙으로 시험 격리하고 추가 경로·이유를 보고한다.
3. **외부 연결 격리의 증거를 남긴다.** 수정 대상별 기존 의미와 대역 경계, 묶음 실행의 외부 연결 시도 수를 보고한다. 현재 OutboundNetworkGuard는 기본 꺼짐·ProxySelector를 거치지 않는 소켓 미포착·설치 전 클라이언트 미포착이며 차단 건수 자체를 단언하지 않는다. 이것만으로 네트워크 전체0을 주장하지 않는다. 시험 전용 감시를 관련 클라이언트 생성 전에 설치하고, 예상하지 않은 외부 연결은 실패로 드러내되 로컬 PG·루프백 대역은 허용한다. JVM 전역 상태·관측 시작 문·추가 스레드 설정은 시험 종료/예외 때 복원한다. 진단 도구가 뒤 시험의 동작을 바꾸지 않는지도 확인한다.
4. **N15 PG 시각 의존을 시험만 고친다.** DYNAMIC의 봉·BTC 입력·접수·승인·E를 같은 기준에서 구성한다. 기존 EntryClock과 자료/판정 대역을 사용하고 제품 시계 접점은 추가하지 않는다. 정시 직전53·55·59분과 정각의 입력을 결정적으로 재현한 뒤 보완하고, 만료 경계·실제 잠금 대기·정상 대조군의 기존 단언은 유지한다. 실행 시각을 골라 피하거나 sleep·건너뜀으로 통과시키지 않는다. 정상 주문 대조군의 `createOrder`에는 유효한 고유 주문번호의 응답 대역을 넣어 비동기 결과 저장 NPE3건도 없앤다. 체결을 가정할 필요는 없으며 접수 결과 커밋 뒤 정리되도록 한다. 제품의 실제 null 반환 방어 변경은 이번 범위가 아니다.
5. **시험 전용 최종 SHA에서 검증한다.** 위 보완을 각각 시험 커밋으로 분리하고 3f9cc926 후속의 독립 시험 통합 가지에 고정한다. 관련19클래스, 게이트 없음/필요한 지연 진단, 시각 경계와 실제 N15 PG를 먼저 확인한다. 그 뒤 변경을 멈춘 SHA에서 **전체 회귀1회**를 실행한다. 실행 직후 종료값·시각·XML·로그·건너뜀 사유를 새 폴더에 보존하고 해시를 고정한다. 실패가 나면 원인을 조사하고 필요한 범위만 재검증한다. 전체 실행을 시간 채우기나 통과 횟수 늘리기로 반복하지 않는다. 기본 게이트는 끄고, opt-in 도구의 비활성 기본값과 전역 상태 복원을 확인한다.
6. **제품 입력이 같으면 빌드를 반복하지 않는다.** 최종 시험 SHA와88f06345의 제품·빌드·프런트 입력 블롭이 같음을 연결하면 기존 jar·PG·프런트 결과를 그 범위에서 재사용한다. 새 시험 결과와 기존 제품 검증을 구분한다. 운영 후보와 실행 출처를 새 시험 SHA로 자동 변경하지 않는다.
