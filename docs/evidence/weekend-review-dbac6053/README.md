## 2. O1·O2·O3 판정 — 사용자 응답을 기다리지 않고 계속한다

### O1: 강제 갱신 로그 고정 문구화 — 로컬 최소 후보 승인

LIVE·DYNAMIC `forceRefreshPrice`의 INVALID_PRICE WARN이 REST market 문자열과 숫자 원문을 기록한다. catch ERROR도 `e.getMessage()`를 기록한다. W3 `trade_price=-5.0`과 두 서비스의 고정 SHA 코드를 대조했다. 보호 매도 결함이 아닌 **로그 출력 계약 보완**이다.

1. 운영 1899b49에서 별도 후보를 만든다. 두 엔진의 **이 메서드 안** WARN·catch ERROR만 고정 사유로 바꾼다. 값은 엔진 구분·0/음수 같은 유한한 분류만 쓴다. REST market/숫자 원문·응답·URL·예외 메시지·스택/Throwable을 출력 인자로 넘기지 않는다. 새 알림은 추가하지 않는다.
2. `INVALID_PRICE`/`FAILED`/`STALE`/`PUBLISHED`, 이벤트 발행 여부, 관측 시각, 재경보·연속 횟수·주기·120초·주문 경로는 유지한다. 로그 수준과 발생 건수도 유지한다. catch ERROR를 WARN으로 낮추지 않는다. 메서드 밖 다른 배치 ERROR 원문은 이번 후보로 일괄 정리하지 않는다.
3. **같은 입력 실패 먼저**: 두 엔진에 0·음수 + 줄바꿈/가짜 표지가 든 market, 형식 이상 가격, 예외 메시지의 가짜 표지·줄바꿈을 준다. 어느 로그에도 원문이 없고 WARN/ERROR 수준·건수·결과·이벤트 수가 그대로인지 본다. 정상 가격·낡은 가격 대조군과 정상 가격 뒤 보호 매도는 기존 시험을 재사용한다.
4. 승인된 관측 정규식의 앞부분과 `발행하지 않음 (` 경계를 유지하거나, 불가하면 **관측 초안의 차분**을 함께 낸다. 승인된 F/배포 블록을 조용히 바꾸지 않는다. N03 뉴스 분류는 변경하지 않는다.

### O2: 반영 전 순자산 계산 거절 — 동작·ERROR 분류 유지

고정 코드 `PoolLossGuard.valuate`는 `filled_quantity > 0 AND applied_executed_funds IS NULL`인 실자금 주문이 있으면 null을 반환해 신규 진입 승인을 거절한다. run2 경고 18:07:46.840과 매도 체결 확정 로그 18:07:47.269의 간격은 **429ms**다. 이는 두 로그의 간격이며, 실제 DB 미반영 전체 지속 시간이나 운영 발생 빈도를 측정한 값이 아니다.

- 보호 동작·ERROR·정기 점검 분류를 그대로 둔다. 유예 시간·자동 재시도·건너뛰기·화이트리스트를 만들지 않는다. 통과시키려고 금액을 0으로 메우지 않는다.
- 운영에서 나오면 해당 주문의 반영 여부·활성 주문·정리 대기·불일치·후속 장부를 기존 읽기 범위에서 대조한다. 정지 직후라는 이유만으로 정상으로 지우지 않는다. 반영 완료가 확인되면 그 사실을 기록하고, 미해결이면 새 미해명 이상으로 남긴다.
- 기존 PoolLossLimit 관련 시험 중 미반영 거절→정산 뒤 정상 계산을 단언한 시험을 먼저 연결한다. 없으면 **그 연결만** 국소 시험으로 보완한다. 제품 변경 후보를 O2만으로 만들 필요는 없다.

### O3: REST 손절의 WS 표기 — 로컬 최소 문구 보완 승인

LIVE뿐 아니라 DYNAMIC 공통 이벤트 처리기의 로그·새 매도 사유에도 `실시간 손절(WS)`가 있다. 새 로그와 새 사유는 **`실시간 손절`**로 중립화한다. 이벤트 출처를 새로 추론하거나 데이터 필드를 추가할 필요는 없다. 과거 DB/문서 이력의 WS 표기는 고치지 않는다. 출처가 필요한 조사는 이벤트·호출 경로의 별도 근거로 한다.

- 조건·가격·손익·ExitReason.STOP_LOSS·매도 수·텔레그램 성공 후 전송 조건은 그대로다.
- 실제 이벤트 처리기의 REST/WS 정상 손절 대조를 LIVE·DYNAMIC 각각 필요한 곳만 검증한다. 새 사유를 검사하는 시험은 그 기대값 변경을 명시하고, 과거 저장 사유를 그대로 보여 주는 API 대조군은 유지한다. 과거 `실시간 손절(WS)` 문자열의 조회 호환성을 없애지 않는다.
- O1과 O3는 같은 두 서비스의 작은 변경이므로 관련 검증 후 하나의 고정 후보로 묶어도 된다. **별도 승인 대기 없이 W6의 실제 로컬 jar 대조·서버 실행 금지 배포/복구 초안·영향 분기 대역 검증까지** 잇는다. 로컬 통과가 운영 설치 승인은 아니다.

## 3. 하네스 보완과 W3 남은 확인

총괄은 현재 하네스 단언 식만 AST로 꺼내 가짜 값 여섯 개로 실행했다(앱·DB·외부 명령 없음). 정상 대조군 세 개와 아래 허위 통과 세 개를 확인했다. **기존 run2/run5의 실제 409·종료0·장부 결과는 보존된 원문에서 확인돼 유효하다.** 하네스의 다음 실행부터 거절할 입력을 보완한다.

1. 재시작 요청의 응답이 **200이고 기록이 안 바뀌어도** 현재 식 `d == []`는 통과한다. 실제 HTTP 409와 거절 사유를 기록 차이 0과 **함께** 단언한다. 성공 응답·다른 HTTP 실패는 거절하는 국소 대조를 둔다. 두 리허설 파일의 같은 검사에 적용한다.
2. F5-3이 기대 텍스트를 출력한 뒤 **종료1이어도** 현재 검사는 통과한다. F5-1 주입 뒤 검사도 종료값을 보지 않는다. `rc==0`을 함께 검사하고, F5-1의 종료 시각은 같은 문자열 세 개라는 조건만이 아니라 **F2 실제 started_at+56일**과 비교한다. `due f`/아직56일전/두 번째 요청 거절은 기존대로 비0이 기대다.
3. 최고 평가액 첫 기록 대기가 실패하면 단순 NOTE로 계속하지 말고 그 단계에서 중단한다. 관측 메모는 통과 단언 수와 분리한다. run5의 기존 `41/41` 원문은 고치지 않고 이후 설명에서 **31단언+10관측**으로 정정한다.
4. 환경 ERROR 예외는 로컬 차단 때문에 관측한 종류로 좁힌다. `Source] 수집 실패`라는 공통 꼬리만으로 모든 뉴스 파싱/처리 오류를 빼지 않는다. 차단 대조와 예상 밖 뉴스 처리 오류를 구분하는 국소 입력을 확인한다. 이 예외는 리허설 전용이며 운영 N03 분류에 적용하지 않는다.
5. 위 검사/집계 보완은 순수 함수·가짜 입력으로 검증한다. **하네스 판정 보완만을 이유로 한 시간 리허설을 반복하지 않는다.** 다음 실제 후보 검증에서 필요한 경로가 있으면 그 구간과 같이 수행한다. 과거 출력·실패 폴더·체크섬은 고치지 않는다.
6. W3의 추가 공백은 **N15가 실제 PostgreSQL 잠금을 기다리다 E에 도달하는 경우**다. LIVE·DYNAMIC 각각 한 경우를 국소 PG 시험으로 확인한다. 기존 EntryClock을 제어하고 실제 계좌/세션 행 잠금 대기 진입을 latch/DB 상태로 확인한 뒤 시계를 E로 움직이고 잠금을 푼다. 기존 동일한 PG 시험이 있으면 그 근거를 재사용하고 새로 만들지 않는다. 결과는 원래 가용액·새 의도/주문/슬롯/거래소 호출 0·ENTRY_EXPIRED를 단언한다. 단순 조회 지점 시계 이동과 실제 잠금 대기를 구분한다. 새 Clock/트랜잭션/잠금 정책을 제품에 만들지 않는다. 의도 직전 환원·늦은 체결의 기존 국소 시험은 코드 동일성을 연결하고 전부 재실행하지 않는다.
