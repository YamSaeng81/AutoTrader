# N21 운영 적용안 초안 — 6379ee0b (총괄 v1.138 §106-3, 실행 금지)

**초안이다. 서버에서 아무것도 실행하지 않았다.** 이 블록을 쓰려면 총괄의 고정 출처 검토와 실행 승인이 먼저 있어야 한다. 로컬 문법 확인과 대역 사례 실행까지만 했다. 대역 사례에서는 서버·docker·cron·네트워크를 쓰지 않았다.

cron은 매시 :19에 `cd ~/crypto_trader/AutoTrader && /usr/bin/python3 scripts/prospective/start_66.py freshness --save`를 실행한다. 그래서 체크아웃 파일이 바뀌면 다음 회차부터 새 판이 돈다. `1899b49`와 `6379ee0b` 사이에 backend 소스 차이는 없다. 바뀌는 것은 `scripts/prospective/` 아래 두 파일뿐이다. 따라서 실행 중인 이미지가 서버 HEAD의 소스와 어긋나지 않는다.

### 파일만 덮어쓰는 방법은 쓰지 않는다

체크아웃은 그대로 두고 `start_66.py`만 덮어쓰면 추적 파일 변경이 1건 생긴다. 그러면 다음 두 검사가 걸린다.

- 정기 점검 `daily_check.sh` 1절이 "서버 작업 트리에 추적 파일 변경 1건" 🔴을 낸다.
- F1이 "HEAD 가 1899b49 가 아니거나 추적 파일 변경 있음"으로 멈춘다.

그래서 초안은 고정 SHA로 체크아웃만 옮긴다. 이것도 기존 운영 기준 검사를 저절로 유지하지는 않는다. 아래 '영향' 표의 핀은 승인과 함께 따로 갱신해야 한다.

### 이미 돌고 있는 회차의 취급

- A0·A1·되돌림은 `pgrep -af "start_66.py freshness"`가 무엇이라도 찾으면 **바꾸지 않고 멈춘다.** 회차를 끊지 않는다.
- 11-09처럼 회차가 길어지면 끝날 때까지 기다린 뒤 A0부터 다시 한다.
- 실행 중인 Python 프로세스는 시작할 때 원문을 이미 읽었다. 그래서 회차 도중에 파일이 바뀌어도 그 회차는 옛 판으로 끝난다.
- 그래도 어느 판이 어느 행을 냈는지 섞이지 않도록 회차가 없을 때만 바꾼다.
- 매시 :14~:24는 피한다. 이것은 새 정책이 아니라 블록의 안전 구간이다. cron 시각·주기·시간제한은 바꾸지 않는다.

### 자연 관측에서 확인할 수 있는 범위

- A2로 확인되는 것:
  - 새 판이 cron으로 시작됐다(시작 줄. PID가 없어 완료 행과의 짝은 확정하지 않는다).
  - 저장 JSON 칸이 그대로다.
  - 실패 종류가 있는데 `exTo`가 남은 행이 0이다.

- 적용 뒤 재조회 실패 회차는 🟢 대신 ⚪ 또는 🔴가 된다. 그래서 72시간 연속 구간이 더 자주 끊길 수 있다(기존 계약으로 돌아가는 것). 총괄 v1.138 검토가 실제 원문 `_streak_reset`·`_streak_update`로 초기화·회복·과거 경보 보존 6확인을 했다.
