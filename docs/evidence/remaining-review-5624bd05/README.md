## 4. 지금 보완할 범위 — 추가 착수 승인 불필요

### 4-1. 생성 호출기

1. C1을 실패 시험으로 고정한다. 사후 목록이 성공이고 **정확한 팔 집합8개·팔별ID1개·예상 밖ID0개**가 확인될 때만 API 생성 대조 성공으로 처리한다. 실패/키 누락/형식 이상/불완전 집합을 빈 성공 결과로 채우지 않는다. DB 검증 전 초안 상태는 계속 명시한다.
2. **의도는 있는데 최종 결과가 없는 전송**이 하나라도 있으면 새 POST를 보내지 않는다. 프로세스 종료·응답 수신 전 종료·기록 쓰기 실패 뒤 재실행을 대역에서 확인한다. 파손된 기록부나 본문/프로토콜/대상 코드가 다른 기록부도 보내기 전에 거절한다. 사전 RUNNING 목록이 비어 있다는 사실로 과거 전송 미접수를 확정하지 않는다.
3. 실행 중복을 막는 기록 폴더 단위 잠금과, 요청 전 의도/응답 후 결과를 보존하는 최소 원자성·기록 실패 시 중단을 갖춘다. 기록부를 지우거나 새 폴더를 만들어 무조건 재시도하도록 안내하지 않는다. 재시작 시 자동 이어 보내기나 서버 생성 API 우회는 넣지 않는다.
4. 응답/목록의 JSON 구조·필수 키·ID/시간 형식을 확인하고, 틀린 응답도 원문/비밀을 출력하지 않는 고정 UNKNOWN/조회 실패로 기록한다. 마감 창과 T0는 실행 시작 한 번의 시각에만 의존하지 않게 요청 직전에도 확인한다. 창을 지났거나 남은 생성의 동시 시작을 보장할 수 없으면 더 보내지 않고 부분 결과로 남긴다.
5. A/B 응답 구분 불가를 보완하기 위해 규칙 지문에 새 팔 표지나 통계 오버라이드를 임의로 추가하지 않는다. OK 응답 ID로 귀속하되, 응답 불명 뒤 목록의 유일 후보는 **잠정 후보**일 뿐이다. 다른 동시 생성이 있을 수 있으므로 팔의 확정 귀속은 요청/응답 기록과 생성 뒤 DB 저장값 대조로 한다. 귀속 불명은 총괄 판단 전까지 멈춘다.

### 4-2. 집계기와 생성 기록부 연결

1. A1/A2를 실패 시험으로 고정한다. API 초안(`db_verified=false`)·검증 플래그 없음·확인 실패·미확인 규칙 지문은 주지표를 계산하지 않는다. 유효한 팔별 지문은 서로 달라도 되지만 모두 존재하고 생성 뒤 보존 DB 확인과 맞아야 한다. 서로 빈 값이 같다는 것을 유효성으로 보지 않는다.
2. 완성 기록부의 필수 필드/정확한 세션·팔 집합, 저장값, T0 전 거래0, 프로토콜 및 고정 최종 SHA를 검증한다. 실제 값이 “확인됨”인 경우만 그 상태를 붙인다. 기존 합성 fixture도 완성본 플래그/지문을 명시한 대조군으로 바꾼다. 설정/거래 전향 결과를 보고 프로토콜을 바꾸지 않는다.
3. 생성 호출기의 API 초안→읽기 전용 DB 결과→완성 기록부→집계기의 **하나의 국소 연결 시험**을 추가한다. ID/팔 뒤바뀜, 한 팔의 저장 하한 불일치, 지문 누락/복수, T0 이전 거래, DB 확인 실패를 각각 거절한다. DB를 읽지 않고 `db_verified=true`만 수동으로 붙인 파일을 확인된 근거라고 쓰지 않는다.
4. v1.148에서 도입할 CLOSING도 아직 보유한 포지션이다. 미정산 행을 추출에서 빼거나 CLOSED 현금흐름으로 만들지 않는다. T1 유효 평가가가 없으면 계속 판정 불가다. 최종 후보의 저장 구조/현금흐름과 추출 SQL·집계 입력을 맞춘다. 기존 42일·4쌍 동일 가중·고정 비용/전체 시도 기록·66 중간 성과 비열람은 유지한다.
