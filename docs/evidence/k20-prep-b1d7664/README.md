## 1. 실제 bootJar 대조

두 작업 사본에서 `./gradlew :web-api:clean :web-api:bootJar -x test --offline` 를 새로 돌렸다. 운영 Dockerfile 의 `gradle :web-api:bootJar -x test` 와 같은 작업이다. 빌드는 12:49 KST 에 끝났다.

- `cat-n08`: HEAD `ea44900`, 추적 파일 변경 없음.
- `cat-n11`: HEAD `b1d7664`, 추적 파일 변경 없음.
- 두 jar 의 sha256 은 `jar-sha.txt` 에 있다.

| 비교 | 출력 | 파일 |
|---|---|---|
| **K1 비교 코드**(문서 블록에서 그대로 꺼냄) | 뉴스 클래스 9줄(변경 7·추가 2)과 `(끝) 779 781` | `jar-diff-k1.txt` |
| J1 원래 코드(#19) | 같은 9줄과 `(끝) 680 682` | `jar-diff-j1.txt` |
| jar 안 전체 항목(로더·`META-INF`·`classpath.idx` 포함) | 같은 9줄과 `(끝) 877 879` | `jar-diff-all-entries.txt` |

- ea44900 쪽 680 은 #19 J1 서버 출력의 새 쪽 680 과 같다.
- 9줄 밖에는 차이가 없다. 같은 소스에서 빌드하면 같은 바이트가 나온다는 뜻이다.

**K1 비교 코드를 바꾼 이유.** J1 코드는 세 가지만 셌다. `BOOT-INF/classes` 의 `.class`, 자체 모듈 jar 안의 `.class`, 외부 라이브러리 jar 다. 그래서 다음 99개는 보지 않았다.

- `BOOT-INF/classes` 의 리소스 96개: `application*.yml`, `db/migration/*.sql` 등.
- 자체 모듈 jar 안의 리소스 3개.

총괄 지시는 클래스·설정/리소스·외부 라이브러리를 대조하라는 것이다. 그래서 두 조건만 "디렉터리가 아닌 모든 항목"으로 바꿨다. 나머지 줄은 J1 과 같다.

`jar-tamper.txt` 는 b1d7664 jar 를 네 가지로 변형해 두 코드의 출력을 비교한 것이다.

| 변형 | J1 원래 코드 | K1 코드 |
|---|---|---|
| `db/migration/V95__x.sql` 추가 | **못 잡음**(9줄·680 682) | `추가 …V95__x.sql`, 782 |
| `application.yml` 변경 | **못 잡음** | `변경 BOOT-INF/classes/application.yml` |
| 외부 라이브러리 jar(flyway-core) 변경 | 잡음 | 잡음 |
| 자체 모듈 jar 안 `META-INF/MANIFEST.MF` 변경 | **못 잡음** | `변경 …core-engine.jar!META-INF/MANIFEST.MF` |

K1 은 9줄이 아니거나 `(끝) 779 781` 이 아니면 **재기동 전에** 멈춘다.

## 2. 블록 문법

계획 §5-9 53 에서 K 블록 8개를 그대로 꺼냈다. 8개는 K 변수, K0, K1, K2, K3, K4, K 뒤 뉴스 관측, K 되돌림이다. `bash -n` 은 8/8 통과했다(`blocks-syntax.txt`). 블록별 sha256 은 `block-hashes.json` 에 있다. 계획 문서의 bash 블록은 63개에서 71개가 됐다. 이전 63개는 바꾸지 않았다.

## 3. 국소 가짜 입력

블록 원문은 그대로 실행했다. 대역으로 바꾼 것은 서버 의존 부분뿐이다.

- 명령: `$PSQL`, `$DC`, `docker`, `git`, `crontab`, `svc`, `sc`, `qc`, `sid203`, `maint_verify`, `start_66.py`.
- 설치본·cron 해시 상수: 대역 파일 값으로 바꿨다.

나머지는 실제로 돌렸다. `btcok`, `btcgate`, `kwin`, `newsobs`, 오류 분리 grep, 시각 계산이다. 이 실행기는 스크래치에만 두고 저장소에는 넣지 않았다.

## 4. 하지 않은 것과 한계

- 서버·DB·외부 HTTP 접속, 운영 설치, docker 이미지 빌드, 앱 기동은 하지 않았다. 기존 167건, 전체 리허설, N11 시험도 다시 돌리지 않았다.
- **K1 과 서버 빌드**: K1 기대값은 로컬 Gradle(Java 17) 빌드에서 나왔다. 서버는 docker `gradle:8.7-jdk17-alpine` 으로 빌드한다. #19 때는 로컬 대조와 서버 J1 출력이 같았다. 서버에서 다르게 나오면 K1 이 재기동 전에 멈추고, 그 출력을 보고한다.
- **K2·K1-되돌림·K 되돌림·K 뒤 뉴스 관측**: 문법만 확인했다. 이 블록들은 J2·J 되돌림과 같은 줄에 대상 값과 문구만 바꿨다.
- **뉴스 줄 형식**: `newsobs` 와 오류 분리는 후보 코드의 로그 형식과 기존 ERROR 원문 4개를 기준으로 짰다. 실제 운영 로그로 확인한 것은 아니다.
- **실제 출처 응답**: RSS 4개와 업비트 공지의 실제 응답 호환성은 배포 뒤 기존 주기의 관측에서 처음 확인한다.
