총괄은 보존된 합성 입력의 UQ만 실제 SQL의 8열 모양으로 투영해 검사기에 1회 넣었다. rc1, `ValueError: not enough values to unpack (expected 7, got 6)`이 재현됐다. 이는 SQL 실행 결과가 아니라 정적 열 수를 반영한 파일 반례다. [checks.json](checks.json)과 stdout/stderr에 보존했다.

## 3. 다음 작업 — 바로 연속 진행, 운영 호출 없음

### 3-1. 새 사본에서 최소 보완

원본 SQL·파서·모델·체크섬은 그대로 두고 새 사본 r1-diag-2를 만든다. SQL이 UQ union_items까지 계약대로 출력하도록 고친다. UNION 각 분기의 열 수·최종 SELECT·주석·출력 식별자를 함께 맞춘다. 원래 ORIG 식과 R1 선택 조건은 바꾸지 않는다.

검사기는 필수 행의 열 수를 인덱스 접근·언패킹 전에 확인하고, 부족한 UQ는 traceback 대신 SHAPE_MISMATCH rc7로 거절한다. 숫자 0으로 누락을 메우지 않는다. 실제 출력으로 META의 Flyway 96, 격리 수준, 보호값, ORIG/SPLIT, 모드·사유·AGE·UQ 관계가 확인돼야 성공이다. 이 검사를 새 실행기에 연결할 때 실제 프로세스 종료값을 확인한다.

### 3-2. 격리 로컬 PG 검증 1묶음 승인

운영과 분리한 로컬 일회용 PG 15.13/기존 timescale 이미지에서 d81c3f2f V1~V96 스키마와 합성 입력만 사용한다. 컨테이너 네트워크는 차단한다. 생산 별칭·SSH·운영 인증·실제 DB 파일을 사용하지 않는다. 제품 시험·회귀·jar는 실행하지 않는다.

목적은 SQL 원문 전체의 문법·실행·출력과 검사기 연결이다. 손계산 가능한 중복 A/P, NULL position_id, 원가 결측, 모드 분류, 무거래 제외를 같은 합성 데이터 묶음에 넣는다. 파일 모델이 SQL 결과를 대신 생성하지 않게 한다. SQL 원문·psql 종료값·stdout/stderr·보호값·수집 시각·검사기 종료값을 회차 고유 경로에 보존한다. 성공은 psql rc0, stderr 없음, 실제 결과의 합계·분류가 기대와 일치하고 형태 검사도 0인 경우뿐이다.
