# 제한 실거래 계획서 정리 — 현재·실행·이력 분리

사용자가 현재 진행과 과거 내용이 섞인 계획서의 정리를 요청해 2026-11-12에 분리했다. 총괄 v1.158의 판단·허용 범위를 요약했으며 새 정책이나 운영 실행 승인을 추가하지 않았다. 커밋·push는 하지 않았다.

## 파일 구성

| 파일 | 역할 |
|---|---|
| [현재 계획](../../LIMITED_LIVE_TEST_PLAN.md) | 110줄. 운영과 로컬 후보, 남은 작업, 전략 검증, 고정 조건과 일정을 표시 |
| [F 실행 절차](../../LIMITED_LIVE_TEST_RUNBOOK.md) | 600줄. 기존 F0~F6의 15개 bash 블록과 중단·종료 대응을 유지 |
| [전체 원문 보존본](../../LIMITED_LIVE_TEST_PLAN_ARCHIVE_20261112.md) | 분리 직전 11,932줄·1,531,593바이트 전체. 종전 §1~§7, §5-9 1~126, 과거 판정과 149개 bash 블록을 보존 |

보존본 SHA256은 `387db4d78d2d187d2503904ec22ec7b8299d6d994746d6d109070e453037af6c`다. HEAD 60777286의 파일만이 아니라, 아직 커밋하지 않았던 총괄 v1.158 반영분까지 포함한 **이번 요청 직전 작업 사본**과 바이트 단위로 같다. 이전 review-60777286/doc-check.json의 계획서 after_sha256도 이 보존본에 해당한다. 이전 검토 근거·체크섬은 고치지 않았다.

## 유지한 것과 바꾼 참조

- F 명령 15개는 순서와 본문이 같다. 각 해시는 audit.json에 기록했다. HEAD·이미지·경로·SID·START_DATE·한도와 명령 기대값은 변경하지 않았다.
- 실행 절차의 중단 대응 설명 중 “운영 fe01207/N15 미반영”이라는 오래된 문장 한 곳은 이미 수용된 운영 b5cd1d0/N15 반영 상태로 고쳤다. 기한과 대응 순서는 변경하지 않았다. 과거 문장은 보존본에 그대로 남는다.
- test_start_gate.py와 test_sid_ledger.py는 F 절차를 새 실행 문서에서 읽는다. test_cron_switch.py는 과거 장부 추가 블록을 보존본에서, 현재 F2-1을 실행 문서에서 읽는다. 시험 기대값은 바꾸지 않았다.
- rehearse_sma20.py·rehearse_w3.py의 RT_PLAN_DOC는 실행 문서를 사용한다. 종전 계획서 경로를 준 호출도 같은 폴더에 실행 문서가 있으면 연결한다. 과거 세션 생성 JSON은 보존본에서 읽고, 분리 전 작업 사본에서는 종전 자체 본문을 그대로 사용한다.
- .gitattributes에 보존본과 실행 문서의 `-text`를 지정했다. 과거 evidence/ 폴더는 변경하지 않았다.
- PROGRESS에는 문서 안내 한 단락만 넣었다. 개발 결과 번호와 총괄 판정 번호는 새로 만들지 않았다. 다른 세션이 만드는 v158 근거와 권한 설정은 건드리지 않았다.

## 확인

| 확인 | 결과 |
|---|---|
| 전체 원문 보존 | 위 SHA256 일치. bash 149개 포함 |
| F 명령 보존 | 15/15 순서·본문 일치 |
| 기존 시작 연결 시험 | **7/7**, 로컬 명령 대역만 사용, 종료 0 |
| 기존 cron 연결 시험 | **44/44**, 로컬 가짜 crontab과 임시 HOME만 사용, 종료 0 |
| 도구 참조·SQL·문서 링크·문법 | verification.json에 개별 결과 기록. 실행기 모듈을 import하지 않고 선택 구문과 추출 함수만 확인 |

F2-1에는 원래 `SHA=<리뷰가 확인한 커밋 SHA>`라는 자리표시자가 있다. 원문 그대로의 bash -n은 이 블록에서 실패하며, 기존 cron 시험처럼 문법 검사 입력에서만 `SHA=syntax-only`로 치환하면 15개 모두 통과한다. 문서의 명령 본문은 바꾸지 않았다. 첫 정적 확인은 이 자리표시자를 그대로 검사해 중단됐다. 그다음 확인은 아직 쓰지 않은 이 README 링크에서 중단됐고, 파일을 작성한 뒤 전체 정적 확인을 마쳤다. 결과를 숨기거나 명령을 고쳐 통과시키지 않았다.

이번에는 서버 접속·운영 DB·Docker·앱/PG 리허설·전체 회귀·jar 빌드·세션 변경을 하지 않았다. test_sid_ledger.py와 두 리허설의 실제 앱 실행도 반복하지 않았다. 그 도구가 추출하는 F5-3 SQL·F 블록·생성 JSON의 동일성만 확인했다. 문서 정리는 전략 수익성이나 운영 안전성의 새 시험 결과가 아니다.

## 이후 갱신

현재 계획의 표와 최신 근거 링크만 갱신한다. 명령은 실행 문서에서 관리하고, 결과는 해당 evidence/README와 PROGRESS로 연결한다. 보존본은 고정하며 옛 §번호 참조를 따라갈 때 사용한다. 새 검토 전문을 현재 계획 맨 앞에 누적하지 않는다.

이 폴더의 SHA256SUMS는 이 폴더의 확정 파일을 대상으로 한다. audit.json에는 문서의 해시·줄 수와 F 블록 해시를 따로 기록했다. Git 커밋 블롭 검증은 실제 결과와 함께 커밋하는 시점에 다시 확인한다.
