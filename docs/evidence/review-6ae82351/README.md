## 3. 지금 시작할 작업 — 완료 즉시 다음 단계

### 3-1 복구 게이트 v3와 소액 시험 원문 초안

원본 v2와 체크섬을 보존하고 별도 사본을 만든다. v2는 `terminal_without_proof_info`를 참고로만 두고 `FAILED AND failure_code IS NULL`만 센다. 제품 `OrderExecutionEngine.isTerminalWithoutNoFillProof`는 **NULL뿐 아니라 허용 목록 밖 코드**도 판정 불가로 본다. 따라서 STOPPED·기존 block 0이라는 이유로 근거 없는 종결 주문을 자동 통과시키지 않게 한다.

- 시험 대상 LIVE 세션의 미입증 종결은 자동 복구 확인에서 차단/사람 확인으로 남긴다. 제품의 코드 목록·취소 확인 조건을 그대로 연결하며, 임의 비어 있지 않은 문자열을 무거래 근거로 인정하지 않는다. 모든 과거 종결을 지우거나 무거래로 재분류하지 않는다. 이미 증거로 해결된 경우의 처리도 명시한다.
- 대상 ID·REAL·maxEntries=정수 1·등록 원천이 없거나 불일치하면 통과하지 않는다. 대상 없음의 0행, 부분 출력, 조회 실패, 알 수 없는 상태도 통과하지 않는다. 후보 스키마와 실제 열 이름으로 대조한다.
- 생성→응답/저장 대조→start→매수/매도/정산 관측→정지/정리→종료 확인을 구체 파일 초안으로 만든다. 인증값을 넣지 않고 승인 날짜·창·대상 ID가 비면 원격/POST 전에 거절한다. 아직 실행기 전체나 실제/가짜 SSH를 실행하지 않는다.
- A3에 필요한 실제 계좌 여유·수수료·최소 주문액·시계/상태 근거는 기존 검토안에서 최소 필드만 연결하고, 얻을 수 없는 증거는 미확정으로 둔다. '계좌 성공=충분'으로 바꾸지 않는다. 신호를 강제로 만들지 않으며 자연 신호가 없으면 미실행으로 기록한다. 대기 종료·강제 정지의 청산 포함 의미를 구분한다.

### 3-2 격리 로컬 PG 1묶음 — 복구 SQL와 제품 경로 확인

운영과 분리된 PG15.13·V96 합성 데이터로 **새 1묶음**을 허용한다. 기존 12/12·H2 11/11은 반복하지 않는다. 실제 거래소/운영 접속은 금지하고 거래소 응답만 대역으로 한다. 회차별 새 보존 경로와 실행 전 대상을 고정한다.

1. 복구 게이트: 정상 종료(완료 cleanup 이력 있음)는 통과, 미완료 cleanup·활성/미정산 주문·잔량·취소 미확인·FAILED NULL/목록 밖 코드·대상 없음·비상 정지는 불통과/보류. 허용된 무거래 근거의 정상 대조도 넣는다. SQL 결과만이 거래소 잔량 확인은 아님을 유지한다.
2. 실제 LIVE 매수 서비스 경로에서 maxEntries=1 생성·저장→첫 매수 의도/정산→매도 정산→다음 매수 시도 거절을 연결한다. 직접 예약 메서드만 부른 기존 시험과 구분한다. BUY 의도 1, 추가 차감/외부 매수 제출 0, SELL/정산은 진행 가능함을 확인한다. 새 트랜잭션에서 저장값을 다시 읽되 앱 재기동 증거라고 쓰지 않는다. 세션/지문·응답 타입도 대조한다.
3. 복구 SQL가 통과해도 구판이 maxEntries를 무시한다는 위험은 남는다. 구판에서 이 세션을 다시 start하지 않는 절차와 거래소 확인 의존을 실행안에 연결한다. 정지 경합을 해결했다고 쓰지 않는다.

구동기 결함/제품 실패가 있으면 원문을 보존하고 실패 단계와 추가 실행 필요 범위만 보고한다. 실패를 숨기기 위한 반복·기대값 변경·전면 데이터 보정은 하지 않는다.
