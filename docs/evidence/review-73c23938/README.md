## 2. 수집 계약 보충 — 실행 승인이 아님

1. **C0~C6은 실행 관리 순서다. P7 `meta.steps`에 그대로 넣지 않는다.** P7 v8이 받는 순서는 `db_fp_pre → exchange_before → db_extract → exchange_after → db_fp_post`의 정확히 5개다. C2의 실제 psql 호출 구간만 `db_extract`에 대응할 수 있다. 나머지 4개는 별도 수집 근거가 필요하다. 미수집 단계를 같은 시각·같은 지문으로 채우지 않는다. [직접 형식 대조](contract-probes.json)에서 C0~C6을 넣으면 거절됐다.
2. **시계 표본에는 `step:'db_extract'`가 필요하다.** 계약의 예시에는 이 필수 키가 빠져 있다. `version`과 표본의 `pair, step, c0, d, c1, mono_rtt_ms`를 실제 P7 스키마에 맞춘다. 표본 하나는 DB의 d 시각을 수집기 구간으로 옮기는 근거이며, 그보다 앞선 META now()나 과거 생성·월 경계 시각으로 외삽하지 않는다. 직접 대조에서도 d 이전 점의 변환은 미확정이었다.
3. 스냅숏은 psql 호출의 실제 시작·끝 사이에 발생하지만, 벽시계 `[c0,c1]` 구간으로 표현하려면 단조 시계와의 일치 검사가 전제다. 시계 이동·역행이면 그 회차의 축 관계를 미확정으로 둔다. DB의 `[now(), END]` 역시 벽시계가 움직이지 않았다는 근거 없이 수치상 보장된 경계로 쓰지 않는다. 어느 구간도 정확한 월말 T 포착을 뜻하지 않는다.
