# 총괄 v1.239 — 만료 집계 최소화, 배포와 실주문 시작 분리

2026-11-24 KST. c00fb2bc의 조사 5개·시험안 2개 체크섬이 커밋 블롭과 7/7 일치한다. 로컬 코드 조사와 기존 PG 근거 연결을 범위 수용한다. r1-diag-3 초안 및 실주문 실행은 수용 전이다. 총괄은 로컬 파일·Git만 확인했으며 운영·계좌·PG·빌드·시험 호출은 없다.

## 1. 조사 판정과 정정

E 예약 거절은 유력한 가능성이며 d81의 ENTRY_REJECTED 기록은 이미 존재한다. 과거 9개 행의 실제 경로는 여전히 미확정이다. D/O/S에 필요한 주문 없는 OPEN이 있다는 사실만으로 “주문 기록이 사라졌다”를 확정하지 않는다. 비정상 커밋/트랜잭션 경로·기존 고아 등 가능성을 남긴다.

strategy_log는 포지션 외래키로 연결되지 않는다. 같은 세션·코인·6분 창의 거절 로그는 **상관 근거**이지 해당 포지션이 E였다는 충분조건이 아니다. `E_ONLY`는 “E 조건만 맞았다”는 분류일 뿐 경로 입증이 아니다. `updateSignalQuality`의 null·저장 실패도 있다. 모든 로그가 같은 트랜잭션에 있다는 코드 판독만으로 과거 인과를 확정하지 않는다.

초안은 다음 이유로 그대로 실행하지 않는다.

- EXP의 `date_trunc('minute', max(closed_at)+30일)`은 만료보다 최대 약 1분 이르다. R1 조건이 `closed_at >= cutoff`이므로 경계와 정확히 같아도 남는다. 안전한 재확인 시각은 **마지막 만료 경계보다 엄격히 뒤**여야 한다.
- NEW의 11-01 기준은 이전 AGE의 끝일 뿐 “직전 진단 뒤 발생”이 아니다. 또한 현재 DYNAMIC NO_SOURCE 부분집합만 보므로 다른 새 R1 분기는 보이지 않는다. NEW=0을 신규 판정 불가 전체 0으로 쓰면 안 된다.
- 과거 E 입증만으로 제품 R1은 바뀌지 않는다. 이번 일정 판단에는 상세 경로 분류보다 **현재 전체 R1·만료 상한·실자금 실행 상태**가 먼저 필요하다. strategy_log 연결을 더 정교하게 만들며 일정을 늘리지 않는다.

## 2. 실주문 시험안 — 금액 설계는 참고, 실행 보류

9,950원 요청·0.05% 수수료 가정의 산술은 1만원 예산 안이다. 하지만 실행 환경의 실제 수수료/예약 계약 확인 전 확정 상한으로 보지 않는다. 자연 신호 전략과 FORCED_STOP 왕복을 구분한 것은 맞다.

**“정산 직후 stop을 부르면 매수 최대 1회”는 보장으로 수용하지 않는다.** 정지 요청 전 가격 급변·자동 매도·재진입·관측 지연·세션 종료가 가능하고, 열린 포지션 중 추가 진입 보호도 미확인이다. H1 다음 평가 전에 사람이 대응한다는 조건은 원자적 매수 횟수 제한이 아니다. 이 안으로 start를 실행하지 않는다.

새 시험은 DAILY_SMA20/KRW-BTC/H1을 기본안으로 유지한다. 거래를 만들기 위해 다른 전략이나 강제 신호로 바꾸지 않는다. 신호가 없으면 미실행이다. 대기 일수·실행 창은 실제 배포 후 상태에 맞춰 정하며 지금 며칠 동안 무인 RUNNING으로 두지 않는다.

### 3-1. 만료·실행 상태 최소 진단 묶음

r1-diag-3 초안은 보존하고 새 사본으로 단순화한다. strategy_log·E/D/O/S 연결·원인 단정 태그는 이번 읽기에서 뺀다. 금액·행 ID·원시 사유는 출력하지 않는다.

필수 출력은 아래에 한정한다.

1. 기존 R1 LIVE/DYNAMIC 각각 A·P·합계. 기존 식·대상 조건을 유지하며 서로 합계가 맞아야 한다.
2. 해당 R1 모든 대상의 최초/최종 만료 경계. UTC 원시 경계와, 마지막 경계보다 확실히 뒤인 **다음 분 시작**을 구분해 출력한다. 대상 0은 명시적인 빈 경계로 처리한다. 새 경계가 발견되면 과거 9건 상한과 분리한다.
3. 직전 진단 DB 시각 `2026-11-24T04:49:14.512Z` 이후 각 분기에 잡힌 행 수. 이는 해당 시각 이후의 sell_applied_at/closed_at 수이지 모든 삽입·수정·삭제 이력의 증명이 아님을 명시한다.
4. REAL LIVE/DYNAMIC 세션 상태별 개수, 미해결 제출·활성 주문·열린/정리 중 포지션 개수. 모드/종류 불명·소유자 없음은 별도 불명으로 내며 0으로 메우지 않는다. 기존 범위 밖 옛 고아 행은 금액 없이 분리해 계속 보존하고 정상으로 재분류하지 않는다.
5. 기존 META·Flyway96·15s/2s·READ ONLY·REPEATABLE READ·ROLLBACK·시각 축과 종료값 계약을 유지한다.

새 SQL·형태 검사기·**승인 값이 비어 있는 실행기 사본**을 작성한다. 실제/가짜 SSH는 실행하지 않는다. 실행기는 기존 고정 v1.236에서 바꾼 부분의 차이·해시와 bash -n 결과만 제출한다. 실제 창·폴더·호출 횟수는 검토 후 총괄이 확정한다.

**격리 로컬 PG 1묶음을 승인한다.** 운영과 분리된 network none PG15.13·수용 스키마로 정상, 대상0, 분 경계 직전/정각, 새 A/P 대상, 실행 중 REAL, 조회 실패/보호값 이상을 한 묶음에서 확인한다. 파서는 필수 행·열·타입·합계·실패 출력을 파일로 확인한다. 제품 엔진 PG·전체 회귀·jar는 반복하지 않는다. 구동기에는 실제 SSH 대체 경로를 두지 않는다. 회차별 고유 폴더를 실행 전에 정하고 실패 원문도 보존한다.

### 3-2. D81 유지보수 배포용 U0 보정안

총괄은 **매매 시작 관문과 유지보수 배포 관문을 분리하는 방향을 채택**한다. R1>0 상태의 신규 실자금 진입 차단은 제품에서 그대로 유지한다. 과거 DB·제품 예외·pf3ok 원문을 고쳐서 통과시키지 않는다.

로컬에서 새 U0 사본만 준비한다. 기존 R1=0 전용 원문도 보존한다. 보정안은 다음 조건을 모두 갖출 때에만 “유지보수 배포 준비 가능, 매매 시작 금지”로 구분할 수 있다.

- REAL RUNNING 세션 0, 실자금 보유·진행 주문·미해결 제출·청산/정리 대기 0을 확정할 수 있다. 불명·조회 실패는 거절한다.
- 실제 R1 수와 분류를 기록한다. 이번에 확인한 과거 DYNAMIC P 무원천 대상 외의 새로운/불명 분기가 있으면 멈춘다. 과거 대상인지 입증 못하면 허용하지 않는다. 집계 숫자 9만 같다는 것을 동일 행 증거로 쓰지 않는다.

### 3-3. 실주문 1회 제한의 최소 설계

기존 코드에서 열린 포지션·회차·주문 의도·정지와 재진입의 잠금/트랜잭션 경계를 먼저 확인한다. 기존 코드만으로 누적 매수대금+수수료 1만원과 매수 1회가 보장되면 그 근거를 낸다. 사람의 stop 속도만으로 보장됐다고 하지 않는다.

불가능하면 별도 후보의 **최소 1회 진입 제한 설계**를 제출한다. 기본 비활성·기존 세션/지문 불변, 주문 의도와 동일한 잠금/트랜잭션 안 차단, 재기동·동시 신호·UNKNOWN 이후 재제출·매도 후 재진입에 대한 보존 동작, 기존 보유 매도/정지 영향 없음을 요구한다. 이번에는 제품 구현·새 PG·최종 d81 통합까지 확대하지 않는다. 설계 수용 후 필요한 후보와 직접 시험만 정한다.

정지 시장가 매도는 시험 범위로 유지할 수 있으나 자연 매도 검증과 구분한다. 매도 전 최종 상태·잔량·부분 체결·최소액 미달 처리안은 유지한다. 반올림된 계좌 요약만으로 정확한 여유 현금을 확정하지 않는다.
