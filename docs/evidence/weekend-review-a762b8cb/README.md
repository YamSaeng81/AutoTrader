## 2. 추가로 확인한 두 공백

### H1. F5-3 리허설 판정이 0.0016 BTC도 통과

`scripts/restart-test/judge.py:f53_ok`는 `거래소 BTC 증감 0`의 부분 문자열을 찾는다. W3 실제 F5-3 출력의 해당 줄만 `거래소 BTC 증감 0.0016 · 주문 순체결량 0E-8 · 열린 포지션 수량 0`으로 바꾸면 현재 판정이 참이다. 종료0·해시·STOPPED·DB정리 문구는 그대로인 **같은 입력 한 곳 차이**다. 가짜 입력은 `f53-nonzero-btc.input.txt`에 보존했다.

- 현재 run5 원문은 실제 증감0·장부 차이0이므로 앞선 통과를 취소하지 않는다. 제품 주문/정산 결함이나 운영 계좌 차이를 발견한 것도 아니다.
- **부분 문자열 대신 숫자/행 구조를 확인하는 국소 보완을 지금 한다.** BTC 줄의 거래소 증감·주문 순체결량·열린 수량을 Decimal로 읽어 모두0을 요구한다. 정상0·0E-8·음의0 같은 동등한0은 허용하고, 0.0016·−0.0016·누락·형식 이상·서로 다른 중복 행은 거절한다. 임의의 한 행만 고르지 않는다. F3해시·기대상태·종료0·DB정리 확인도 유지한다.
- 같은 입력으로 실패 먼저를 보존하고, 실제 W3 원문 대조와35개 종전 기대값을 유지한다. 운영 F3/F5 블록·계좌 허용오차·정기 점검 분류를 바꾸지 않는다. 하네스 보완만으로 긴 리허설을 다시 돌리지 않는다.

### H2. jar 비교기가 자체 모듈 내부 중복 항목을 놓침

현재 비교기는 바깥 ZIP 이름 중복은 검사하지만, 자체 모듈(core-engine/strategy-lib/exchange-adapter) 내부에서는 같은 이름을 dict에 덮어쓴다. 내부에 `p/A.class`를 다른 내용으로 먼저 넣고 같은 이름의 기대 내용으로 다시 넣으면, 중복 없는 대조 jar와 **차이0**이다. 같은 방식의 바깥 중복은 잡히는 대조도 확인했다. D1 U1 안 함수가 그 비교기와 같은 AST임을 대조했다.

- 합성 자료 세 개는 `fixtures/`에 있다. **실제 보존1899b49/0d142aa jar에는 바깥·자체 모듈 내부 중복이 모두0**이어서 현재3항목 차이를 취소하지 않는다. 이미 배포된 jar의 중복을 발견했다고 기록하지 않는다.

## 3. 전체 시험 실패1건 — 조사와 시험 격리 수정까지 지금 승인

두 원본 XML에서 실패는 `ExecutionDriftTrackerTest#record_negativeSlippage`이고, 기대 음수 대신 **0.000000**을 읽었다. `driftRepo.findAll().get(0)`는 방금 기록한 행을 특정하지 않고, 이 클래스에는 첫 시험 전 정리가 없다. 앞선 행/공유 상태가 원인일 가능성은 있지만, **기점에서도 실패한다는 사실만으로 시험 문제라고 확정하지 않는다.**

1. 기존 음수 체결 입력에서 방금 저장된 행을 추적하고, 조회가 읽은 행과 대조한다. 양수/0의 다른 행을 먼저 넣는 고정 탐침으로 같은 실패를 재현한다. 실행 순서 고정·sleep·반복 성공 선택·실패 제외를 쓰지 않는다.
2. 오염/행 선택 문제로 확인되면 **이 시험 클래스의 데이터/컨텍스트 격리와 대상 행 조회**만 고친다. 원래 음수/양수 단언을 유지하고0을 허용하지 않는다. 고정 오염 입력→수정 전 실패/수정 후 통과·정상 대조를 보존한다.
3. 실제 저장 계산이 틀리면 시험 문제로 덮지 말고 원인·영향을 구분한다. 이미 정해진 저장 계산 계약 안의 결함은 격리 후보의 최소 보완/관련 시험까지 진행해도 된다. slippage 정의·비용 기준·한도/전략 정책을 새로 정해야 하는 부분만 보류하고 다른 과제는 계속한다.
4. O1·O3 제품 변경과 시험 격리 보완을 담은 **최종 SHA**를 고정한다. 관련 국소 시험 뒤 web-api 전체를 그 SHA에서 한 번 돌려 새 실패가 없는지 확인한다. 기존 건너뜀과 PG 환경 미설정 건너뜀은 따로 집계하고, 실제 실행과 같다고 세지 않는다. 기존 두 실패 실행 원문은 유지한다. 원인이 새로 나오지 않는 한 전체를 계속 반복하지 않는다.

## 4. PG 근거 출처 설명 정정 — 재실행 불필요

README는 r11/r12를 후보0d142aa 실행이라고 적었지만, 보존된 HEAD는 **b9f16a6**, 상태는 **N15 PG 시험1개 untracked**다. r11 종료11:04:31 뒤 시험 전용 최종 커밋0d142aa가11:04:43에 생겼다.

시험 사본을0d142aa 커밋 파일과 CRLF/LF만 정규화해 대조하면 같고, b9f16a6→0d142aa는 그 시험 추가1개뿐이다. 따라서 결과는 **후보 제품 코드 b9f16a6 + 이후 커밋과 같은 시험 소스**로 유효하다. 실행 당시에 깨끗한 최종0d142aa였다고만 쓰지 않으면 된다. 다음 실제 결과에서 별도 정정 메모로 출처를 바로잡고, 이 이유만으로 PG를 재실행하지 않는다.

- "로그 범위 확보"는 **현재 컨테이너 재생성에 따른 공백이 없다는 확인**이다. 로그 회전/전송 유실 등 모든 사건이 빠짐없이 기록됐다는 독립 보증은 아니다. 과거13:32~13:36 미확보도 해소하지 않는다. 총괄은 서버 `.log.gz` 전체를 받거나 다시 세지 않았다.
- 앞선 W4 캐시·#26 원문 누락은 현재 커밋에서 보완됐다. 반복 보완 커밋을 만들 필요는 없다.
