## 값 계약

`daily_checks.sql`이 내는 모양만 유효로 본다.

| 대상 | 유효한 값 |
|---|---|
| 건수 키 19개 | 음수 아닌 정수 |
| `quarantine_release_rows` | 정수 또는 `-1` |
| `sid_status` | SQL이 내는 상태 이름(대문자·`_`) 또는 `none` |
| `sid_available_krw` | 음수 아닌 수 또는 `-` |
| `sid_orders_window` | `매수 매도` 정수 두 개 |
| `sid_settle_ids` | `-` 또는 정수 목록 |
| `s66_not_running` | `-` 또는 `id:상태` 목록 |
| `s66_coins` | `-` 또는 공백으로 나뉜 목록 |
| `tg_last_ok` | `YYYY-MM-DD HH:MI` 또는 `none` |

다음 경우는 모두 ⚪(종료 1)이다. 그 키는 🔴로도 정상으로도 판정하지 않는다.

- 단일 값 키가 두 번 이상 나옴. 같은 값이어도 마찬가지다. 앞 값은 보존하고, 뒤 값으로 덮지 않는다.
- 셋째 칸이 있음.
- 빈 값 또는 위 계약 밖의 값. 0으로 메우지 않는다.

보고 줄에는 그 키의 값을 `?`로 적는다.

그 밖의 처리는 다음과 같다.

- **다른 키의 유효한 🔴**: 그대로 낸다.
- **상태를 확인할 수 없을 때**: BTC 줄에 "상태 확인 불가 — 입력 판정 못 함(⚪)"으로 적는다. 적용 제외로 정상 처리하지 않는다.
- **`btc_h1_*` 값 형식**: 기존 N09 검사가 상태별로 그대로 본다. 여기서 더한 것은 중복·셋째 칸 검사뿐이다.
- **`tg_fail`**: 여러 행이 정상이다. 행마다 `유형|정수`만 확인한다.
- **기존 판정**: 시작 전(CREATED) 보유·미결·구간 주문 검사와 66세션·격리 해제·정산 확인 불가 줄도, 확인할 수 없는 키는 건너뛴다. 이 경우는 이미 ⚪로 나간다.

## 범위

- 운영 서버·운영 DB·앱·cron·장부·F1~F6·최종 S·backend는 건드리지 않았다. 서버 접속도 없었다.
- 로그 분류(뉴스 Connection reset 미분류 🔴 포함)는 바꾸지 않았다.
- 전체 앱 시험과 격리 리허설은 반복하지 않았다.
- 시험 출력의 임시 경로와 실행 시각은 로컬 실행 값이다.
- 운영 설치는 후보 검토 뒤에 한다.
