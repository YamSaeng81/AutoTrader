## 실행 시점과 범위

**22시 보고를 기다릴 필요 없다.** 시작 시각이 서버 기준 KST **10:10~20:59 또는 22:10~07:59**이고, 재기동 뒤 30분 안전 확인과 60분 출처 첫 차례 뒤 관측까지 약 70분 이상 계속 대응할 수 있을 때 진행한다. 시간 창은 시작 조건이며 빌드/외부 응답 소요나 종료 시각을 보장하지 않는다.

1. 직전 정기 보고 **본문·서버 전송 기록**을 읽고 현재 HEAD/이미지·BTC·SID 203·설치본·cron에 새 미해명 이상이 없는지 확인한다. 이미 대조한 11-06 10시의 기존 뉴스 reset 미분류 🔴와 BLAST를 없애려고 재실행/분류 변경하지 않는다. 새 보고가 생긴 뒤라면 그 보고를 읽는다. 보고가 없으면 수동 생성/전송 없이 OPS §5로 진단해 보고한다.
2. **de5a7e4 §98 원문만** 사용한다. F → G → §98 U 변수 → U0 → U1. D1/D2/§92와 섞지 않는다. U1은 U0 신선도 30분 안에 시작한다. 서버 main checkout/pull은 하지 않고 승인된 블록의 fetch/고정 후보 checkout만 한다.
3. U1은 실행 backend를 아직 바꾸지 않는다. 새 전체 이미지 ID, 실제 jar 차이 두 항목·`(끝) 881 881`, 이전 이미지 보존, 현재 실행 이미지와 사전검사 결과를 운영자에게 제시한다. **U2 바로 전에 “재기동 진행” 확인 1회**를 받는다. #25/과거 야간 확인을 대신 쓰지 않는다. 이번 승인에 대한 별도 확인 질문은 필요 없다.
4. 확인 뒤 U2로 **backend만 한 번** 재생성한다. 5~10분 뒤 U3, 기동 30분 뒤 U4, 60분 출처 첫 차례가 지난 뒤 U 뒤 관측을 실행한다. 실제 관측 시각·StartedAt/Created를 구분해 적는다. 관측할 이상을 유도하지 않는다.
5. 어느 단계든 중단되면 다음 단계로 가지 않는다. U1 jar/해시 차이는 재기동 전에 중단하며 명시된 U1-되돌림 조건을 따른다. 배포 뒤 “되돌림 필요”라고 명시된 조건 또는 총괄 지시 때만 U 되돌림으로 **ee509cf/200f2f57…**에 복귀한다. 연결 획득 시간 초과는 로그 수준과 무관하게 **P0 즉시 보고**한다. 장기 대여만 있으면 개선 미확인으로 기록하고 자동 되돌리지 않는다. BTC/뉴스/적재 미관측도 원래 블록의 재조회/보고 지시를 따른다.
