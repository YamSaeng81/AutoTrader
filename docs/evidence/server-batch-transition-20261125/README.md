## 1. 지금 바로 가능한 서버 작업 승인

## 2. PC가 꺼져도 끝나는 서버 배치로 전환

목표는 AI 세션을 서버에 항상 켜 두는 것이 아니라 **고정 명령을 실행하고 종료하는 유한 작업**을 서버에서 지속하는 것이다. Claude CLI 설치·로그인이나 토큰 이동 없이 구성한다. 세션 중단 뒤 AI 판단·채팅 보고까지 저절로 이어진다고 약속하지 않는다. 로그와 완료 결과가 서버에 남아 나중에 회수 가능해야 한다.

지금 다음 배치 실행 원문을 작성해 제출한다. 서버에서 무해한 파일/시각 검증까지는 위 범위로 실행 가능하다. **실제 배포 예약 배치를 등록·시작하기 전 총괄의 원문/해시 검토를 받는다.** 사용자의 같은 운영 의사를 다시 승인받기 위한 절차가 아니라, 이미 승인된 U0/U1을 새 실행 방식에 정확히 연결하는 검토다.

- `nohup`/`setsid` 등 실제 지원되는 사용자 프로세스로 구성한다. SSH가 끊겨도 유한 작업이 끝나고 결과가 남도록 stdin을 닫고 출력·오류를 고유 파일로 보존한다. sudo·패키지 설치·기존 cron/systemd 변경은 하지 않는다. 기존 cron 해시와 점검 경로를 유지한다.
- 전역 중복 방지 잠금·고유 작업 ID·PID/실행 상태·단계 종료값·실제 시작/끝·최종 완료 파일·manifest를 둔다. 성공 확정은 마지막 필수 기록까지 성공한 뒤에만 한다. 시작 전 오류면 후속 변경 0, 실행 후 기록 오류면 미완료·원격 상태 미확인으로 남기고 재실행하지 않는다.
- 대기 작업이 필요하면 목표 시각/기한이 명시된 1회 작업으로 하고 무제한 반복하지 않는다. 서버의 검증된 시각으로 날짜와 창을 확인한다. 원문을 점검할 수 없는 시간대 문자열이나 로컬 PC 타이머를 기준으로 삼지 않는다.
- **배포 블록 11개는 452ac384 그대로 유지한다.** 바꿀 부분은 전송/실행 위치와 배치 기록 틀이다. 고정 출처와 추출·해시 검사를 통과한 블록만 서버에서 실행하며, 배치 코드가 임의 명령을 생성하거나 다음 버전으로 이동하지 않는다. 현재 로컬 run.sh를 서버에서 그대로 실행해 자기 자신에게 ssh하는 구조는 쓰지 않는다.
- 11-27 10:00 N03·09:30 장부는 서버가 이미 만드는 보고 원문을 직접 보존·검사하는 경로를 설계한다. 로컬 회수 성공 여부를 서버 배치의 유일한 진입 근거로 삼지 않는다. 기존 보고 생성/발송 cron을 바꾸거나 보고를 재생성하지 않는다. 실제 보고 정상·설치 핀·매매/정산 이상 판정은 기존 계약을 유지하고, 단순 파일 존재나 초록 이모지만으로 통과시키지 않는다. 필요한 원문/판정 필드를 검토표에 연결한다.

## 4. 운영 서버의 시험 경계

실자금 주문이 없어도 운영 서버는 기존 모의 세션·보고·데이터 수집을 처리한다. 현재 상태와 가용 자원을 확인하기 전에 대규모 회귀·Docker 빌드·추가 PG를 무제한 병행하지 않는다. 향후 필요한 통합 시험은 운영 DB가 아닌 격리 DB/컨테이너, 실제 계좌 인증 없는 환경으로 범위를 정한다. 이번에는 이미 통과한 제품 시험을 서버에서 다시 돌리는 일보다 서버 차이·배치 지속성 확인을 우선한다.
