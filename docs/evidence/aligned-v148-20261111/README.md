### W4: CLOSING을 미정산 보유로 노출한 방식

- **보유 조회** `getOpenPositions`
  - OPEN과 CLOSING을 함께 돌려주고, 상태 값은 그대로 둡니다. OPEN의 뜻은 바꾸지 않았습니다.
  - 화면용 응답은 `unrealizedPnl=null`, `valuationStatus=평가 불가`입니다.
  - 마지막 기록값은 "기록 시각 미상, 현재 평가 아님" 표시와 함께 따로 줍니다.
  - 결정한 사유와 판단 시각도 줍니다.
- **성과 요약**
  - 대기가 있는 세션과 전체에서 미실현·총손익·수익률을 0으로 메우지 않고 null로 둡니다.
  - `pendingCloseCount`와 `valuationStatus`를 함께 줍니다.
  - CLOSING은 완료 거래에 넣지 않습니다.
- **정지 응답·일괄 정지 응답·정지 알림**
  - 대기가 있으면 "최종 자산"으로 표시하지 않습니다.

## 2. V96과 V95 번호 충돌

- **파일:** `V96__paper_aligned_runtime_state.sql`
  - `position.exit_decided_at TIMESTAMPTZ`와 `virtual_balance.mdd_peak_krw NUMERIC(20,2)`를 추가합니다.

  - 과거 판단 시각·미실현 고점은 추정해 넣지 않습니다.
  - 키 없는 세션(종전 PAPER·사전 등록 66)은 코드가 두 열을 읽지도 쓰지도 않습니다.
- **번호를 V96으로 정한 이유:**
  - 운영은 V94까지 적용돼 있습니다. main에는 미배포 `V95__paper_session_slippage.sql`이 있습니다.
  - 후보는 V95를 덮어쓰지도, 슬리피지 기능을 가져오지도 않았습니다. 그래서 겹치지 않는 V96을 썼습니다.
- **최종 통합 때 정할 순서**(총괄 결정, 지금은 제안만):
  - (a) V95 슬리피지를 함께 또는 먼저 내보내면 V95 → V96 순서로 그대로 맞습니다.
  - (b) V95를 내보내지 않으면 V96만 적용되고 95는 빈 번호로 남습니다. 그 뒤 V95를 적용하면 Flyway 순서 위반(outOfOrder 꺼짐)이므로, 그때 슬리피지 파일을 V97 이상으로 옮겨야 합니다. 아직 어디에도 적용되지 않은 파일이라 옮겨도 이미 적용된 SQL을 바꾸는 일이 아닙니다.
- **H2 시험 스키마:** `schema-h2.sql`에 같은 두 열을 `IF NOT EXISTS`로 더했습니다.
- **PostgreSQL 확인은 하지 못했습니다.** 로컬 Docker 데몬이 꺼져 있었습니다(`failed to connect to the docker API`). Docker를 임의로 켜지 않았습니다. 남은 항목 §5를 보십시오.
