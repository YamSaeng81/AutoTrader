### R6-1. 연결 주문의 소유도 금액 범위에 묶는다

r5는 대상 포지션을 LIVE#203으로 제한했지만 POS 안의 BUY/SELL/정산 불일치 하위 조회는 `position_id = p.id`만 쓴다. 다른 세션이나 종류의 주문이 그 포지션을 가리키면 그 주문의 수량·원가가 합계에 섞인다. 합성 예로 정상 매수20개/원가10,005원에 LIVE#204의매수20개/원가90,000원을 같은 position_id로 연결하면 매수 원천 합계는40개/100,005원이 된다. 잔량 불일치로 원가 배분이 막혀도 이미 외부 금액이 원천 열에 들어간다. **정적 SQL 반례이며 운영 발생이나 PG 재현 결과가 아니다.**

새 사본에서 관련 주문의 종류/세션 소유까지 제한한다. 또는 같은 스냅숏의 **금액 절 전 소유 연결 관문**으로 이런 연결을 완전히 거절한다. 다른 소유 행을 빼서 정상 원가로 확정하지 말고 소유 불일치를 금액 없는 사유/개수로 남긴다. 소유 없는 옛 행을 임의 귀속하거나 운영 DB를 고치지 않는다.

검증은 **이 새 합성 연결 사례 한 개의 보완 전/후 비교만**, 네트워크 없는 격리 로컬 PG 한 묶음에서 허용한다. 다른 세션/종류 연결로 구판의 범위 밖 원천 혼입을 확인하고 보완판은 그 금액을 반출하지 않으며 정상 원가로 확정하지 않아야 한다. 기존4사례·제품 PG·회귀는 반복하지 않는다.
