# 총괄 v1.259 — 승인된 공식 점검 구간 반영 뒤 동일 한도 시험

사용자는 운동 중에도 운영 대리인이 권고 방향으로 진행하고 필요한 운영 반영을 하도록 승인했다. 앞서 제시한 공식 점검 구간1행 등록 승인을 포함해 적용했다. 기존 SSH 키만 사용하고 대화에 들어온 비밀번호는 명령/파일/기록에 넣지 않았다. 사용자 즉시 응답을 전제로 하지 않고 대리인이 관측하며 서버 자체 종료를 유지한다. 원금/누적 매수+수수료1만원 한도·1회 제한·SID203/APENFT 분리 조건을 그대로 지킨다.

## 이미 반영한 것

고정 register-window.sql(2988eba0)로 공식11-09 KST02~07 구간을 기존 표에1행 등록했다. ID2, UPBIT/ALL_MARKETS, UTC11-08 17~22, 공식 URL·Seoul 원문 시간대·확인자/시각을 기록했으며 SQL rc0·stderr0B다. 등록 전 운영 SHA/이미지/기동 시각·비가동 REAL·V96/체크섬·중복/겹침을 확인했다. 가격·잔고·위험 한도·스키마·설치본·SSH/cron은 변경하지 않았다.

## 새 사전 관문

실제 LIVE에 주입되는 MarketDataCacheRepository의 market_data_cache를 검사한다. 기존 작업 사본/변수명 혼용으로 candle_data를 진단한 오류와 그에 따른15행 불필요 수집은 v1.258 정정에 남긴다. 이번에는 그 경로/일일수집 변경·재빌드를 하지 않는다.

- 최신 완료 H1·최근500시간480개 이상 조건을 유지한다.
- 등록된 정확한 ID2 공식 구간에 완전히 포함되는 결측만 계산에서 제외하며 점검 밖 미해명 결측은 허용2칸 그대로다.
- 실제 runtime 결측 재조회 로그는12:12:55에 해당5칸이 거래소에도 없었다고 기록했다. 공개 GET(14:19)도 동일5칸 부재였다. 이 부재 기록을 가진 같은 backend StartedAt(12:10:38.948)을 사전 관문에서 고정 확인한다. 다른 인스턴스면 통과시키지 않는다.
- 제품 본래 관문은 여전히 공식 구간+runtime 부재 조회 두 조건을 확인하며, 현재 최신 봉 없음은 예외 없이 차단한다. 새 사전 검사는 이를 대신해 제품 판정을 우회하는 것이 아니다.

순수 사전 관문15경계만 로컬에서 확인한다. 기존 PG·회귀·jar·v3 HTTP/관측기 시험은 입력/원문이 같아 반복하지 않는다. 고정 v3의 P0/생성/검증/시작, 같은 서버 관측/stop1회·gate v4/잔량 확인을 새 경로 exp3에서 재사용한다. exp1/exp2와 정지된#204는 보존하며 재시작하지 않는다. 새 세션은 실제 생성 후 ID를 기록한다.

실매수 정산 또는20분 기한에 정지하며 자연 신호가 없으면 매수 없이 종료한다. 신호를 강제하거나 위험 한도를 늘리지 않는다. 공식 공백 등록은 공통 엔진에 영향을 주므로 개입 시각 이후 데이터를 구분하고, 66세션 상태가 바뀌었는지는 필요한 상태 확인만 한다. 등록 자체를 수익성·실체결·12월 최종 S 완료로 쓰지 않는다.
