2026-11-16. 대상은 ce6df2fa에서 실행한 U2와 [현재 로컬 실행 근거](../v172run-20261116/)다. 실행 근거는 아직 미커밋이며, 이번 검토 시점의 파일 해시는 checks.json에 기록한다. 총괄은 운영 서버에 접속하지 않았다.

## 1. 판정

**1안인 확인 보정 경로를 채택한다.** U2는 rc1로 남기고, backend는 이미 새판으로 기동된 상태로 기록한다. 현재 원문에서 V96 적용 실패나 P0를 뒷받침하는 근거는 없다. 이 확인식 오류만을 이유로 되돌리지 않는다. 새로운 안전 이상은 별도로 판단한다.

실제 진단 행은 `96:true:-424836241`이다. ce6df2fa의 U2는 같은 SELECT 결과를 `96:t:-424836241`과 비교한다. 대역의 docker 응답도 같은 잘못된 `t`를 돌려준다. 총괄의 앞 검토도 이 DB 응답 계약 차이를 놓쳤다. 진단의 개별 boolean 열 `t` 표시와 SQL 문자열 연결 결과 `true`를 구분한다.

현재 확인된 상태는 **HEAD0e1d2a02·backend 이미지2c5d8427·Flyway96**이다. backend StartedAt은 **14:16:14.129686133 KST**, U2의 배포 기준 기록은 **14:16:12 KST**다. 두 시각을 원문대로 구분한다. frontend는 구판이고, 완전한 릴리스 반영 판정·F 핀 갱신·새 모의 세션 생성은 후속 확인 뒤다.

## 2. 지금 준비할 보정 — 추가 착수 질문 없이 진행

1. U0~U2 출력·원격 종료값·원래12블록 해시·14:17/14:22 읽기·DB 진단을 먼저 보존한다. 최초 진단 SQL의 따옴표 오류도 실패 이력으로 남긴다. 원래 U2 rc1과 과거 대역 원문을 수정하지 않는다.
2. U2 교정 사본은 동일 SQL의 기대값 한 곳을 **`96:true:$V96SUM`**으로 바꾼다. 이번 기동에 U2 전체를 다시 실행하지 않는다. 실제 이력 출력과 직접 연결되는 표현을 쓰고, 허용값을 `t 또는 true`로 넓히지 않는다.
3. 이번 시도를 마무리하는 별도 **`U2확인` 블록**을 만든다. 기존 F·G·U변수와 `UB=V172D4`, `~/maint-v172`를 유지한다. 이후 U3·UF2·U4·뒤 관측은 ce6df2fa 원문과 해시를 그대로 쓴다. 새 판 표지로 바꿔 기존 단계 기록과 섞지 않는다.
4. U2확인은 **기동 로그 확보·P0 검사부터** 하고, 현재 HEAD/추적 변경, 실행 backend와 U1의 새 이미지 대응, 실행 frontend와 U0의 구판 대응, SID203·66세션, 공유 풀 등록값, V96 최고 버전과 정확한 성공·체크섬 한 행, 다른4서비스 불변을 다시 확인한다. U1 통과·기존 배포 시각·미완료 U2를 전제로 하며, 복구나 frontend 교체가 이미 시작된 상태에서는 멈춘다.
5. 검사가 모두 통과하면 U2의 미실행 꼬리인 서비스 대조·git 기록을 완성하고 **마지막에만 `ok-U2`를 기록**한다. 새 출력은 별도 이름으로 남긴다. 원래 배포 시각·StartedAt·실패 출력은 보존한다. 확인 블록에는 재빌드·재기동·tag·checkout·DDL·DB 쓰기를 넣지 않는다. 조건 검사 없이 표지만 만드는 명령을 쓰지 않는다.
6. 가짜 DB의 응답을 실제 `96:true:` 형식으로 고친다. 로컬 PostgreSQL에서 같은 SELECT 표현식을 한 번 대조하고, 좁은 대역에서 정상·false·체크섬 다름·0행/복수행·조회 실패·서비스/이미지 불일치·P0/로그 실패가 표지 생성 전에 멈추는지 확인한다. SQL은 실제 출력, 대역은 제어 흐름의 근거로 구분한다.
7. **보정 블록·해시·실행 틀·관련 검증을 새 커밋에 고정해 제출한다.** 총괄은 이 좁은 보정 출처를 검토한 뒤 U2확인 실행과 기존 U3 이후의 재개를 판정한다. 제품 전체 회귀·PG 전체 묶음·jar/이미지 빌드·전체 배포 대역은 반복하지 않는다.

보정 준비 중에는 기존 승인된 읽기 범위에서 기동 뒤 로그의 P0·누수·한도·새 ERROR와 실제 상태를 확인할 수 있다. 실제 읽은 시각과 범위만 기록하고, 세션이 확인하지 않은 시간을 감시했다고 쓰지 않는다. 새 안전 이상이 보이면 영향받는 운영 진행을 중단하고 원문을 보고한다.

## 3. 보정 출처 수용 뒤의 순서
