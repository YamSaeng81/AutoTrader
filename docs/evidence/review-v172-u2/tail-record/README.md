# U2확인 준비 중 추가 검토 — 꼬리 기록과 NULL 혼합 입력

2026-11-16, v1.174 후속 메모다. 개발의 2회차 대역은 진행 중이며 최종 결과나 고정 출처를 수용한 기록이 아니다. 총괄은 진행 중인 대역·블록·서버를 변경하지 않고 로컬 준비본을 읽었다.

## 1. 원래 꼬리 이름 완성은 허용 범위다

현재 U2확인 준비본 해시는 **844e5c0c18e6ac25977b85c108ed6d0f8237443ef06c9b46ff10b7c56e6c5ab5**다. U4 원문은 `svc-deploy.txt`의 backend 행을 현재 상태와 대조한다. v1.174 §2-5도 원래 U2의 미실행 꼬리인 서비스 대조·git 기록 완성을 요구한다.

따라서 `svc-u2c-<시각>.txt`·`git-u2c-<시각>.txt`에 이번 검증 결과를 보존하고, 시작과 쓰기 직전에 원래 두 파일이 없음을 확인한 뒤 같은 바이트로 채우는 것은 지시 범위다. 복사와 바이트 대조가 끝난 뒤 마지막에만 ok-U2를 쓴다. 원래 시각의 기록으로 소급해 표현하지 않고 U2확인이 꼬리를 완성했음을 기록한다.

실행 중 블록을 바꾼 1회차는 혼합된 진단 실행으로 보존한다. 2회차는 고정된 블록·장치·사례를 써서 원문을 보존한다. 이후 보완이 필요하면 현재 실행을 고친 결과로 합산하지 말고 별도 실행과 해시로 구분한다.

## 2. 로컬 PG 음성 입력을 한 가지 추가한다

현재 PG 출력은 단독 checksum NULL 입력을 거절한다. 그러나 `string_agg`는 NULL 입력을 제외한다. 정상 V96 한 행과 checksum NULL인 다른 V95 이후 행이 함께 있으면, 문자열 결합 결과에서 추가 행이 빠져 `96:true:-424836241`만 남을 수 있다. 이는 코드와 문서에서 도출한 관찰이며 이번 총괄 세션이 PostgreSQL에서 재현한 결과는 아니다. [PostgreSQL 15 집계 함수](https://www.postgresql.org/docs/15/functions-aggregate.html)

현재 대역을 완료·보존한 뒤 같은 실제 PG 구동기로 **정상 V96 + checksum NULL인 추가 V95 행**을 확인한다. 필요한 경우 NULL인 추가 V96 행도 같은 범위에서 확인한다. 재현되면 U2확인 한 곳에서 **`count(*)`와 이력 내용을 같은 SELECT로 반환해 행수1·정확한 성공/체크섬을 함께 요구**한다. 별도 SELECT 두 개로 스냅샷을 나누지 않는다. U2-교정 사본은 기존 한 줄 형식 교정의 근거로 유지한다.

이 보완과 관련 PG·대역 입력 추가는 별도 착수 질문 없이 진행할 수 있다. 제품 코드·위험 정책·기존 단계 블록은 이번 범위에 포함하지 않는다. 바뀐 U2확인의 해시·실행기13해시·실제 SQL 출력·관련 사례·고정 커밋을 제출하면 최종 출처 검토를 한다.
