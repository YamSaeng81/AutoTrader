# 12월 준비 30 — 실제 읽기 수집 구간·시계 축·원천 연결 계약 초안 (총괄 v1.207 §3-2) — 실행 전 초안, 운영 실행 금지

2026-11-20 KST, 개발 세션 제출(총괄 판정 전). [읽기 출처 표](../dec-read-source-20261120/README.md) §1에서 "시각" 행은 **미확정**으로 남아 있었다. 이 문서는 그 미확정 부분을 실행 전 계약 초안으로 채운다. 기존 SQL 9818db54·파서 0f6fe827의 바이트는 바꾸지 않았고, 새 SQL도 실행하지 않았다. 이 초안은 실행 승인이 아니다. 새 SQL/계좌 읽기·SSH 변경은 별도 승인이 필요하다.

## 1. 수집 순서와 실패 시 중단 위치

각 호출은 새 폴더에 보존하고, 폴더가 이미 있으면 시작하지 않는다(출처 표 "호출별 보존"). 단계 번호는 P7 관측 `meta.steps`의 `{step, start, end}` 구간 형식에 그대로 대응한다.

| 순서 | 할 일 | 남기는 것 | 실패 시 |
|---|---|---|---|
| C0 | 등록표 파일 sha256 계산. kind별 ID 배열 `live_ids`·`dyn_ids` 생성 | `registry.json`·`vars.txt` | 등록표 없음·비어 있음·형식 오류 → **여기서 중단**. psql을 부르지 않는다 |
| C1 | 수집기 벽시계 `c_start`와 단조 시계 `m_start`를 기록 | `clock.json`(수집기 축) | 기록 실패 → 중단 |
| C2 | psql 1회 호출(`-X -q -v ON_ERROR_STOP=1`). 호출 직전·직후에 수집기 벽시계·단조 시계를 기록(`c0,m0` / `c1,m1`) | `stdout.tsv`·`stderr.txt`·`psql_rc.txt`·`clock.json` 추가 | psql rc≠0 → 파서 **20**. 금액 변환·계좌 판정으로 **넘기지 않는다** |
| C3 | 수집기 벽시계 `c_end`, 단조 시계 `m_end` 기록 | `clock.json` 마감 | 단조 시계 경과와 벽시계 경과의 차이가 허용치를 넘으면 그 회차의 시계 관계를 쓰지 않는다(값은 보존하고 축 관계는 미확정) |
| C4 | 원문·종료값 보존, sha256 기록 | `SHA256SUMS` | 해시 기록 실패 → 다음 단계 금지 |
| C5 | 파서 v3 실행 | `parsed.json`·`parse_rc.txt`·`parse_stderr.txt` | 10 STOP(금액 열람 없음) → 금액 단계 없이 종료. 30 형식/게이트 불일치 → 종료. 0이어도 아래 C6 조건을 따로 확인 |
| C6 | P7 관측 묶음 조립 → P7 → F3 v9, 성적표 원천 입력 | P7 출력·F3 출력 | 이 단계 입력이 없는 값은 미확정으로 둔다(§3). F3 불통과는 그대로 기록한다 |

STOP·psql 실패·파서 30에서는 금액 변환·계좌 판정·성적표 계산을 시작하지 않는다. 파서 0이나 GO는 "2단계까지 읽었다"는 뜻일 뿐이다. 관측 안정·계좌 일치·월말 확정으로 올려 보지 않는다.

## 2. 시계 축과 증거의 출처

| 축 | 이번 읽기에서 오는 값 | 성격 | 정확한 스냅숏·월 경계 시각으로 쓰는가 |
|---|---|---|---|
| db | META 3열 `now()` | 트랜잭션 시작 시각. 첫 문장에서 스냅숏이 고정되므로 스냅숏과 가깝지만 같다는 증거는 없다 | **아니다** |
| db | META 4열 `clock_timestamp()` | META 문장이 실행되는 동안 읽은 DB 벽시계 표본 1개 | **아니다**. 표본 1개로만 쓴다 |
| db | END 행 시각 | 트랜잭션 끝 근처의 DB 표본 | 아니다 |
| collector | C1~C3의 `c_start`, `c0`, `c1`, `c_end`, 단조 `m_*` | 수집기 벽시계·단조 시계 | 아니다. 스냅숏을 **감싸는 구간**의 경계로만 쓴다 |
| app | 세션·주문 `created_at`(앱 `Instant.now()`) | 앱이 쓴 행 시각. 이번 읽기에는 앱 시계 표본이 없다 | 아니다 |
| exchange | 거래소 주문 생성 시각·완료 조회 기간 | 이번 DB 읽기에는 들어 있지 않다. 거래소 조회는 별도 승인 단계 | 아니다 |

- **스냅숏을 감싸는 구간**: collector 축 `[c0, c1]`이다. psql 호출 전후이므로 스냅숏 고정 시점은 이 안에 있다. db 축으로는 `[now(), END]`이 같은 스냅숏 트랜잭션을 감싼다.
- **db↔collector 관계**: P7 v5의 `samples` 규칙을 그대로 쓴다. 표본 `{pair:['db','collector'], c0, d=clock_timestamp(), c1, mono_rtt_ms}`에서 (db − collector) ∈ [d − c1, d − c0]이다. 이 표본은 C2의 psql 왕복 하나라서 연결 수립 시간까지 포함되므로 범위가 넓다. 범위가 월 경계를 걸치면 그 비교는 `CLOCK_AXIS_UNCONFIRMED`로 보류한다. 평균이나 단일 상수 오프셋은 쓰지 않는다.
- **app·exchange 축**: 이번 수집에는 증거가 없다. app↔db, exchange↔collector 관계는 **미확정**이다. 같은 물리 시계라는 `same_source` 선언은 운영 근거(예: 앱·DB가 같은 호스트의 같은 시계를 쓴다는 출처)가 있을 때만 적는다. 합성 P0의 선언을 기본값으로 복사하지 않는다.
- 월 경계 T 시점에 관측이 있었다는 확정은 이 읽기만으로 하지 않는다. T가 `[c0, c1]` 구간 밖이면 그 관측은 T 시점 관측이 아니다. 구간 안이어도 스냅숏의 정확한 시각은 미확정으로 둔다.

## 3. 원천 열 → 소비 필드 연결표

| 원천(파일·열) | 소비처 필드 | 축 | 없을 때 |
|---|---|---|---|
| 등록표 sha256 (C0) = META 8열 | 파서 `registry_sha256` → P7 등록표 대조 | — | 불일치·없음 → 파서 30, 진행 안 함 |
| `live_ids`·`dyn_ids` (C0) = META 9·10열 | 파서 kind/ID 재계산 | — | 불일치 → 30 |
| META `now()` | 파서 `observed_at` → P7 관측 db 추출 시각 | db | 없으면 형식 결함 30 |
| META `clock_timestamp()` + C2 `c0,c1,m0,m1` | P7 `meta.clock.samples` 1개 | db↔collector | 수집기 시각이 없으면 표본 없음 → 축 관계 미확정(보류) |
| META `pg_current_snapshot()` | 파서 `snapshot` (보존·대조용) | — | 30 |
| META flyway 최대 판 | 파서 `flyway_version` | — | 30 |
| C1~C3 수집기 시각 | P7 `meta.steps` `{step, start, end}` | collector | 없으면 관측 안정 미확인 → F3 불통과 |
| 2단계 주문·포지션 행 | P7 `db`, 성적표 원천 | app(행 시각) | STOP이면 비어 있음. 0으로 채우지 않는다 |
| 앱 코드 SHA | P7 `meta.app_code_sha`·`_ref` → F3 `code` | — | 이 읽기에는 없음 → 별도 출처 필요, 없으면 F3 불통과 |
| 거래소 계좌·주문 | P7 `exchange_before/after`·`done_query` | exchange | 이 읽기에는 없음 → `exchange_coverage` 미확정, F3 불통과 |
| 등록 자본·미배정 현금·`cash_base` | P7 `account_sum` | 등록표 선언 축 | 등록표에 없으면 미확정. 추정값·합성 값으로 채우지 않는다 |
| `ruleset.confirmed` | P7 규칙 지문 | — | 없으면 `RULESET_UNCONFIRMED` 보류 |

따라서 이번 DB 읽기 하나만으로는 F3를 통과할 수 없다. 거래소·코드 출처·자본 등록이 함께 있어야 한다. 이것은 의도된 동작이다.

## 4. 이번에 정하지 않은 것

- psql 왕복 하나보다 좁은 db 표본(예: 같은 연결 안에서 문장 전후로 잰 표본)은 새 SQL이 필요하다. 이번에는 SQL 바이트를 바꾸지 않았다.
- 단조/벽시계 차이 허용치의 수치는 P7의 `MONO_TOL`을 따른다. 운영 실측값은 없다.
- 실제 등록 ID·자본·미배정 현금은 추정하지 않았다.
