## 2. 보완 ([scorecard.py](scorecard/scorecard.py), 출력 `scorecard-3`)

- **수수료·매수 대금 귀속**: 정산 시각을 모르는 매수(또는 매도)가 있으면 그 수수료와 매수 대금의 월 귀속을 모른다. 이때 `fees_paid`·`buy_funds`는 `null`로 내고, 알려진 부분 합(`fees_known_part`·`buy_funds_known_part`), `fees_status=미확정`, 사유 목록을 따로 낸다. 시각이 모두 확정이면 지금처럼 확정 합을 낸다. 월 밖으로 확정된 매수는 미확정이 아니라 0으로 귀속한다.
- **시각 모순**: 같은 거래의 매도 정산 시각이 매수 정산 시각보다 앞서면(엄격히 작으면) 계약 위반(rc2)으로 거절한다. 매도가 여러 건이면 각각 대조한다. 같은 시각은 허용한다(보유 0시간). 시각 미상은 순서를 추정하지 않는다(거절 없음·보유시간 없음).
- v2의 비용 뒤 월손익, 앞 네 보완(S1~S4), 입력 계약은 그대로다. 월손익은 기초·기말 평가로 계산하므로, 매수 시각을 몰라도 `month_pnl`은 확정으로 남는다(V1 단언).

## 4. 월 귀속 출처안 — 누적 주문 행과 체결/정정 이벤트

현재 0e1d2a02 저장소(Git 원문 기준, 운영 조회 없음)가 가진 시각:

| 출처 | 시각 | 값 | 한계 |
|---|---|---|---|
| `order` 한 행(누적) | `filled_at`(처음 체결로 확인한 시각, 한 번만 씀) · `sell_applied_at`(매도가 포지션·잔액에 처음 반영된 시각, 한 번만) · `reported_observed_at` | `reported_*`/`applied_*` = **최종 누적** 체결 대금·수수료(정정 때 덮어씀) | 부분 체결 단계별·정정별 시각과 값이 없다. 최종 누적값을 최초 시각에 전부 붙이면, 뒤 달의 정정이 앞 달 값을 조용히 바꾼다 |
| `order_settlement_discrepancy` | `detected_at` | 감소·역행(FEE/FUNDS/VOLUME_DECREASE·STATE_REGRESS)만 이전/수신 값 | 정상 증가 정정은 남지 않는다 |
| `dynamic_sell_settlement` | `settled_at` | DYNAMIC 매도 확정 1건당 순대금·실현 | DYNAMIC만, 확정 시점 값(뒤 정정 반영 안 됨) |
| 앱 로그 | 정정 로그 줄("매수 정산 정정 → 포지션", 매도 정정) | 차분 | 보존 기간·회전에 달림. 성적표 원천으로 고정되지 않음 |

예시(가상): 11-30 23:50에 매도 10개 체결·반영, 12-01 00:10에 같은 주문 잔량 5개 체결, 12-03에 수수료 +0.01 정정.
- 이벤트로 귀속하면 11월 = 10개분 대금·수수료, 12월 = 5개분 + 정정 차분 0.01이다.
- 현재 행만으로는 `sell_applied_at` 11-30과 최종 누적 15개분밖에 없다. 그래서 15개분과 정정분이 모두 11월로 간다. 이미 낸 11월 성적표를 다시 계산하면 값이 바뀐다.

제안:
1. 월 성적표는 행의 최초 시각(`sell_applied_at`, 매수는 `filled_at`)으로 귀속하되, 정정이 있었는지 알 수 없으면 그 행을 "정정 귀속 미확정"으로 표시한다. 최종 누적을 최초 시각에 붙여 과거 월을 확정 값처럼 바꾸지 않는다.
2. 월을 넘긴 부분 체결·정정을 확정 귀속하려면 체결/정정 이벤트(시각·차분)가 필요하다. 현재 확보 가능한 것은 위 표뿐이다. 새 DDL·수집기는 착수하지 않았다(지시).
3. 실제 12월 이력에서 정정이 없으면(정정 로그 0·discrepancy 0) 1번 귀속이 이벤트 귀속과 같다. 이 확인은 승인된 읽기 범위가 정해진 뒤 한다.

입력 변환(DB → `scorecard-input-2`)은 아직 없다. 실제 월 평가 사용은 출처 연결과 함께 판단한다.
