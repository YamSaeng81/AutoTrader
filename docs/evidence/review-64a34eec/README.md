2026-11-24 KST. 64a34eec의 체크섬을 커밋 블롭으로 대조했다: 진단 134/134·U0 초안 29/29·설계 2/2, 합계 **165/165** 일치. 격리 PG 원 회차의 변형 실패 1건은 그대로 두고 보존 출력의 보충 결과와 구분해 수용한다. 기존 PG·회귀·빌드는 다시 실행하지 않는다.

총괄 검증은 로컬 Git·원문·차이와 새 실행기 bash -n 종료 0이다. 총괄이 실제/가짜 SSH·DB·계좌·제품 시험을 실행한 것은 아니다.

## 1. KNOWN은 진단 분류로만 수용

SQL의 KNOWN은 DYNAMIC P·n_any·not q_any·REAL·과거 기간·A 중복 없음이다. **주문 0과 exit_reason NULL을 요구하지 않는다.** 예를 들어 확정 체결은 없지만 미확정 BUY 행이 있는 과거 포지션도 들어올 수 있다. 따라서 직전 9건과 같은 모양인지조차 이 분류만으로 확정하지 않는다. 이름을 “알려진 동일 행”으로 읽지 않는다.

이번 SQL은 전체 R1·만료·실행 상태를 읽는 **진단**으로 수용한다. KNOWN을 동일 행 증거나 무거래 확정, 과거값 보정, 배포 통과 근거로 자동 소비하지 않는다. OTHER/NEW가 0이어도 모든 삽입·수정·삭제가 없었다는 의미는 아니다.

EXP는 엄격히 뒤인 다음 분을 출력하도록 보완됐다. 이 값은 DB 시계 기준 재확인 계획에 쓰되, 해당 시각이 됐다는 사실만으로 R1=0을 확정하지 않는다. 이후 실제 재확인 승인과 새 관측이 필요하다. 임의의 몇 초 여유를 붙여 앱/DB 시계 축 관계가 입증됐다고 쓰지 않는다.

## 3. 읽기 뒤 바로 이어갈 로컬 작업

### 3-1. 유지보수 U0 — 다음 두 공백 보완

KNOWN을 이번 9개의 대리 증거로 채택하지 않는다. 필요하면 새 분류에서 **주문 없음·exit_reason NULL·REAL·기간·P/NO_SOURCE**를 명시적으로 요구하되, 그래도 동일 행 증거가 아니라는 한계를 유지한다. 새/불명 분기는 중단한다. 배포 예외는 제품의 진입 차단을 그대로 유지하는 **정지 상태 유지보수**로만 판단한다. 과거 원가·무거래 판정 자체는 바꾸지 않는다. 이번 읽기 결과를 보고 이 제한을 만족할 수 있는 최소안을 정리한다.

U0-maint의 `echo ... | tee "$M/r1-gate.txt"` 및 판정 결과 기록/표시도 필수 기록이다. 현재 원문은 그 기록 실패를 모두 검사하지 않아 성공 표지까지 갈 여지가 있다. **r1-gate 필수 기록 실패 → ok-U0 없음 → U1 금지**로 고친 새 사본을 만든다. pf3ok 0 경로와 유지보수 예외 경로 모두 확인한다. 조회·형태·기록 실패를 비용 미확정으로 취급하지 않는다.

파일 대역은 정상 예외 1건, r1-gate 쓰기 실패 1건, 출력 기록 실패 1건, 새/불명 R1 분기 1건만 추가한다. 실제 SSH·생산 별칭·PATH 치환은 사용하지 않고 판정/기록 부분만 실행한다. 기존 10건은 반복하지 않는다. 실제 PG에서 예외 통과 경로는 미확인으로 남겨도 되며, 새 SQL이 필요하면 정확한 차이와 최소 검증 범위를 먼저 제출한다. 새 PG를 이번 지시에서 추가 승인하지 않는다.

**이 보정안·유지보수 배포는 아직 실행 출처로 채택하지 않는다.** U0/U1/U2 고정 출처와 새 창은 읽기 결과/보정 원문 검토 뒤 정한다. U2 사용자 최종 확인은 유지한다.

### 3-2. 매수 1회 제한 — V97은 아직 채택하지 않음

한 번의 체결 확인 시험 때문에 바로 스키마를 바꿀 필요가 있는지 먼저 비교한다. **제한 없는 기존 세션 지문을 유지하는 것과, 제한 있는 새 세션의 지문에 제약을 반영하는 것은 양립한다.** 매매 거동을 바꾸는 maxEntries를 지문에서 무조건 빼는 안은 RulesetRegistry의 계약과 맞지 않는다.

설계 표에 다음 두 안만 비교하고 최소안을 권고한다. 아직 구현/제품 시험은 하지 않는다.

- 현재 제안한 선택 열+카운터 방식: V97·기존 V96 배포/복구 영향, 카운터 하한/NULL/초과 DB 제약, 중간 롤백/보상·의도 커밋/철회·기존 세션 기본값, 제한 있는 세션만 지문 추가를 명시한다.
- **스키마 없는 선택 옵션+기존 BUY 의도 이력 방식:** 옵션이 없으면 기존 동작·지문 유지, 있으면 새 세션의 지문에 포함한다. 계좌/세션 잠금 안에서 수명 전체의 이미 커밋된 BUY 의도를 세어 매도 후·재기동·UNKNOWN/철회 후 새 예약을 거절할 수 있는지 확인한다. 주문 행 삭제/초기화·모든 제출 우회 경로·동시성·옵션 변경 불가·대상 세션 한정 검증을 다룬다. strategy_params와 청산 해석기가 추가 키를 안전하게 처리하는지도 확인한다. 이것이 불가능하면 이유를 쓰고 억지로 채택하지 않는다.

정지 경합은 알려진 한계다. 잠금 안에서 RUNNING을 한 번 더 읽는 것만으로는 stop이 같은 잠금을 사용하지 않는 경합까지 해결됐다고 하지 않는다. 1회 제한과 “정지 뒤 제출 없음”은 별개다. 불필요한 범위 확장 없이 최소 시험 계약을 선택한다. 금액/수수료 상한과 실제 계좌 여유는 별도 관문으로 남긴다.

1만원 실주문은 선택적 인수 시험이며, 이 설계가 커진다는 이유로 기존 D81 비용 보호 배포를 V97과 묶지 않는다. 지금은 구현·생성·start·실주문을 하지 않는다.

## 4. 예약·작업 흐름
