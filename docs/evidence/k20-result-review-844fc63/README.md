## 설명 정정과 후속 범위

“실패가 이제 ERROR가 아니라 WARN”이라는 제출 설명은 정정한다. 네 출처의 catch ERROR 호출은 이전 ea44900과 b1d7664에서 동일하다. Connection reset이 발생하면 기존 ERROR가 남는다. HTTP비200은 이전에도 WARN이었으며, N11은 상위 수집기의 실패/부분 결과 WARN을 추가했다. CryptoPanic403 두 회는 이 경로의 실제 관측이다. 22시 ERROR 수 감소만으로 회복을 확정하지 않는다.

CryptoPanic의 HTTP 비200 로그는 기존에도 응답 본문 전체를, UpbitNotice는 앞120자를 기록한다. 전자는 이번 운영 로그의 HTML 첫 줄과 개발의 다중 행 관측이 있고, 두 호출은 고정 소스에서 확인했다. 특정 비밀이 유출됐다고 판정한 것은 아니다. N12는 이 두 HTTP 로그의 본문을 제거하는 최소 로컬 후보로 분리했다. 기존 catch ERROR/분류·결과 계약·상위 로그·시도 시각/간격·캐시·DB/요청 설정은 보존한다. 실제 출처에 강제 재시도하거나403을 우회하지 않는다. 자세한 지시·완료 조건은 계획 v1.90 §58에 있다.
