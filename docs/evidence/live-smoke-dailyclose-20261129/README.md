# 총괄 v1.260 — 일봉 마감 시각에 맞춘 유한 시험 1회

사용자의 운영 대리인 위임·필요한 운영 반영·누적 매수대금과 매수수수료 합계1만원 시험 승인을 적용한다. 자금/전략을 늘리지 않고, 실제 전략이 평가하는 시각에 한 번만 시험한다. 기존#204·#205는 각각 매수0·정상 정지로 예산 사용0원이며 다시 시작하지 않는다.

## 실행 조건과 범위

- 목표: **2026-11-29 09:03 KST**, 시작 허용은09:03 이상09:08 미만이다. 늦게 재접속했다고 즉시 실행하거나 다음날로 이월하지 않는다.
- 기한:09:23 KST. 자연 매수 정산 또는 기한에 정지1회·청산/정산·gate v4 PASS·거래소 BTC잔량0을 확인한다. 신호가 SELL/HOLD면 주문 없이 종료할 수 있다. 매수를 강제로 만들거나 전략/위험 한도를 바꾸지 않는다.
- 새 LIVE1개만 생성, DAILY_SMA20/KRW-BTC/H1·원금10,000·비율0.995·상한9,950·손절5·시간청산0·maxEntries 정수1. SID203은 CREATED 유지, APENFT는 기존 별도 보유로 유지한다.
- 첫 두 실제 세션#204·#205의 COMPLETE·STOPPED·gate PASS·BUY0 원문을 시작 전에 재확인한다. 새 사전 읽기에서 핀·같은 backend 인스턴스·공식 점검 구간·최신 입력·정확한 계좌 여유·수수료·활성/보유/배정을 재확인한다. 하나라도 실패하면 생성/시작하지 않는다.
- 서버 전용 폴더 `~/work-batches/live-smoke-20261129-dailyclose`의 독립 사용자 프로세스다. 운영 Git·제품·이미지·cron·SSH 설정·스키마는 바꾸지 않는다. PC/Claude 세션과 무관하게 진행하지만 서버 재부팅 뒤 자동 재개는 하지 않는다. `CANCEL` 파일이 있거나 시계 이동>2초·이미 지난 창·출처/기존 결과 불일치면 시작하지 않는다.
- 생성/시작/정지 POST와 불명 응답은 재시도하지 않는다. 주문 1회 제한·서버 종료 관측기는 앞 시험과 동일 원문이다. 총괄이 중복 실행하지 않고 서버 작업 하나만 실행 주체로 둔다.

## 출처와 확인

driver.py는 c24deed8의 날짜 검사 표현 한 곳만11-29로 바꿨다. runtime 부재 증거의 backend StartedAt(11-28)은 그대로다. preflight.py·observer.py는 c24deed8과 바이트가 같다. safe_api.py·smoke.sh·kst.py는 fecf3b90의 v3, gate/checker는 기존 v4를 그대로 패키징한다. scheduler.py는 네트워크/주문 명령 없이 지정 시각에 이 driver를 한 번 실행한다.

새 일정 경계6/6을 파일 시험으로 확인했다. 기존 PG·회귀·jar·HTTP·관측기 시험을 반복하지 않는다. 최초 준비는 날짜 문자열 전체 개수 가정이 틀려 복사/외부 호출 전에 중단됐다. 정확한 승인 날짜 표현1곳만 바꾸는 것으로 정정했으며 인스턴스 핀은 바뀌지 않았다.

지금의 준비/예약은 실체결 성공 또는12월 최종 S 완료가 아니다. DYNAMIC은 병행 등록표·감시/계좌 대조·최종 구성 확정 뒤 별도 시작하며, frontend 개선은12월 초기 안정화 뒤 기존 FD15/FE 목록으로 진행한다. 사용자에게 노출된 비밀번호는 파일/명령에 사용하지 않고 기존 SSH 키만 쓴다.
