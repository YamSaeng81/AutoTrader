2026-11-24 KST, Claude Code 로컬 작업이다. **운영 호출·주문·계좌 조회는 0회다.** 이 문서는 실행안이고 실행 원문이 아니다. 총괄이 1회 실행 창·원문·금액을 확정하기 전에는 아무것도 실행하지 않는다. U2 직전 사용자 확인은 그대로 남는다.

## 0. 선행 조건 — 하나라도 아니면 시험하지 않는다

1. d81c3f2f 배포와 U2 이후 인수 확인을 통과한다. 운영 0e1d2a02에는 비용 보호 보완이 없으므로 그 위에서는 시험하지 않는다.
2. **R1 = 0(LIVE·DYNAMIC 모두)이다.** d81에서 DYNAMIC R1>0이면 이 시험 세션의 매수도 거절된다. 지금 상태로는 9건이 자연 만료되는 시각(상한 12-01 13:49 KST)이 시험이 가능한 가장 이른 시각이다. [R1 조사](../r1-closure-audit-20261124/README.md) §4의 r1-diag-3 EXP로 정확한 시각을 정한다.
3. 실제 계좌 여유가 기존 배정(SID203 20,200원)과 이 시험 10,000원을 함께 감당한다(A3). 지금은 보류 상태다. 이 조건을 닫지 않고 "충분하다"고 쓰지 않는다.
4. 알림 수신자와 대응자를 지정하고, 실제 수신을 확인할 사람을 정한다.

## 2. 한도 — 누적 매수대금 + 매수 수수료 ≤ 10,000원을 보장하는 방법

**생성 요청 본문(제안):**

```json
{"strategyType":"DAILY_SMA20","coinPair":"KRW-BTC","timeframe":"H1",
 "initialCapital":10000,"investRatio":0.995,"maxInvestment":9950,
 "stopLossPct":5.0,"maxHoldHours":0,"strategyParams":{}}
```

- 매수 요청액은 `min(가용 10,000 × 0.995, 9,950)`을 둘째 자리에서 버린 **9,950원**이다(1556~1565). 시장가 매수라 체결대금은 9,950원 이하다. 수수료는 0.05%로 4.975원 이하다. 둘을 합해도 **9,954.98원 이하**다. 최소 주문 5,000원을 넘으므로 금액을 늘릴 필요가 없다.
- 위 세 값은 세션 생성 때 저장된다. 시험 중에는 바꾸지 않는다. 생성 응답과 DB에서 `initial_capital=10000`, `invest_ratio=0.995`, `max_investment=9950`인지 확인한다.
- **재진입 차단은 설정으로 할 수 없다.** 매도가 정산되면 가용액이 약 9,9xx원으로 돌아와 5,000원을 넘는다. 그러면 다음 신호에 두 번째 매수가 나간다. 그래서 **매수가 체결·정산된 것을 확인하면 바로 `stop`을 부른다.** 정지는 다음 순서로 진행한다.
  1. 활성 주문을 취소한다.
  2. 보유분을 `FORCED_STOP` 시장가 매도로 넘긴다(`markClosingWithSellIntent`).
  3. 세션이 STOPPED가 된다.
  이렇게 하면 매수는 최대 1회다. 정지 뒤에는 평가가 멈춘다. 열린 포지션이 있을 때 추가 매수를 막는 규칙은 이번에 따로 확인하지 않았으므로, 매수 정산을 확인하면 다음 H1 평가 전에 정지를 부른다. 한계도 있다. 정지 전에 실시간 손절(5%)이 먼저 매도할 수 있다. 그때도 정지를 바로 부르면 재매수는 없다.
- 미사용 현금은 세션 배정일 뿐이다. 이체하지 않는다. 계좌에 남은 돈은 손대지 않는다. STOPPED 뒤에 배정이 풀리는지는 사후 읽기로 확인하며, 확인 전에는 풀렸다고 쓰지 않는다.
- 매도 수수료는 매도대금에서 빠진다. 시험 비용에 포함해 보고한다.

**알려진 한계:** 매도는 전략 신호가 아니라 정지 경로(FORCED_STOP)로 한다. 그래서 자연 매도(신호·익절·손절) 경로는 이 시험으로 확인되지 않는다. 대신 FORCED_STOP은 성과 집계에서 빠지므로 전략 성과를 왜곡하지 않는다. 손실은 LIVE 30일 손실 합에는 들어간다.

## 3. 실행 순서와 읽기

| 단계 | 내용 | 허용 출력 | 멈춤 조건 |
|---|---|---|---|
| P0 사전 | 설치 핀, Flyway, R1(LIVE·DYNAMIC), RUNNING 세션 목록, SID203 행 불변, 활성 주문·미해결 제출·정리 대기 0, 공유 풀 등록 로그, 계좌 KRW 여유(A3 계약 범위) | 상태·개수. 계좌는 승인된 금액 칸만 | 어느 하나라도 기대와 다르면 생성하지 않는다 |
| C 생성 | `POST /sessions` 1회 | 응답의 id·status=CREATED·저장값 | 오류면 재시도하지 않고 보고한다 |
| S 시작 | `POST /sessions/{id}/start` 1회 | status=RUNNING | 시작이 거절되면 보고 |
| W 대기 | 승인된 창 안에서 자연 신호를 기다린다. 확인 간격은 총괄이 정한다 | 그 세션의 주문·포지션 상태만 | 창이 끝났는데 매수가 없으면 S2(정지)로 가서 **미실행**으로 끝낸다 |
| B 매수 뒤 | 주문 FILLED, applied_executed_funds·applied_paid_fee, 포지션 size>0, 세션 가용액 감소 = 체결대금+수수료, 알림 | 그 세션의 주문 1건·포지션 1건의 값 | P0·UNKNOWN·접수 불명·정산 불명·잔액 불일치·기록 실패 |
| S2 정지 | `POST /sessions/{id}/stop` 1회 | status=STOPPED | — |
| X 매도 뒤 | SELL FILLED·sell_applied_at·대금·수수료, 포지션 CLOSED/FORCED_STOP, 미해결 제출 0, 정리 대기 0, 활성 주문 0, 계좌 증감, 알림 전송·실제 수신 | 그 세션의 값 | **STOPPED만으로 완료 처리하지 않는다.** 실제 주문·잔량·예약·정리 대기까지 확인한다 |

- 접수가 불명이면 **다시 제출하지 않는다.** 제품의 주문 조회·취소·정산 확인 경로가 처리하는지 지켜본다. 사람이 하는 조치는 그 결과를 보고 정한다.
- 부분 체결 뒤 취소, 또는 매도 잔량이 최소 주문액에 못 미치면 추가 주문을 내지 않는다. 잔량과 처리안을 먼저 보고한다. 정지 경로는 잔량을 정리 대기로 등록한다.
- 실행자는 Claude 단독이다. 결과 폴더는 `docs/evidence/live-smoke-run-<날짜>-<HHMM>/`로 하고 실행 전에 비어 있어야 한다. 호출 횟수는 C 1회, S 1회, S2 1회, 그리고 P0·B·X 읽기다. 읽기 횟수는 총괄이 정한다. 자동 재시도는 없다.

## 4. 증거로 남길 것

- 주문 식별자 연결: 주문 id ↔ 거래소 uuid ↔ 포지션 id ↔ 세션 id
- 매수·매도 각각의 체결량, 체결대금, 수수료
- 세션 가용액과 계좌 KRW·BTC의 증감
- 알림: 전송 기록과 실제 수신 여부(수신은 사람이 확인)
- 최종 상태
- 확정 손익(양쪽 대금·수수료가 정산된 값)과 평가·미확정을 나눠 적는다
- 시험 총비용 = 매수대금 + 매수 수수료 − (매도대금 − 매도 수수료)

## 5. 총괄이 정할 것

1. 전략 안 A/B와 대기 창(안 A는 신호가 드물어 며칠까지 기다릴지)
2. 실행 시점: R1 만료 뒤(EXP)이면서 d81 인수 뒤. 12-01 본운영 시작과 같은 날이면 순서를 정해야 한다
3. P0 계좌 여유 읽기의 범위(A3와 같은 계약을 쓸지)
4. 사전·사후 읽기 원문과 횟수

기존 한도와 시스템만으로는 매수 1회를 자동으로 보장하지 못한다. 이 안은 **매수 정산 직후 사람이 정지를 부르는 것**에 기대고 있다. 이를 자동으로 바꾸려면 제품 변경이 필요하다(예: 세션별 "매수 1회 후 정지" 옵션). 이번에는 제안하지 않는다.
