# 추가 정정 메모 — G1의 두 값 구분 (2026-11-13, 총괄 v1.166 §1 반영)

원문 [README](README.md)·[SHA256SUMS](SHA256SUMS)·`runs/`와 앞 메모 [CORRECTION-20261113-g1](CORRECTION-20261113-g1.md)는 수정하지 않았다. 판정 근거는 [총괄 v1.166](../review-6f27b35d/README.md) §1이다.

앞 메모의 첫 항목은 `INTENT_READY`와 `dispatching=false`를 함께 "낡은 읽기"라고 적었다. 두 값은 성격이 다르다.

- **낡게 읽힌 것은 저장소 엔티티의 상태 `INTENT_READY`(주문번호 null)뿐이다.** 정지 트랜잭션의 영속성 컨텍스트에 claim 전에 올라간 엔티티를 그대로 돌려줬다. 같은 순간의 독립 JDBC 읽기는 `SUBMITTED`였다.
- **`dispatching=false`는 캐시된 값이 아니다.** 등록부(`isDispatching`)를 그 시점에 실제로 읽은 값이며, claim 종료 뒤 `claimOwned`의 `finally`가 정상적으로 해제한 결과다(G1 근거 §2 표 +0.132).
- 따라서 "캐시된 `INTENT_READY` + 등록부 없음 = 제출 유실"이라는 종전 추정은 철회한다. 폴러 회복은 인위적으로 만든 미제출 의도에 대한 직접 호출 근거이며, 실제 G1 주문이 폴러로 회복된 것은 아니다. G2·G3·G4는 남는다.
