# DYNAMIC 감시·선택·매매 흐름의 PAPER/REAL 차이 (야간 D)

2026-11-10 · 개발 제출 · 총괄 v1.144 D · 기준 소스 `b5cd1d0`(후보 브랜치에서는 DynamicTradingService를 바꾸지 않았다)

**고정 코인 SMA20 비교(B·C)를 통과했다고 DYNAMIC이 검증됐다고 쓰지 않는다.** 아래는 소스 읽기와 실행 재현 1건의 결과다.

## 같은 것 — 한 틱 경로를 PAPER와 REAL이 함께 쓴다

`processTick` → `processScanningTick` / `processMonitoringTick` 하나를 두 종류가 같이 쓴다. `isPaper` 분기는 체결과 집계에만 있다. 이것은 기존 `DynamicPaperLiveRuleParityTest`가 소스 허용 목록으로 지킨다.

같은 항목:
- 세션 서킷 브레이커(틱 시작)
- 워치리스트: 세션별 갱신 또는 공용 유니버스
- 닫힌 봉 평가, 전략 평가
- EMA200 관문(여유·감액), RANGE 관문
- BLACK_SWAN 3단계(차단·감액)와 쿨다운
- 캔들 최신성 `freshCandles` · BTC 판정 불가 진입 차단 `blocksEntry`
- WF 관문
- 손실 쿨다운
- 세션 간 동일 코인 노출 상한
- 최고 강도 후보 1개 선택 `pickBestBuyCandidate`
- 실시간 손절·익절 감시(WS)
- SL 미점검 경보

DYNAMIC 전체(두 종류 같음)와 고정 코인 엔진의 차이는 PAPER/REAL 차이가 아니라서 따로 적는다.
- 캔들 출처: `MarketDataSyncService.fetchWithCache`(캐시 + 부족분 거래소 수집). LIVE·PAPER는 캐시 테이블만 읽는다.
- 전략 SELL 청산은 기본으로 꺼져 있다(`trading.strategy-signal-exit.enabled=false`).
- 매수금이 최소 주문보다 작으면 최소 주문으로 올린다.

## 실행 재현 — #8 BLACK_SWAN 쿨다운 공유

후보 브랜치 `3f6afb90`의 시험 `DynamicBlackSwanCooldownCrossKindTest`. 운영 호출부 `processTick`을 그대로 쓰고, 매번 BUY를 내는 시험 전략 하나를 두 세션에 같이 쓴다. 외부 호출은 0이다.

| 단계 | 관측 |
|---|---|
| PAPER 틱: 마지막 마감 봉 −10% | `BUY / 차단=BLACK_SWAN_GUARD 발동 — 1시간 내 딥 급락 -10.00% ≤ -8.0%`. 전역 지도에 KRW-XRP가 기록됨 |
| 이어서 REAL 틱: 회복 캔들 | `BUY / 차단=BLACK_SWAN 쿨다운 — 0분 전 차단된 종목 (해제까지 240분)` |
| 대조: PAPER 틱 없이 같은 REAL 틱 | `BUY`, 차단 없음 |

- **PAPER 활동이 REAL 진입 판단을 바꾼다.**
  - 같은 급락을 REAL이 직접 평가했다면 REAL도 막혔을 것이다.
  - 그러나 REAL이 그 시각에 그 코인의 BUY를 평가하지 않은 경우가 있다. 워치리스트가 다르거나, 전략이 다르거나, 보유 중이었던 경우다. 이때는 PAPER가 연 쿨다운이 240분, 진입가 가드는 1,440분까지 REAL을 막는다.
  - 반대로 REAL의 기록도 PAPER를 막는다. 이 방향은 PAPER 표본을 REAL에 맞춰 준다.
- 이것을 결함으로 판정해 고칠지는 총괄의 결정이다. 고치는 방법 두 가지 모두 진입 계약을 바꾼다.
  - 쿨다운을 종류별로 나눈다.
  - 또는 시장 상태로 보고 기동 복원에도 PAPER 로그를 넣는다.
- 이번에는 고치지 않았다.
- 실행 이력(`run1~3/`):
  - 1회차: 캔들 공급 목이 빠져 로그가 없었다.
  - 2회차: 입력 추세가 완만해 EMA200 관문이 먼저 막았다.
  - 3회차: 입력 기울기만 고쳐 2/2. 기대는 바꾸지 않았다.

## 아직 재현하지 않은 것

- #3 회차 승인 차이는 고정 코인에서 같은 `EntryPriorityRounds`로 재현했다(B·C의 S04·A04). DYNAMIC 공유 풀 경로 자체는 기존 `EntryPriorityEndToEndTest`가 지킨다. PAPER/REAL 쌍으로 재현하지는 않았다.
- #4 풀 거절: 고정 코인 S09b와 같은 예약 경계다. DYNAMIC 쌍 재현은 하지 않았다.
- #9 기동 복원 비대칭은 소스로만 확인했다. 재기동 재현은 하지 않았다.
