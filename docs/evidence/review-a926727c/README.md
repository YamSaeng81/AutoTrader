# 총괄 v1.209 — 458차 부분 묶음 조립기 검토

2026-11-20 KST. **수집 계약 보충과 파일 입력만 사용하는 조립 방향, 보존된 7경계 결과를 수용한다. 조립기 최종 수용은 기록 확정 결함 1건을 보완한 뒤 판정한다.** 출처는 **a926727cbf0c7acc9007450a0dcbad315ae171d6**이며 HEAD와 저장 origin/main이 같다. 원격에는 새로 접속하지 않았다. [파일 대조](checks.json) 16조건을 확인했고 목록3개 고유108파일의 커밋 블롭·작업 파일이 모두 일치한다. 16조건에는 아래 결함의 재현도 포함되므로 결함0을 뜻하지 않는다. 제품·PG·psql·운영·기존 시험 묶음은 실행하지 않았다.

## 1. 수용한 범위

- [계약 보충](../dec-collect-contract-supp-20261120/README.md)은 P7 5단계와 C0~C6, `db_extract` 표본의 필수 키, 단일 표본의 외삽 금지, 단조/벽시계 검사를 반영했다. SQL9818db54·파서0f6fe827은 커밋에서도 수용 바이트 그대로다.
- [조립기](../dec-collect-assembler-20261120/README.md) **7717c6671de76d8a93ac0697e1d490152f7cb0f9628746687fb08cfc3985b1bf**의 외부 명령은 고정 파서의 파일 처리뿐이다. psql·SSH·계좌 호출은 없다. 정상 원문은 보존 A_V3와 같고, 실패/STOP 때 계산을 진행하지 않으며 P7/F3/계좌·월말 확정 표시도 모두 false다.
- 보존된 7/7은 각 결과·원문 해시·묶음 해시·차단 표시로 연결한다. 합성 시계 표본의 형식 통과를 운영 측정으로 보지 않는다. 기존 PG 결과는 **3PASS/1FAIL + 별도 정상 원천 보충 비교**를 유지한다. F3 v9·성적표·P7·제품d81c3f2f·D81 출처cd8bd76f의 기존 수용은 바뀌지 않는다.

## 2. F1 — 체크섬 기록 실패 뒤 성공 묶음이 남음

`finish(0)`은 먼저 `bundle.json`에 `rc:0`, `downstream:db_part_only`를 쓰고 나중에 `SHA256SUMS`를 쓴다. 총괄이 **체크섬 쓰기 한 곳만 PermissionError로 주입**하자 반환값은42였지만, 남은 bundle은 여전히0·db_part_only였다. 체크섬 파일은 없었다. [주입 결과](write-failure.json)와 [남은 묶음](sha-write-failure/bundle.json)을 보존했다. 실제 디스크 고갈이나 운영 실행을 한 것은 아니다.

따라서 “0 이외는 downstream:blocked”라는 제출 계약이 마무리 기록 실패에서는 성립하지 않는다. 호출자가 종료42를 지키면 중단되지만, 파일만 이어 읽는 쪽이 성공으로 오인할 수 있다. 새 매매 제품 결함은 아니며 **이 조립기를 다음 단계 입력으로 사용하는 것은 보완 전까지 보류**한다. 원문 보존·기존 7건을 실패로 바꾸지는 않는다.

## 3. 다음 작업 — 이 경계만 보완

1. **새 사본에서 기록 확정 순서만 고친다.** 최종 성공 묶음/완료 표지는 필수 원문·파서 결과·해시 기록이 모두 확정된 뒤에만 유효하게 보이도록 한다. 임시 파일·미완료 표지·마지막 확정 방식 중 최소 방식을 택하고, 소비 조건을 명시한다. 쓰기 실패 때 실패 사유를 다시 쓰는 것만으로 안전을 보장하지 않는다(그 쓰기도 실패할 수 있다). 실패 경로에 성공으로 소비 가능한 파일을 남기지 않고 종료42와 미완료 흔적을 유지한다. 기존 출력 경로를 자동 삭제하거나 다시 사용하지 않는다.
2. **직접 영향만 확인한다.** 옛7717c667의 위 실패는 본 총괄 근거에 연결하고 반복하지 않는다. 새 사본에서 정상 대조1건, 체크섬 쓰기 실패1건, 선택한 마지막 확정 단계 실패1건만 새 경로로 확인한다. 두 실패 모두 다음 단계가 파일을 직접 읽어도 거절되는지 확인한다. 기존7건 전체·PG·제품 회귀·빌드는 반복하지 않는다. SQL·파서·P7/F3·제품 원천은 바꾸지 않는다.
3. **첫 실행 미보존을 정확히 적는다.** 현재 제출의 첫4/7은 README 경위만 있고, 삭제 후 다시 쓴 run1에는 최종7/7만 남는다. 첫 회차의 사례/콘솔 원문을 보존했다고 쓰지 말고 재구성·재실행으로 대신하지 않는다. 이후에는 호출 전 고유 경로를 정하고 실패 회차를 삭제·덮어쓰지 않는다. 본 총괄 폴더와 새 보완·관리 문서3개를 기존 범위에서 커밋·일반 푸시하고 블롭을 대조한다. 권한 설정·캐시는 제외한다.
4. 이 기록 경계가 닫히면 추가 수집 기능을 계속 늘리지 말고 실제 읽기에 필요한 미확정 원천·승인 항목만 인계한다. 마지막 운영 읽기는11-20 10:31:28/32 시작·보존 서버 시각37초다. 다음 N03은11-20 22:00 보고를22:12 이후 기존 고정 범위로 회수하며 이미 읽었으면 반복하지 않는다. 18:00 이후에는 다음 날08:00까지 승인된 독립 작업을 이어 가고 세션 공백은 미관측으로 남긴다. 새 SQL/계좌 읽기·배포·토큰/POST·생성/T0·실자금 시작·SSH 변경은 별도 승인 전이다.
