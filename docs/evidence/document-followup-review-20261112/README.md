# 문서 추가 점검 — 2026-11-12

**판정: 현재 관리 문서의 대규모 재분리는 필요하지 않다. 추출 경로와 진행 상태의 최신성 보완이 먼저다.** 운영 서버·DB·Gradle·진행 중인 회귀에는 접근하지 않았다. 로컬 문서 목록·제목·참조와 필요한 절만 확인했으며, 모든 설계 내용의 정확성을 재검증한 것은 아니다.

## 1. 현재 분량과 탐색

점검 전 현재 계획 123줄, PROGRESS 38줄, CURRENT_HANDOFF 28줄, 준비 목록 45줄, 관리표 56줄, 시작 안내 36줄이다. RUNBOOK 600줄과 OPS 209줄은 고정 명령을 포함하므로 길이만을 이유로 다시 쪼개지 않는다. 일상 작업에서 이 파일들의 전체 본문을 함께 읽지 않는다.

시작/관리 문서 14개의 로컬 Markdown 링크 121개를 URL 디코딩 후 확인했으며 경로 누락은 0개다. 이는 링크 대상 존재 검사이며 실행 원문 추출의 성공을 보장하지 않는다.

## 2. 우선 보완 — F5-3 추출 경로

RUNBOOK의 F5-3은 아직 `git show "$SHA":docs/LIMITED_LIVE_TEST_PLAN.md`에서 F3를 꺼낸다. 문서 분리 이후 SHA를 지정하면 현재 계획에 F3가 없으므로 다음과 같다. 원문의 awk 식만 로컬 파일에 적용했으며 나머지 명령은 실행하지 않았다.

| 같은 추출 식의 입력 | 종료값 | 추출 크기 |
|---|---|---|
| 현재 계획 | 0 | **0바이트** |
| RUNBOOK | 0 | 12,376바이트 |

RUNBOOK에서 추출한 F3 SHA256은 `bb86fb397da00523f564a8f02a1960c98bb1ac03887629fe74372990929fa2bb`다. 링크 검사·문법 검사·고정 블록 보존만으로 놓칠 수 있는 문서 이동 후 연결 문제다. 분리 이전 고정 SHA의 옛 계획에는 F3가 남아 있으므로 모든 과거 실행이 실패했다는 뜻은 아니다.

최종 S를 고정하기 전에 F5-3의 출처 경로를 RUNBOOK으로 연결하고, 추출 실패·빈 결과·기대 해시 불일치가 실행 전에 멈추는 것을 새 출처에서 확인한다. 과거 고정 블록은 덮어쓰지 않는다. 이번에는 RUNBOOK 머리와 준비 목록에 미완료 조건만 명시했다.

## 3. 반영한 짧은 안내 보완

- 현재 계획의 인계 링크를 날짜가 고정된 옛 인계에서 CURRENT_HANDOFF로 바꿨다.
- PROGRESS에서 초기 통합 SHA `666619ce`와 후속 회귀 기준 `1eed27d1`을 구분했다. 최종 결과 취합·별도 탐침 보완은 아직 남아 있으며 수용으로 쓰지 않았다.
- 현재 인계에 이 점검 링크를 추가했다. 실행 블록·운영 핀·사전 등록·과거 근거/체크섬은 바꾸지 않았다.
