## 3. 계속 가능한 범위와 제출 시점

- 위 범위의 격리 브랜치 구현, 국소/관련 시험, 하네스 수정, 필요한 로컬 PG, 후보 커밋·push, 근거·문서 main 기록은 추가 착수 확인 없이 진행한다. 네트워크 주문/알림/수집은 대역으로 차단한다. 권한 거부를 우회하지 않는다.
- 승인된 선택은 그대로다: A/B 양쪽 보완된 LIVE_ALIGNED, 4쌍8세션·가상100000·비율0.8·상한20000·24h·42일, 생성은 기존 Bearer API, DYNAMIC 쿨다운 종류별 별도 후보. 이 선택을 다시 질문하며 대기하지 않는다.
- 후보가 안정되면 원래 3개 추가 시험(A12/F 포지션/D 복원)과 새 관련 시험이 어느 SHA에 있는지 추적한다. 배포 후보에 필요한 회귀가 별도 시험 가지에만 남았다면 최종 시험 대상과 연결을 명확히 한다. 전체 회귀는 원인 보완과 통합을 끝낸 최종판에서 필요한 범위로 실행한다.
- 제품 변경 뒤 실제 로컬 jar를 대조하고 변경 경로·고정 SHA·기대 출력·D4 후속판을 함께 갱신한다. 앞 후보 기대값을 그대로 쓰지 않는다. 서버 빌드·checkout·배포·재기동·세션 생성/활성화·설정/cron/장부/DB 쓰기는 **이번에 승인하지 않는다**.
- 실제 결과 단위로 중간 제출하고 작업을 계속한다. 새 실패는 보존하고 다음 독립 작업으로 전환한다. 미승인 제품 변경을 main에 합치지 않으며 총괄 문서/근거는 다음 실제 결과에 함께 넣는다. 확인용 커밋만 따로 만들지 않고 `settings.local.json`은 제외한다.
