## 2. 고정1 단독 대조 경로 — RUNBOOK F3·F3-2·F5-3의 d81 연결

원래 초안 §3은 병행용 P7 v8과 F3 v9 판정기를 비교했다. 그 비교는 **DYNAMIC 병행 단계의 참고로만 남긴다.** 고정1 단독에 쓰는 경로는 [RUNBOOK](../../LIMITED_LIVE_TEST_RUNBOOK.md)의 F1/F3(첫 일봉), F3-2(일상 장부), F5-3(종료 대조)이다. 아래 표는 이 경로가 쓰는 열과 판정이 d81 출처에서 바뀌는지만 본 것이다. 비교 대상은 0e1d2a02..d81c3f2f, 제품 14파일이며 migration은 0이다.

**한계:**
- 출처만 본 결론이다. 실제 d81 운영 행으로 F3·F3-2·F5-3을 실행한 근거는 없다.
- 실제 계좌·장부 대조(F1 `account-f1.json` 기준, 업비트 KRW·BTC)는 시작 전과 시작 뒤에 여전히 필요하다.
- **고정1 단독 시작에 registry-3/P7 완성을 새 필수 조건으로 붙이지 않는다.** DYNAMIC 병행에는 실제 registry-3, P7 전체 관측, 병행 감시가 추가로 필요하다.

원래 초안 §3 끝의 "다음 읽기 제안"은 registry-3 초기값을 목적으로 한 것이었다. 그래서 이 보충에서는 **DYNAMIC 병행 준비용**으로 낮춘다. 고정1 단독에 필요한 계좌 기준은 기존 F1 절차가 만든다.

## 3. 손실 상한 표현 정정

원래 초안 §1의 다음 문장은 철회한다.
- "고정1만으로는 손실 40,000원에 도달할 수 없다"
- "누적 −15,000원선이 먼저 발동한다"

초기자본 20,200원만으로는 둘 중 어느 것도 실행에서 보장되지 않는다. 월초 평가자산, 이전 이익, 순손익과 손실합의 정의가 서로 다르다. 관측 지연과 체결 오차도 있다.

**정정 문구:** 고정1은 예산 20,200원과 기존의 더 엄격한 중단 조건을 유지한다. 월 손실의 측정·담당과 실제 작동은 별도로 확인하기 전이다.

**자동 작동과 사람 판단 구분:**
- 누적 −15,000원, 24시간 −3,000원, 비용 >0.40%는 [§6-2](../../LIMITED_LIVE_TEST_RUNBOOK.md)에 따라 **운영자가 확인 결과를 보고 판단해 정지하는 조건**이다. 이 선에서 제품이 자동으로 정지한다고 쓰지 않는다.
- 제품 쪽 자동 동작은 다음 두 가지다. 정확한 발동식은 `RiskManagementService`·`risk_config`를 따르며, 이번에 다시 검증하지 않았다.

## 4. 복구 불가(STOP_INCOMPATIBLE) 때의 정지 표현 정정

원래 초안 §2의 "신규 진입은 기존 정지 경로로 막는다"는 철회한다. RUNBOOK §6-2에 **청산 없이 신규 주문만 막는 기능은 없다**고 적혀 있다. 기존 정지(세션 정지·비상 정지)는 아래 세 가지를 **함께** 한다.
- ⓐ 미종결 매수에 취소 요청
- ⓑ 장부 수량이 있는 OPEN 포지션을 시장가 매도
- ⓒ 세션을 STOPPED로 전환

**정정된 대응 틀** — 새 기능은 만들지 않는다:
1. 현재 바이너리(d81)를 유지한다. 행 삭제, NULL 치환, DB 과거 복원은 하지 않는다.
2. 운영을 멈춰야 하면 §6-2 정지를 쓴다. **정지에는 청산이 포함된다**는 점을 결정 전에 명시한다.
3. 불명 주문이 있으면 기존 자동 중복 방어(같은 세션 신규 매수 거절, CLOSING 매도 재전송 없음)를 확인한 뒤, §6-2의 UUID·identifier 조회 순서를 따른다.
4. **STOPPED만으로 완료 판정하지 않는다.** 완료는 활성 주문 0(불명 포함), 정리 대기 0, 업비트 보유와 내부 기록 일치를 모두 확인한 뒤에만 적는다. 거래소에서 먼저 직접 매도하지 않는다.
5. 활성 주문·정리 대기·실보유 대조의 확인 방법, 대응 가능 시간, 담당은 **운영자 기입 빈칸**이다. 호환 바이너리를 쓸지는 미결정이다.
