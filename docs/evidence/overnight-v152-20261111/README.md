이 폴더는 [야간 지시](../../OVERNIGHT_20261111.md)의 작업 큐 결과를 **끝난 단위로** 쌓는다. 각 절은 그 절을 쓴 시점의 사실이다.
운영 배포·서버 빌드/재기동·운영 DDL·실제 모의 세션 생성/시작은 하지 않았다. 운영 서버·운영 DB에 접속하지 않았다(§N03 읽기 제외, 그 절에 따로 적음).

- 기점: main `c4a4d684`, 후보 `candidate/sma20-paper-fwd-aligned2` `19dbad3a`
- 격리 PG: 컨테이너 `v152-pg` (로컬에 이미 있던 `timescale/timescaledb:latest-pg15`, PostgreSQL 15.13, 127.0.0.1:15437, 신뢰 인증). 다른 컨테이너·DB 는 건드리지 않았다.
  - 처음 `postgres:15`(이 작업에서 받음 → 바로 지움)·`postgres:15-alpine`(원래 있던 이미지)으로 띄웠다가 V1 의 `create_hypertable` 이 없어 실패(`s5/pg-run1-failed-no-timescale/`). v1.150 과 같은 timescale 이미지로 바꿨다.
- 진행 상태·재개 지점: [CHECKPOINT.md](CHECKPOINT.md)

## F. 공유 실행기 포화 — 관측 후보 `0298628b`(시험만), 격리 조사 가지 `03cfd9eb`(미승인)

`SharedMarketDataExecutorSaturationTest`: 실제 `marketDataExecutor`(코어2·최대4·대기열100·AbortPolicy, 설정 변경 없음)를 래치로 막고(작업자 4개 실제 실행 신호·대기열 가득), Future.get·실행기 장벽으로 해제·회복을 확인. sleep 없음.

- **① 포화 중 발행 1건: 발행 쪽으로 `TaskRejectedException`.** 스택상 **DYNAMIC `onRealtimePriceEvent`(@Async)가 먼저 호출돼 거절**됐고, 같은 이벤트를 **LIVE 실시간 손절 처리기·PAPER 선택 모드 리스너(거절 +0 = 호출 안 됨)·동기 시세 장부(BTC=null)가 받지 못했다.** (`f-saturation/run4/`)
- ② 해제 → 막은 작업 전부 완료 → 새 시세: 예외 없음, LIVE 수신 회복, 시세 장부 정상.
- ③ 작업자만 바쁨(대기열 여유): 거절 없음, 해제 전에는 LIVE 미처리, 해제 뒤 처리(수신 지연 = 앞선 작업 완료까지).
- 운영 영향 경로(코드 읽기): 웹소켓 틱 `onWsTick` 은 예외가 WS 콜백으로 올라간다. REST 폴백 묶음은 바깥 catch 로 **남은 코인 발행이 중단**되고, 강제 갱신은 실패로 분류된다. 리스너 호출 순서는 등록 순서라 고정 보장이 없다. 운영 b5cd1d0 에도 같은 구조가 있는 기존 위험으로 보이며 운영 발생은 확인하지 않았다(로컬 합성 부하).
- 격리 조사 후보 `candidate/md-executor-reject-isolation` `03cfd9eb`: 크기·대기열 그대로, 거절 시 예외 대신 그 작업만 버리고 누적 건수·경고. 같은 포화에서 발행 예외 없음·시세 장부 수신·버린 @Async 작업 3 (`f-saturation/isolation-candidate/`, 관측 시험·공유 루프 시험 2/2 함께 통과). **실자금 경로의 거절 정책이라 판단이 필요하다** — aligned2 에 합치지 않았다. 버린 작업에는 `ExchangeRecoveredEvent` 같은 다른 @Async 이벤트도 포함될 수 있다(현재도 같은 조건에서 예외로 잃는다).
