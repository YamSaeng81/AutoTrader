# 프로젝트 작업 시작 안내

**현재 상태의 기준은 [현재 계획](LIMITED_LIVE_TEST_PLAN.md)이다.** 이 안내와 현재 계획을 먼저 읽고, 맡은 작업에 필요한 문서만 추가로 연다. 관리 문서·설계서·이력을 일괄 첨부하거나 처음부터 끝까지 읽지 않는다.

## 현재 문서의 역할

| 질문 | 한 곳에서 확인 |
|---|---|
| 무엇이 운영 중이고 무엇을 해야 하나 | [현재 계획](LIMITED_LIVE_TEST_PLAN.md) |
| 18:00 이후 아침까지 어떻게 이어 가나 | [현재 계획](LIMITED_LIVE_TEST_PLAN.md) §2의 야간 작업 원칙 |
| 방금 한 작업은 제출인가 수용인가 | [최근 결과](PROGRESS.md) |
| 다른 세션에서 이어받을 것은 | [현재 인계](CURRENT_HANDOFF.md) |
| 담당·완료 조건·N번호는 | [관리표](NOVEMBER_LIVE_UPGRADE.md) |
| 실거래 시작 조건을 닫았나 | [준비 목록](LIVE_READINESS.md) |
| 어떤 명령을 실행하나 | [F 실행 절차](LIMITED_LIVE_TEST_RUNBOOK.md) / [OPS](OPS_DAILY_CHECK.md)의 해당 블록 |
| 고정 계약·기술 근거가 필요한가 | [상세 색인](README.md)의 해당 파일/절 |

**최신 지시는 [총괄 v1.166 / 412차](evidence/review-6f27b35d/README.md)**다. G1은 시험의 낡은 읽기 문제로 종결했다. 지금은 누락 로그23개·줄바꿈 차이106개의 원문 보존, 6클래스 외부 연결 격리, N15 PG 시각 의존·주문 대역을 보완한다. 시험 전용 최종 SHA에서 전체 회귀1회를 진행한다. 11-16 10:25 KST U0 목표를 유지하며, 원문236/236 블롭 대조 뒤 기존88f06345 / V161D4의 U1 진행을 재개할 수 있다.

## 읽기 범위를 줄이는 방법

1. 현재 계획에서 작업 이름·N번호·고정 SHA·연결된 최신 근거를 찾는다.
2. 문서가 길면 제목/키워드를 검색한 다음 해당 절과 선행 조건만 읽는다. 예: `rg -n '^##|정리 경합' docs/evidence/review-60777286/README.md`.
3. 원문이 필요할 때만 그 결과 폴더의 파일과 체크섬을 연다. 다른 결과의 긴 README/로그까지 자동으로 읽지 않는다.
4. 과거 판단은 `*_ARCHIVE_*`에서 날짜·§번호·SHA로 찾고, 현재 계획의 수용 상태와 대조한다.
5. 명령 실행 때는 요약에서 명령을 재구성하지 않는다. 고정 출처의 필요한 변수·블록·선행 조건을 읽고 원문/해시로 확인한다.

## 문서가 다시 길어지지 않도록

- 현재 계획·관리표·준비 목록은 **각 150줄 안팎**을 목표로 한다. PROGRESS는 최근 **5건 이내**의 짧은 요약과 링크만 둔다. 이는 편집 기준이며 확인에 필요한 계약을 잘라내는 제한이 아니다.
- 한 결과당 상세 설명은 evidence의 README 한 곳에 기록한다. 여러 관리 문서에 같은 판정 전문을 붙이지 않는다.
- 날짜가 붙은 인계는 그 날짜의 이력으로 닫고, 지금 이어받을 내용은 CURRENT_HANDOFF 한 곳만 갱신한다.
- 실행 원문·사전 등록·설계의 안정적인 §번호·과거 체크섬은 보존한다. 긴 참조 문서는 필요한 절만 읽는다.
- 상태와 날짜는 마지막 실제 관측/검토 기준을 밝힌다. 보고가 없거나 세션이 멈춘 동안을 감시했다고 쓰지 않는다.

현재 파일 분류와 보존 위치는 [문서 색인](README.md), 이번 변경의 분량·해시·참조 대조는 [문서 점검 기록](evidence/document-audit-20261112/README.md)에 있다.
