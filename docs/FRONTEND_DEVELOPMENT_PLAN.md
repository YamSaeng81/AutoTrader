# 프런트엔드 후속 개발 — 심플한 디자인과 세션 상세

2026-11-23 사용자 요청: **“좀 더 심플하고, 각 세션 상세에서 보기 편하면서 상세한 데이터가 보이도록 프런트엔드도 개발. 실운영 12월1일 이후에 해도 됨.”** [후속 목록](DEVELOPMENT_BACKLOG.md)의 FD15를 구체화한다. 현재는 계획 등록이며 제품 코드·운영 화면·API를 변경하지 않았다.

**착수 시점은 2026-12-01 이후, 실운영 개시와 초기 안정성을 확인한 뒤 선정한다.** 현재 [v1.229 준비](evidence/review-825d7efd/README.md)와 시작 일정이 우선이다. 날짜가 됐다는 이유로 자동 구현/배포하지 않는다. 다만 실제 금전 지표·위험 행동의 오류가 확인되면 기존 안전 절차로 즉시 보고하며 디자인 후속 일정으로 미루지 않는다.

## 1. 목표와 현재 출발점

- **첫 화면은 빠르게 파악:** 어떤 세션이 어떤 전략으로 돌고 있는지, 무엇을 보유하는지, 손익과 주의할 상태가 무엇인지 알 수 있게 한다.
- **상세는 충분히 탐색:** 주문 하나의 신호·승인/거절·부분 체결·수수료·정산·청산 사유까지 연결해 볼 수 있게 한다. 세부 정보를 없애지 않고 필요할 때 펼쳐 본다.
- **공통 구조, 유형별 정보:** 고정 LIVE·DYNAMIC REAL·모의의 공통 항목은 같은 위치/정의로 표시하고, DYNAMIC 감시 후보처럼 유형별 정보는 별도 영역으로 둔다. 같은 숫자 ID라도 유형을 함께 표시한다.

계획을 위해 현재 소스(80d4e4a3 시점)의 일부만 읽었다. [LIVE 상세](../crypto-trader-frontend/src/app/trading/[sessionId]/page.tsx), [DYNAMIC 상세](../crypto-trader-frontend/src/app/trading/dynamic/[id]/page.tsx), [모의 상세](../crypto-trader-frontend/src/app/paper-trading/[sessionId]/page.tsx)에 차트·손익·주문/거래·전략 로그가 이미 있다. 이를 새로 모두 만드는 과제가 아니라 배치·표현·데이터 정의를 정리하는 과제다. [테마](../crypto-trader-frontend/src/components/layout/ThemeProvider.tsx)·[메뉴](../crypto-trader-frontend/src/components/layout/navConfig.ts)도 기존 구조를 활용한다. 이는 전체 UI 감사나 현재 운영 화면 재확인이 아니다.

## 2. 디자인 원칙

1. **덜 복잡한 화면:** 저채도 기본색, 일관된 여백·글자 크기·숫자 정렬, 얇은 구분선 중심으로 정리한다. 경고·매수/매도·손익처럼 의미가 있을 때 색을 강조하고 색만으로 상태를 구분하지 않는다.
2. **요약 → 상세:** 핵심 요약은 적은 수의 카드로 묶고 나머지는 탭·표·행 펼치기로 제공한다. 같은 숫자와 설명을 여러 카드에 반복하지 않는다.
3. **일관된 표시:** 돈/코인 수량/비율의 단위·자릿수·부호·시각을 통일하고 상세 원값을 확인할 수 있게 한다. 표시 반올림으로 계산 원천을 바꾸지 않는다.
4. **모바일과 테마:** 휴대폰에서도 핵심 요약과 상태를 먼저 읽을 수 있게 하고, 넓은 표는 우선 열/행 상세를 제공한다. 밝은/어두운 테마의 배경·차트·툴팁·표·초점 표시를 함께 확인한다.
5. **명확한 상태:** 불러오는 중·자료 없음·실패·오래된 값·정산 대기·평가 미확정을 구분한다. 조회 실패를 거래0이나 손익0으로 표시하지 않는다. 마지막 갱신/가격 시점을 이해하기 쉽게 표시한다.

## 3. 화면 구성안

적용 범위는 운영 대시보드·세션 목록/상세·계좌·성과·로그·설정이다. 1차는 운영 현황과 세션 목록/상세에 집중하고, 계좌/성과/로그/설정은 공통 디자인과 탐색 규칙을 순차 적용한다. 연구/백테스트와 관리 기능은 목적에 맞게 구분한다.

### 세션 목록

운영 중 세션을 먼저 파악하도록 유형·REAL/PAPER·상태·전략·코인/감시 방식·주기·평가자산·손익·주의 상태를 같은 규칙으로 배치한다. 상태/유형/전략 필터, 검색·정렬과 목록 복귀 시 필터 유지를 제공한다. 기존 상세 URL과 연결은 보존한다. 비교 기능은 열람이 허용된 세션과 기간만 대상으로 한다.

### 세션 상세

| 영역 | 기본으로 보일 내용 | 더 볼 내용 |
|---|---|---|
| 상단 | 유형#ID·모드·상태·전략·코인/감시 방식·주기·갱신 시각 | 시작/종료·평가 기간·운용 버전 |
| 핵심 요약 | 평가자산·비용 반영 손익·실현/미실현 구분·가용/예약/보유 요약 | 각 값의 기준 시점·정의·미확정 사유 |
| **요약 탭** | 성과 추이·보유 현황·최근 거래/주의 사항 | 자산 곡선·낙폭·비교 기준은 원천이 있을 때 표시 |
| **포지션·주문 탭** | 보유/청산 중·미체결·부분 체결·진행 상태 | 주문 요청/체결량·가격·예약/환급·수수료·정산 상태·관련 주문/포지션 |
| **거래 이력 탭** | 왕복별 매수→매도·보유 시간·순손익·청산 사유 | 분할 체결·수수료 정정·실제 실행 비용과 원천 연결 |
| **판단 기록 탭** | 신호·매매하지 않은 이유·필터/위험 차단 사유 | 당시 시장 상황·신호→승인/차단→주문→체결의 타임라인 |
| **설정·위험 탭** | 자본·주문 상한·손절/보호 조건·현재 제한 | 파라미터·규칙 지문·코드 버전 등 재현용 고급 정보 |
| DYNAMIC 추가 영역 | 현재 감시/선택 코인·스캔 상태·보유 코인 이력 | 후보 제외/선택 이유·필터 값·갱신 주기·실제 유효 설정 |

탭명과 카드 수는 시안 단계에서 조정한다. 시작/정지 같은 행동은 조회 정보와 시각적으로 분리한다. 정지에 시장가 청산이 포함되는 현재 계약을 그대로 설명하고 대상 유형/ID·영향을 확인한다. 단순 화면 이동/탭 변경/새로고침으로 주문·시작·정지 요청이 나가지 않아야 한다.

## 4. 데이터는 화면과 함께 계약을 정한다

| 정보 | 후속 연결 | 구현 원칙 |
|---|---|---|
| 현재 상태·포지션·주문·기존 차트/로그 | 기존 API와 조회 hook | 먼저 실제 응답과 표시를 연결한다. 타입/소유 세션·모드·부분 응답을 검증하고 같은 유형#ID로 조회한다 |
| 순손익·수수료·원가·실현/미실현 | FD12 엔진/손익 계약 | 저장 손익·주문 원천 계산·참고 평가를 구분한다. '수수료 차감 후' 같은 문구도 실제 정의로 확인하고 수수료/슬리피지를 이중 차감하지 않는다 |
| 자산 곡선·낙폭·월/24시간 성과 | FD02/FD03 이력과 포착 | 원천·간격·가격/시각 관계가 확보된 범위만 표시한다. 표본 낙폭을 장중 최대 낙폭으로 표시하거나 과거 값을 복원한 것처럼 그리지 않는다 |
| 자본 배정·미배정·공유 계좌 | FD06 등록/계좌 대조 | 계좌 전체와 세션별 값을 구분하고 다른 세션의 금액을 이 세션 성과에 섞지 않는다 |
| 진입/차단·시장 상황·체결 차이 | FD13 판단 자료 | 존재하는 로그로 시작하고 없는 필드는 원천 추가 후보로 표시한다. 사후 가격으로 당시 판단 근거를 채우지 않는다 |

디자인/공통 레이아웃 정리는 모든 새 백엔드 기능을 기다리지 않고 진행할 수 있다. **원천이 없는 지표만 미확정/준비 중으로 남긴다.** 필요한 읽기 API 확장은 허용 열·세션 범위·시점·페이지 처리·권한을 별도 설계한다. 접힌 영역이나 숨긴 열도 불필요한 전체 목록/금액을 미리 가져오지 않는다. 운영 토큰·비밀값·내부 오류 원문은 브라우저에 넘기지 않는다.

| **FE05 사용성·반응성** | 모바일·키보드·글자 확대·명암 대비·로딩/빈/오류/오래된 값, 큰 표의 조회/렌더링 | 주요 조작을 모바일/키보드로 수행 가능. 화면 폭별 넘침과 테마 대비 확인. 필요한 탭/페이지 자료만 읽고 성능 문제는 측정 후 개선 |

작업은 **FE01/02 시안과 데이터 목록 → FE03 한 상세 경로 → 유형별 확장과 필요한 FE04 → FE05/06 확인**으로 진행한다. 전면 교체를 한 번에 묶지 않고 읽기 화면부터 점진적으로 전환한다. 매 묶음에서 소스/도구 버전과 허용된 새 검증 범위를 정한다. 실제 데이터 API를 바꾸면 기존 클라이언트와의 호환성도 확인한다.

## 6. 보호할 범위와 미래 착수 시 필요한 것

- 현재 운영 backend/DB·자본·전략·위험 한도·기존56일 계약을 디자인 변경에 섞지 않는다. 새 의미의 중지 버튼은 FD01 기능과 정책이 먼저 확정돼야 한다.
- 사전등록 비열람 세션 522~587 및 그 성과/신호/포지션은 기존 제한을 유지한다. 화면을 접거나 숨겨 놓고 이미 API로 읽는 방식도 피한다. 시안/자동 검증은 합성 자료와 허용된 세션만 쓴다.
- 현재 운영에 자료를 만들려고 주문·세션 생성·이상 상태를 유도하지 않는다. 청산 중/불명 주문/가격 없음/정산 대기/거래0 등은 우선 대역 데이터로 확인한다.
- 착수 때 확인할 것은 실제 배포 SHA, 우선 적용할 세션 유형, 확정/미확정 필드 목록, 초안 시안과 직접 검증 범위다. 12월1일 이후라는 일정은 운영 조회/배포 승인까지 포함하지 않는다.

다음 후속 작업 선정 때 FD15와 이 문서를 함께 확인한다. 현재는 **사용자 요구·디자인 방향·작업 순서 등록 완료 / 구현 미착수**이며 12월 실운영 준비를 먼저 진행한다.
