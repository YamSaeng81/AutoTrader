## 3. 수익 근거를 만드는 기록과 평가

- **판단 흐름:** 감시 후보 → 제외/선택 사유 → 전략 신호 → 승인/차단 사유 → 주문 접수/거절/불명 → 체결 → 청산 → 잔액/손익을 연결한다. 거래가 없는 이유도 전략 무신호·후보 필터·위험 한도·통신/시세 문제로 나눈다. 기존 기록을 먼저 활용하고 필요한 이벤트만 수집한다.
- **버전:** 세션ID·실제 시작/T0·전략/주기·모드·코인 선정 규칙·자본·코드SHA·규칙 지문을 외부 등록표로 고정한다. 지문이 같아도 전략/코인/모드가 같다는 뜻으로 쓰지 않는다. 전략/설정 변경은 새 구간으로 분리하고 이전 손실을 지우지 않는다.
- **시장 상황:** 매매 판단 시점에 알 수 있던 추세·변동성·유동성/스프레드·BTC 관문 상태를 연결한다. 소수의 분류 기준과 계산 버전을 결과 전에 정하고, 사후 가격을 보고 당시 국면을 고쳐 붙이지 않는다. 엔진/전략/주기/코인/당시 상황별로 비용 뒤 손익·낙폭·표본 수를 보며, 표본이 작은 조합을 최적 전략으로 선정하지 않는다.
- **성과:** 엔진/전략별 비용 뒤 손익·수익률, 실현/미실현, 최대 낙폭, 보유/현금 비중, 완료 왕복 수·보유시간·회전율·손익 분포를 함께 낸다. 계좌 전체 손익도 별도 대조하고 같은 거래를 여러 전략의 독립 근거로 더하지 않는다.
- **월손익:** 기말 평가자산 − 기초 평가자산 − 순입금으로 잔액을 대조한다. 수수료가 이미 잔액에 반영됐으면 두 번 빼지 않는다. 미정산/CLOSING·가격 미확보는0원이 아니라 미확정으로 표시한다. 실제 체결가에 포함된 슬리피지를 손익에서 다시 차감하지 않고 신호가 대비 실행 비용으로 따로 측정한다.
- **비교:** 같은 기간/초기자본의 현금·BTC 보유 비교와 노출 차이를 함께 제시한다. 동적 코인 선택 효과와 전략 신호 효과를 구분하며 미래에 선정된 코인을 과거부터 보유한 것으로 계산하지 않는다. 동일 시세의 대응 모의를 비교할 때 REAL 계좌 관문·체결 차이를 분리한다.
- **전체 결과:** 모든 시작 세션·실패·중단·손실·거래0을 포함한다. 유리한 주/코인/버전만 골라 월 성과로 내지 않는다. 거래 수가 부족하면 양수여도 판정 불가이며 고정된 수익 목표 달성을 위해 재시작/튜닝하지 않는다.

일별은 안전·정산·의사결정 누락을 확인하고, 주별은 새 운용 세션만 비용/낙폭/거래 빈도/차단을 점검한다. 주별 결과로 규칙을 바꾸려면 변경 이유와 새 구간을 먼저 남긴다. 12-31 평가에는 실제 운영일수와 아직 열린 포지션을 적고, 1월 첫 검토에서 지속/중단/추가 연구를 판단한다. 기존56일 시험의 정식 종료 판정은 별도로 유지한다.

향후 전략 선택형 LIVE를 만들 때는 이 자료에서 얻은 선택 규칙을 별도 기간에 검증하고 고정 단일전략 기준선과 비교한다. 선택/전환 비용·충돌 신호·기존 보유 처리·판정 불가 시 행동도 검증 대상이다. 과거 구간에서 가장 잘된 전략을 매번 사후 선택한 성과를 실제 선택 성과로 주장하지 않는다.

수수료율·최소/최대 주문 제약은 실제 시작 시점의 [업비트 주문 가능 정보](https://docs.upbit.com/kr/reference/available-order-information)로 확인할 대상이다. 성과는 비용·시장 상황·비교 기준·유리한 결과만 고르는 문제를 함께 보아야 하며, 한 달의 수익이 향후 수익을 보장하지 않는다. ## 4. 시작과 중단 경계

12-01은 목표이며 각 엔진의 준비 상태를 따로 판정한다. 고정코인만 준비됐다고 다이나믹을 자동으로 켜지 않으며, 한쪽 지연으로 준비된 다른 쪽의 관측을 없애지도 않는다. 단계적 시작은 실제 시각으로 기록한다.

실전 시작 전에는 금액/손실 상한·세션 조건 고정, 새 미해명 안전 이상 없음, 주문/수량/잔액 대조, 시세/BTC 입력, 알림 실제 수신·운영자 정지/복구 대응, 최종 출처/승인을 확인한다. 개발 PC 절전/세션 종료와 무관한 서버 거래·보호·알림 경로를 확인하며 예약 생존만으로 감시했다고 쓰지 않는다. P0·주문 불명·정산 불일치·정해진 손실선은 기존 중단 절차를 따른다.

현재 공유 풀/포지션 상한·SID203·기존66·실행 원문·체크섬·SSH 보안 조사의 경계는 유지한다. PAPER9의11-18 날짜는 만료 보존하고11-19 제안의 실제 승인 기한은12:00이다. 새 DYNAMIC 생성/시작과 금액 확정·한도/설정 변경·SSH 변경·배포는 이 준비 지시만으로 실행하지 않는다. 18:00 이후에는 [현재 계획 §2](LIMITED_LIVE_TEST_PLAN.md#2-지금-진행할-작업)의 다음 날08:00 원칙으로 독립 로컬 준비를 이어 간다.
