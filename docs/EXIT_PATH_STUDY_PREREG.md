## 3. 데이터와 측정

| 항목 | 값 |
|---|---|
| 주 분석 | `position`, `status='CLOSED'`, `session_kind='DYN_PAPER'` — **442건 / 89코인** |
| 기간 | 2026-08-07 ~ 09-20 (**약 6주**) |
| 보조 | LIVE 277건 · DYNAMIC 30건 (`exit_reason` NULL — ④ 불가) |
| 경로 | `candle_data` H1(전 코인) + M15(**330/442 = 74.7%**) |
| 관찰 구간 | `t_in` ~ `t_in + H`, **실제 청산과 무관하게** |

```
entry  = entry_price
목표가 = entry × (1 + a/100)
손절가 = entry × (1 − b/100)

τ_목표 = 처음 목표가에 닿은 시각,  τ_손절 = 처음 손절가에 닿은 시각   (§4 의 판정 순서를 따름)
```

**세 가지 배타적 결과**

| 결과 | 조건 | 체결 가정 | 가격기준 손익 |
|---|---|---|---|
| 목표 선도달 | `τ_목표 < τ_손절 ≤ H` 또는 `τ_목표 ≤ H < τ_손절` | 목표가 정확히 (갭 상향 이득 없음) | `+a − c` |
| 손절 선도달 | `τ_손절 < τ_목표 ≤ H` 또는 `τ_손절 ≤ H < τ_목표` | `min(손절가, 해당 봉 시가)` | `≤ −b − c` |
| 미도달 | 둘 다 H 안에 없음 | `t_in+H` 종가 | `(close−entry)/entry×100 − c` |

`c = 0.30%` (수수료 0.05×2 + 슬리피지 0.1×2, 가격 기준). 스트레스 `c = 0.50%`.

H ∈ {24, 48, 72}             봉(시간)   ← 실제 평균 보유 7~25h 를 감싼다

## 4. 경로 판정 절차 — 순서가 중요하다

### 4.1 시작 봉

🔴 진입 시각이 봉 중간이면 그 봉의 고·저가에는 **진입 전 움직임**이 섞여 있다.
M15 를 써도 진입이 M15 봉 중간이면 같은 문제가 생긴다.

1. 접촉 탐색은 **시작 시각이 `t_in` 이후인 봉**부터 한다 (가용한 가장 짧은 주기: M15 있으면 M15, 없으면 H1)
2. `t_in` 을 포함한 **부분 봉**은 그 부분의 고·저를 알 수 없다. 이 부분 봉의 전체 고·저가 목표가 또는 손절가에 닿았다면 → **시작봉 불명**으로 표시한다 (닿지 않았다면 그 구간은 어느 쪽도 접촉하지 않았음이 확실하므로 그냥 넘어간다)
3. 시작봉 불명은 §4.3 의 양쪽 경계에 포함한다

📝 **v3.2 개정 (2026-09-23, 1차 실행 후)**: 위 2 의 "부분 봉은 통째로 불명" 대신
**그 구간만 M1 으로 세분**한다 — §4.3 이 H1→M15 에 대해 정한 세분 원칙을 한 단계 더 적용한다.

```
진입 후 완전한 M1 봉들 → §4.2 규칙으로 순서대로 판정 (주 창 앞에 이어 붙인다)
진입을 포함한 M1 봉    → 남은 불명 (최대 1분)
```

🔴 **격자·비용·판정 기준은 바꾸지 않는다** — 바뀌는 것은 시작봉의 **해상도**뿐이다.
🔴 **M1 도 완전한 해결이 아니다.** 진입이 분봉 중간이면 그 1분 안의 선후는 여전히 모른다.
더 세밀한 체결 데이터가 없으므로 **남은 불명은 그대로 보고한다.**
⚠️ 업비트가 생략한 무거래 분봉은 체결이 없었다는 뜻이므로 접촉 없음으로 본다.

### 4.2 봉 하나에 대한 판정 순서

각 봉에서 **시가를 먼저** 본다. 갭은 봉 내부 접촉보다 앞선다.

```
1. open ≤ 손절가            → 손절 선도달, 체결 = open        (갭 하향)
2. open ≥ 목표가            → 목표 선도달, 체결 = 목표가      (갭 이득 없음)
3. high ≥ 목표가 AND low ≤ 손절가  → 동시 접촉 → §4.3
4. high ≥ 목표가            → 목표 선도달
5. low  ≤ 손절가            → 손절 선도달
```

1·2 가 한 봉에서 동시에 성립하는 일은 없다(`손절가 < entry < 목표가`).

### 4.3 순서 불명

H1 봉에서 3(동시 접촉)이 나오면:

1. 해당 시각의 **M15 4봉**으로 4.2 를 반복한다 → 대개 해소된다
2. M15 가 없거나(25.3%), M15 한 봉 안에서도 동시 접촉이면 → **순서 불명**
3. 시작봉 불명(§4.1 2)도 같은 범주로 처리한다

결과는 **두 경계로 함께 보고**한다.

| | 순서 불명·시작봉 불명을 |
|---|---|
| **비관 경계** | 전부 손절 선도달로 간주 |
| **낙관 경계** | 전부 목표 선도달로 간주 |

🔴 두 경계가 판정을 가르면 그 칸은 **판정 불가**다. 불명 비율도 칸마다 보고한다.

### 5.1 블록 부트스트랩 — 다일 블록

🔴 H=72 면 **오늘·내일·모레 진입의 관찰 구간이 겹친다.** 일 단위 블록으로는 부족하다.

```
주        3일 블록  (= H_max 72시간)      K ≈ 15
민감도    1일 블록  K ≈ 45   ·   7일 블록  K ≈ 6
B = 2000,  시드 20260923,  진입 시각 기준으로 블록 배정 (동시 진입은 같은 블록)
```

⚠️ **약 6주 자료다.** 3일 블록이면 유효 블록이 15개뿐이고 7일 블록은 6개다.
구간 추정은 **넓고 불안정**하며, 블록이 길수록 더 그렇다. 세 블록 길이의 결과를 나란히 보고하고,
**블록 길이에 따라 부호가 뒤집히면 그 칸은 안정적이지 않다**고 기록한다.

### 5.2 위약 진입

같은 코인·같은 기간에서 무작위 시각에 진입해 같은 (a,b,H) 규칙을 적용한다.
코인별 진입 횟수와 비중첩 규칙은 실제와 동일하게 맞춘다.

### 5.3 🔴 다중비교 — 탐색 절차 전체를 위약에서 반복

인접칸 조건은 **다중비교 보정이 아니다.** 인접칸은 같은 거래 경로를 공유하므로
우연한 양수가 이웃과 함께 나타날 수 있다. 그래서 다음을 **주 우연성 지표**로 삼는다.

```
위약 반복 R = 200 회
각 반복에서 60칸 전체를 계산하고 §5.4 의 후보 선정 절차를 그대로 수행한다
     (부트스트랩 복제 수는 계산량 때문에 위약에서만 B=300 — 본 분석은 B=2000)
     → 후보 발생률 = (후보가 하나 이상 나온 반복 수) / R
```

| 후보 발생률 | 해석 |
|---|---|
| ≤ 0.05 | 실제 탐색에서 나온 후보를 우연으로 보기 어렵다 |
| 0.05 ~ 0.20 | 우연과 구분되지 않는다 → 실제 후보가 있어도 **판단 보류** |
| > 0.20 | 이 탐색 절차 자체가 후보를 쉽게 만들어낸다 → **후보 없음**과 같이 취급 |

### 5.4 판정 — 착수 전 확정

**후보 선정 절차** (위약에서도 동일하게 수행):

> 어떤 칸이 ③ > 0 을 **양쪽 경계 모두**에서 만족하고,
> **세 블록 길이(1·3·7일) 모두에서 비관 경계의 95% 구간 하한 > 0** 이며,
> **a·b 를 한 칸 옮긴 인접칸(4-이웃)도 같은 조건을 만족**하면 → 그 칸은 후보다

📝 **v3.1 정정**: v3 은 "세 블록 길이 모두에서 부호가 유지"라고 썼으나, 블록 길이는
**점추정을 바꾸지 않으므로** 그 문장은 공허하다. 블록 길이가 바꾸는 것은 구간이다.
따라서 **구간 하한**으로 판정한다. 실행 전 정정이며, 위약(§5.3)도 동일한 절차를 쓴다.
7일 블록은 K≈6 이라 하한이 매우 보수적이다 — 이 조건은 **강하다**.

| 결과 | 판단 |
|---|---|
| 후보 0개 | **후보 없음.** 검사한 진입 집합과 청산 격자에 대한 연구를 마무리한다 |
| 후보 ≥ 1개 **이고** 위약 후보 발생률 ≤ 0.05 **이고** ⑥ 위약 대비 양수 | **후보 있음.** 규칙을 고정해 **새 자료**에서 검증한다 |
| 그 외 | **판단 보류** |

## 6. 🔴 결과를 읽을 때

**가설**: 고정 보유기간 검사에서 진입의 방향 우위를 확인하지 못했으므로 전 칸 음수일 수 있다.
그러나 그 결과가 **경로 기반 청산의 기대수익 부재를 증명하지는 않는다.** 이것은 예상이 아니라 가설이며,
결과가 어느 쪽으로 나오든 §5.4 의 **같은 기준으로** 판단한다.

- **양수 칸이 남으면** — 규칙을 고정해 새 자료에서 검증할 이유가 생긴 것이다. 수익 전략을 찾은 것이 아니다.
- **남지 않으면** — 검사한 진입 집합과 청산 격자에 대한 연구를 마무리할 근거다. **프로젝트 전체의 종료를 뜻하지 않는다.**

이 실험 결과로 운영 청산 설정을 바꾸지 않는다.

2. 결과를 보고 격자·비용·블록·판정 기준을 고치지 않는다
3. 고치고 싶어지면 새 사전 등록을 쓴다
4. 운영 DB 는 **읽기 전용**으로만 접근하고, 비밀번호는 `PGPASSWORD` 환경변수로만 받는다
