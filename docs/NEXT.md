## 실전은 언제? — 조건을 정해 뒀다

**날짜가 아니라 조건으로 판단한다.** 아래를 다 채우면 그때 소액으로 시작한다.

| | 조건 | 현재 |
|---|---|---|
| 1 | WF PASS 그룹 n ≥ 30 | 10 |
| 2 | PASS 평균 알파 > 0 | **−1.095** |
| 3 | PASS 알파 > FAIL 알파 | 반대 |
| 4 | DOGE 비중 < 50% (한 코인이 결과를 지배하지 않을 것) | 70% |
| 5 | 상승·하락 국면이 모두 표본에 있을 것 | 하락만 |

**빨라야 3~4주.** 5번 때문에 더 걸릴 수 있다 — 지금 표본은 하락장 한 주가 전부다.

### 조건을 못 채우면?

**전략을 더 만들거나 세션을 늘리는 것은 답이 아니다.** 백테스트가 현실을 못 맞춘다는
뜻이므로, *무엇이 빠졌는지*를 찾아야 한다. 후보는 이미 좁혀져 있다:
체결 지연 · 슬리피지 · 신호 시점과 체결 시점의 괴리.

### 예외 — 체결 오차 측정용 소액 실전은 더 일찍 해도 된다

위 조건은 **"전략에 우위가 있는가"** 를 묻는다. 그런데 그와 별개로
**"페이퍼가 실전을 얼마나 잘 모사하는가"** 는 페이퍼로는 절대 알 수 없다.
체결 지연·부분 체결·실제 슬리피지는 실거래에서만 측정된다.

코드에 `ExecutionDriftTracker`(`execution_drift_log`)가 이미 있고 LIVE 경로에 붙어 있다.
**10만원 정도로 LIVE 1세션**을 열면 그 측정이 시작된다. 목적이 수익이 아니라 계측이므로
조건 1~5 와 무관하게 진행할 수 있다. 다만 지금은 급하지 않다.

## 하지 말 것

- **세션 늘리기** — 같은 조합은 같은 시각에 같이 사고 판다. n은 늘어도 정보는 안 는다.
- **동적 세션 늘리기** — 워치리스트에 검증 불가한 신규 상장이 계속 들어온다.
- **`kill-criteria.auto-stop` 켜기** — 판정 자체가 아직 검증되지 않았다.
- **원수익률로 PASS/FAIL 비교하기** — 두 그룹의 코인 구성이 달라 시장 방향을 재게 된다.
  반드시 알파로 볼 것. `status.sh` 가 그렇게 고쳐져 있다.
