## 2. 진행 원칙 — 한 작업의 판단 대기가 전체 대기가 되지 않게 한다

1. **W1 → W2 → W3 → W4 → W6 순서**로 진행하고 W5의 정해진 읽기 시각에는 전환한다. 먼저 실제 변경 경로와 기존 근거를 확인해 새 공백을 선정한다. 이미 입증한 같은 시험을 성과용으로 반복하지 않는다.

3. 기존 계약 안의 결함은 스스로 좁혀 수정한다. 시험의 상태 공유·대역·시각·인코딩·자료 준비 오류도 원인을 남기고 직접 고친다. 실패 제외, 단언 약화, 임의 sleep/순서 고정으로 통과시키지 않는다.
4. 전략·수익 조건, 신호/만료 시간식, 120초 시세 기준, 호가 깊이, 손실 한도, 시작·종료 정책을 새로 정해야 하면 해당 변경만 보류한다. 재현·대안·영향을 정리하고 다른 작업을 계속한다. 정책을 바꿔야 하는 수정에는 이 일괄 승인을 적용하지 않는다.
5. 후보는 **1899b49에서 격리**한다. main의 미배포 V95·연구·설정 변경을 섞지 않는다. 관련 후보를 통합할 때도 이 운영 기점과 정확한 변경 경로를 다시 확인한다. 후보 수가 늘어날 때마다 jar를 반복 빌드하지 말고 통합 검증을 마친 고정 SHA로 만든다.
6. 각 과제는 검증 가능한 결과를 남긴 뒤 다음 과제로 이어간다. 새로운 결함이 없으면 ‘해당 검토 범위에서 미발견’으로 닫는다. 시간을 채우려고 새 기능·외부 연동·최적화·재시험을 늘리지 않는다.

## 5. W3 — 현재판의 로컬 PostgreSQL 시나리오 리허설

W2에서 고른 영향 경로를 실제 PostgreSQL과 격리 앱에서 한 흐름으로 확인한다. 외부 거래소·운영 계좌·운영 DB를 사용하지 않는다. 기존 전체 리허설과 같은 확인만 하게 되면 중복 실행을 생략하고, 현재판 연결에 필요한 차이만 리허설한다.

1. 운영과 같은 V94 상태를 만든 **로컬 PostgreSQL**을 준비한다. main의 V95를 운영 후보 시험에 끼우지 않는다. 외부 API·시세·주문은 127.0.0.1 대역/주입 객체로 격리하고 실제 URL/토큰을 넣지 않는다. 교체되지 않은 주문/수집 경로가 있으면 실행하지 않는다.
2. CREATED 최초 시작 1회·재시작 차단 → 만료 전/경계/후 진입 → 시세 이상 거절 후 정상 시세 회복 → 매도 접수/대기/늦은 체결·반복 보고 → 정지/정산을 연결한다. 기존 사례를 그대로 반복하지 않고 현재 수정이 닿는 조합을 선정한다.
3. 실제 PostgreSQL 잠금 경합이 필요한 새 공백이 있으면 로컬에서만 검증한다. H2 결과를 PostgreSQL에서 확인한 것으로 바꾸어 쓰지 않는다. 단순한 시계 주입과 실제 잠금 대기를 구분한다.
4. 56일 종료는 시계를 주입해 진행한다. 서버 시각 변경·실제 56일 대기·운영 F2/F6·cron 변경을 하지 않는다. F5-3/장부의 DB 정리·잔액/수량 조건과 주문 호출 수를 대조한다.
5. 실패하면 제품/시험 결함을 나눠 보존하고 수정 후 관련 구간을 다시 검증한다. 의미 없는 반복 실행으로 성공 표본을 고르지 않는다. 로컬에서 통과해도 운영 자연 발생·실제 거래소 체결 관측으로 기록하지 않는다.

완료물: 선정 시나리오와 기존 대비 차이, 실행 전 소스/환경·주문 대역 설정, 실행별 XML/로그·DB 판정, 잔액/수량/주문 수, 한계. 기존 예산을 관리하되 근거 없는 소요 시간을 만들지 않는다.

- 기존 로그에서 HOLD 처리/건수, 장기 대여와 반환, 연결 획득 실패를 원래 시간 범위와 함께 확인한다. 처리 줄 없음은 질의 미실행의 증거가 아니다. 로그에 없는 실제 SQL 시간을 역산하거나 운영 EXPLAIN ANALYZE·통계 갱신을 하지 않는다.
- CryptoPanic 403·Connection reset은 ERROR 집계와 완료/FAILED 기록을 구분한다. 실패 없는 구간을 출처 복구로 확정하지 않는다. 403 원인은 기존 설정/호출/공식 문서의 읽기 대조까지만 가능하다. 토큰을 포함한 실 API 시험·강제 재시도·뉴스 분류 변경은 하지 않는다.
- **새 미설명 🔴·⚪는 전체 원문을 보존하고 운영 변경을 보류한다. 연결 획득 시간 초과는 로그 수준과 무관하게 즉시 P0로 기록·보고한다.** 이번 범위에는 자동 복구/재기동이 없다. 사고 원인과 관계없는 독립 로컬 작업은 계속할 수 있다.

## 8. W6 — 통합 후보·실제 jar·실행안·최종 인계

- W2/W3에서 수정할 결함이 나온 경우만 관련 후보를 통합한다. 후보별 재현과 수정 범위를 먼저 보존하고, 공통 파일의 양쪽 방어가 남아 있는지 대조한다. 기존 계약을 바꾸는 부분은 통합하지 않는다.
