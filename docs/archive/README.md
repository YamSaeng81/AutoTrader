## 왜 옮겼나

`docs/` 에 현행 운영 문서와 6개월치 과거 기록이 섞여 있었고, 낡은 문서가 현행처럼 읽혀
**실제로 잘못된 근거가 인용되는 일이 발생**했다. 대표적으로 2026-09-15 구조 리뷰에서
문서에 박힌 오래된 줄 수 때문에 서로 다른 숫자를 근거로 논쟁이 벌어졌다.

## 무엇을 옮겼고 무엇을 남겼나

**옮긴 기준** — 셋을 모두 만족하는 문서:

1. 특정 시점의 분석·측정·리뷰 기록이고
2. 그 내용이 이후 변경으로 더 이상 현재를 설명하지 않으며
3. **저장소 안에서 실질적으로 참조되지 않는다** (코드 인용 없음, 현행 문서의 링크 없음)

**남긴 것** — 낡았어도 다음에 해당하면 제자리에 두고 배너만 달았다:

- **소스 코드가 인용하는 문서**: `20260415_analy.md`(20개 파일이 `Tier N §M` 로 인용),
  `20260415_sharpe_audit.md`. 경로와 번호가 사실상 API 라 옮기면 인용이 끊긴다.
- **현행 문서가 링크하는 문서**: `DESIGN.md`, `SINGLE_STRATEGIES_GUIDE.md`, `Strategy/` 등
- **이미 별도 아카이브인 것**: `old_progress.md`, `old/`

## 되돌리려면

이동은 `git mv` 로 했으므로 히스토리가 보존된다. 특정 파일이 다시 필요하면:

```bash
git mv "docs/archive/<파일명>" docs/
# 배너는 수기로 제거할 것
```

파일이 언제 어떻게 바뀌어 왔는지는 `git log --follow -- docs/archive/<파일명>` 로 추적된다.
