# 1단계 체결 비용 집계 — 선행 조건 2

`LIVE_ENTRY_PREREG.md` §4(실제 체결 비용 — 정의와 판정)·§7-2(표본 부족 처리)를 그대로 구현한 집계다. 판정 규칙을 바꾸지 않는다.

| 파일 | 내용 |
|---|---|
| `export.sql` | 운영자가 운영 DB 에서 **읽기 전용**으로 실행해 CSV 를 받는다(실자금 세션의 닫힌 포지션 × 체결 주문) |
| `aggregate.py` | CSV → 판정 보고. 파이썬 표준 라이브러리만, 금액·비율은 `Decimal` |
| `test_aggregate.py` | 규칙별 자체 시험(합성 자료) |

## 실행

```bash
# 1) 운영 DB (psql, 읽기 전용) — export.sql 의 SELECT 를 \copy 로
\copy (SELECT ... export.sql 그대로 ...) TO 'stage1_orders.csv' WITH CSV HEADER
# 2) 집계
python scripts/stage1_cost/aggregate.py stage1_orders.csv --start <1단계 시작 ISO 시각> [--as-of <기준 시각>] [--end <단계 종료 시각>] [--size 20000]
# 자체 시험
cd scripts/stage1_cost && python -m unittest -v test_aggregate
```

## 판정 (사전 등록 그대로)

- 왕복 비용 = 불리(진입) + 불리(청산) + 0.10 — 불리는 부호 있는 값(유리한 체결은 비용을 깎는다)
- ③ = **판정 가능 코인(왕복 ≥ 3)** 의 코인별 단순평균을 **코인 동일가중** 평균. ⚪(1~2건·0건)은 제외 — 0 이나 평균으로 채우지 않는다
- 종료: 판정 가능 코인 ≥ 8 / 22 **AND** 왕복 ≥ 30, 기간 상한 60일(미달이면 판정 불가 → 2단계 진입 불가)
- ③ ≤ 0.30 유효 · 0.30 < ③ ≤ 0.40 검증 §4(나) 재계산(이 스크립트 범위 밖) · ③ > 0.40 가정 깨짐
- 코인별 > 0.60 → 그 코인 2단계 제외 표시
- 분포·절대 편차·표본 수는 보고만 한다

## 정의 (리뷰 2026-10-19 판정)

| | 정의 | 판정 |
|---|---|---|
| D1 | 판정 대상은 사전 고정 22코인뿐(총 왕복 30 도 그 안에서 센다). 밖의 코인은 따로 센다 | 동의 |
| D2 | 한 방향의 비용은 **금액 기준**: BUY = (Σ체결대금 − Σ(신호가×체결수량)) / Σ(신호가×체결수량) × 100, SELL 은 부호 반대. 신호가가 주문마다 다르면 주문별 슬리피지의 수량 가중 평균과 값이 다르다 | 보완 반영(계산 정의의 보완) |
| D3 | 측정 불가 왕복은 따로 센다(유효 표본 수와 구분). 대상 포지션은 추출에서 먼저 보존한다 — 주문 없음·한쪽 체결 없음·체결량·신호가·대금 누락·미결 상태의 체결·매수/매도 수량 불일치 | 동의(추출 보완) |
| D4 | **등록된 진입 배정액**(`position.entry_allocation_krw`)이 `--size` 와 같은 왕복만 판정(다른 크기·불명은 따로) | 동의 |
| D5 | 페이퍼 가정 체결(`fill_price_source` 있음)이 섞인 왕복 제외(따로 센다) | 동의 |
| D6 | 코인별 > 0.60 으로 제외 표시된 코인도 ③ 평균에는 남긴다(사후 제거 금지) | 동의 |

**집계 기간**(리뷰 2026-10-19): 단계 시작 **이후 진입**하고 기간 끝 **이전 청산**한 왕복만 판정한다. 기간 끝 = min(`--as-of`, `--end`, 시작 + 60일).
60일 뒤의 거래로 조건을 채워 '정상 종료' 가 되지 않는다. 시작 전 진입·기간 끝 뒤 청산은 따로 센다.

## 이 스크립트가 하지 않는 것

- 검증 §4(나) 거래당 순수익률 재계산(0.30~0.40 구간) — 페이퍼 자료가 필요하다
- 1단계 시작 시각의 결정 — 운영자가 `--start` 로 준다
- 운영 DB 접속 — CSV 만 읽는다
